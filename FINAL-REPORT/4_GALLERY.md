# 4. 질문 후보와 갤러리 선택 (②③④) — 이 시스템의 중심

```
 ① 재료 ─ ▶ ② 질문 후보 ─ ③ 갤러리 ─ ④ 선택 ◀ ─ ⑤ 조판 ─ ⑥ 눈검증 ─ ⑦ 채점
```

## 내부 흐름

```
 재료 + 계약 + scan_material 계수
        │
        ▼
 ② 장마다 "이 장을 무엇으로 말할까" 후보 4~6개
    형태가 아니라 **질문** — "무엇을 답하는 장인가"
        │
        ▼
 ③ 후보를 **실제 pptx로 그린다**          ← 설명 없이 형태만 늘어놓으면 못 고른다
    한 장 = 한 주제                          장 이름 · 재료 요약 · 후보별 답하는 질문
    후보를 3열로 나란히 배치
        │
        ▼
 ④ 사용자 회신  "s04=1 · s07=2 · s09=전탈락"
        │
        ├─ 번호 ──▶ ⑤ 조판으로
        └─ 전탈락 ─▶ ② 로 되돌아간다 (후보 자체가 틀렸다는 신호)
```

## 왜 후보를 그려서 보이나

**장마다 1안씩 내밀면 반려에 방향이 없다.** "별로다"로 끝나고, 다음 안도 찍어서 내밀게 된다.
한 벌을 깔면 사용자가 **번호로** 답한다.

|             | 1안씩                | 갤러리 한 벌      |
| ----------- | -------------------- | ----------------- |
| 사용자 응답 | "별로야" (방향 없음) | "1이 나아" (선택) |
| 왕복 횟수   | 장 수 × 시도 횟수    | 장 수당 1~2회     |
| 반려 시점   | 완성 후              | 스케치 단계       |

## 후보는 형태가 아니라 질문이다

이것이 이 단계의 핵심 규칙이다. `mock_all.py`의 `page()` 주석이 그 이유를 박고 있다.

```python
def page(prs, key, title, headline, material, cands):
    D.compact_header(slide, f"{key} {title} — 이 장을 무엇으로 말할까", headline)
    # 형태만 보이면 "표냐 막대냐"만 고르게 된다 — 무엇을 말하는 장인지를 먼저 준다
    t(slide, G.MARGIN_L, 0.72, FULL_W, 0.20, material, S["foot"] - 1, color=C["muted"])
```

후보 하나는 네 값을 갖는다.

```python
(s04_a, "대응 잇기", "어떤 실패에 어떤 장치가 붙나?", "1:1 대응을 선으로")
#  ^그리는 함수  ^이름   ^답하는 질문                    ^인코딩 방식
```

렌더할 때도 **질문이 형태보다 먼저 읽히도록** 배치한다.

```python
# 이 후보가 답하는 질문 — 형태보다 이게 먼저 읽혀야 한다
t(slide, cx + 0.14, cy + 0.38, cw - 0.28, 0.22, ques, S["foot"] - 1,
  font=F["head"], color=C["accent"], bold=True)
```

## 갤러리 한 장의 구조

```
┌──────────────────────────────────────────────────────────────────┐
│ s04 문제 정의 — 이 장을 무엇으로 말할까                            │  compact_header
│ AI에게 발표자료를 시키면 실패가 넷으로 반복된다 — …                │  헤드라인
│ 재료: 실패 4유형 · 각각의 차단 장치 · 밀도 실측(중앙값 197단어) …  │  재료 요약(muted)
│                                                                  │
│ ┌─①대응 잇기──────┐ ┌─②층 깊이────────┐ ┌─③…────────────┐      │
│ │ 어떤 실패에 어떤 │ │ 그 장치들이 서로 │ │                │      │  질문(accent·bold)
│ │ 장치가 붙나?     │ │ 다른 층에…       │ │                │      │
│ │                 │ │                 │ │                │      │
│ │  [실제 그림]     │ │  [실제 그림]     │ │  [실제 그림]    │      │  cw 3.85 × ch 2.80
│ └─────────────────┘ └─────────────────┘ └────────────────┘      │
│ ┌─④─┐ ┌─⑤─┐ ┌─⑥─┐                                              │  3열 × N행
└──────────────────────────────────────────────────────────────────┘
```

번호 배지는 `primary` 채움 원(0.26″)에 흰 숫자 — 사용자가 그 번호로 회신한다.

## 실측이 낳은 규칙 둘

### ① 관계 이름만 적힌 표를 후보라고 내밀지 않는다

첫 시도에서 "대응 4:4", "층위" 같은 **관계 이름만 나열한 표**를 내놓고 고르라고 했다.
사용자 반응: **"저걸 보고 판단하라고?"**

교정: 실제로 그려서 갤러리로 깐다. 이름은 그림의 라벨이지 후보가 아니다.

### ② 설명 없이 형태만 늘어놓지 않는다

두 번째 시도에서 그림은 그렸는데 **무슨 내용인지 안 적었다.** 사용자 반응:
**"너무 대충 설명해서 뭔 내용에 뭘 고르라는지 모르겠어."**

교정: 장 이름 · 헤드라인 · **재료 요약** · 후보별 **답하는 질문**을 같이 적는다. 위 `page()`
코드가 그 결과다.

두 규칙 모두 [8_INHERITANCE](8_INHERITANCE.md)의 반려 목록에 부정형으로 올라가 있다.

## 실증 예시 — s09 전탈락이 뜻한 것

2026-07-29 갤러리에서 사용자 회신은 `s04=1 · s07=2 · s09=다탈락`이었다.

**s09의 후보 5개가 전부 떨어진 이유**를 뒤에 찾았다. 후보들이 전부 **내부 구현 얘기**였다 —
"부품이 몇 종인가", "선택 규칙이 어떻게 도나" 같은 것. 그런데 아웃라인 계약(`01.5_outline.md`)에
**"내부 지표 금지"** 조항이 있었다. 후보를 내는 단계에서 그 계약을 안 본 것이다.

즉 **전탈락은 "그림이 별로다"가 아니라 "질문 자체가 틀렸다"는 신호**였다. 그래서 전탈락이면
③(다시 그리기)이 아니라 ②(질문 다시 뽑기)로 되돌아간다.

이 사례가 파이프라인에 남긴 것: ②는 재료만 보는 게 아니라 **계약을 같이 본다.**

## 이 단계가 막는 것 — 규칙으로는 못 막았던 것

| 실패      | 규칙으로 시도했을 때                       | 왕복으로 바꾼 뒤                     |
| --------- | ------------------------------------------ | ------------------------------------ |
| 구조 오독 | "재료를 정확히 읽어라" → s05를 병렬로 오독 | 후보 6개 중 사용자가 ①번 선택 → 해결 |
| 형식 수렴 | "다양하게 그려라" → 9장 전부 같은 형식     | 장마다 다른 질문 → 장마다 다른 형식  |

**규칙은 나쁜 것을 막을 수 있어도 맞는 것을 고르지는 못한다.** 고르는 건 사용자의 일이고,
이 단계는 고를 수 있는 형태로 내미는 일만 한다.
