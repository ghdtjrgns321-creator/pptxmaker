# 3. 계약 — 조판이 지어낼 자리를 없앤다

```
 재료 ─────▶ [ 계약 ] ─────▶ 덱
             ▲ 이 장
```

## 이 층이 있는 이유

2026-08-03 실측: 본문 **12장 중 8장의 제목**과 **부 이름 5개 전부**가 조판 단계 창작이었다.
간지에는 「Ⅱ 검증할 데이터」라 적혀 있었는데 사용자가 재료에 써 둔 뎁스는 「합성 데이터 생성」
이었다. **사용자가 그걸 볼 자리가 없었다** — 계약에 그 칸이 없으니 조판이 알아서 지었고,
아무도 대조하지 않았다.

지어내는 것을 막는 길은 둘이다. **게이트로 뒤에서 잡거나, 애초에 계약에서 읽어오거나.**
제목은 전자(`check_deck.headlines`), 부 이름은 후자(`outline.parts`)로 막는다. 부 이름을
후자로 한 이유는 그것이 본문 **전 장의 상단에 5줄로** 깔리기 때문이다 — 손으로 옮겨 적으면
`장 수 × 부 수`만큼 틀릴 자리가 생긴다.

## 계약 서식

산출물은 `_workspace/<프로젝트>/01.5_outline.md`. 절 구성은 머리말 → `## 정형 장 문구` →
`## 장 목록` → 추가 재료 → 개정 이력이다.

### `## 장 목록` — 7열

```
| # | 부 | 장 제목(재료 뎁스) | 헤드라인(확정) | 전하고 싶은 것 (육성 채록 원문) | 재료 출처 | 상태 |
```

| 열                   | 무엇                               | 누가 읽나                                  |
| -------------------- | ---------------------------------- | ------------------------------------------ |
| `#`                  | `S4` 또는 `4` — 정규식 `^S?(\d+)$` | `outline.part_of` · `check_deck.headlines` |
| `부`                 | 로마자 `Ⅰ`~`Ⅴ`. 정형 장은 `—`      | `outline.part_of` → 부 내비 강조 대조      |
| `장 제목(재료 뎁스)` | 재료 헤딩 그대로                   | `check_outline.py`                         |
| `헤드라인(확정)`     | 슬라이드에 실제로 박히는 한 줄     | `check_deck.headlines`                     |
| `전하고 싶은 것`     | 사용자 육성 채록 원문              | ②단계의 초점 (기계 안 읽음)                |
| `재료 출처`          | 어느 절에서 왔나                   | 사람                                       |
| `상태`               | 확정/보류                          | 사람                                       |

### `## 정형 장 문구` — 하위 표 2개

표지·클로징(3열 `자리 | 문구 | 재료 근거`)과 부/간지(4열 `부 | 제목 | 리드 | 재료 헤딩`).

`local-ai-assist` 계약의 부 표 실물:

```
| 부 | 제목                  | 리드                                              | 재료 헤딩            |
| Ⅰ  | 분석 범위와 문제 인식 | 전표 전수를 어디까지 보고, 표본은 무엇을 못 보나 | README `## 1.`·`## 2.` |
| Ⅱ  | 합성 데이터 생성      | 실제 전표를 못 구해 직접 만들었다 …              | README `## 3-1.`     |
| Ⅲ  | 분석 모델             | 룰 기반 검증 · 분석적 검토 · 비지도 학습(VAE)    | README `## 3-2`~`3-5` |
| Ⅳ  | 검증                  | 정상 베이스라인 · 단일 룰 발현 · 이상 주입 후 회수 | README `## 4.`     |
| Ⅴ  | 핵심 의사결정과 한계  | 무엇을 빼기로 했고, 무엇이 아직 안 되는가        | README `## 5.`~`## 7.` |
```

이 표가 **부 내비게이션 문구의 유일한 출처**다. 조판은 `set_parts(O.parts(계약))` 한 줄로
읽고, 게이트는 같은 함수로 기대값을 만든다.

## 파서 — `deckkit/outline.py` (88줄)

```python
def tables(path):
    """마크다운 표를 (헤더, 행들)로 끊어 낸다.

    표가 끝나면 헤더도 버린다 — 한 문서에 표가 여러 개고, 열 위치가 표마다 다르다.
    (구판 파서가 이걸 안 해서 장 목록의 `부` 열을 표지 표에도 적용했다.)
    """
```

| 함수            | 반환                          | 규칙                                                                                  |
| --------------- | ----------------------------- | ------------------------------------------------------------------------------------- |
| `tables(path)`  | `(헤더, 행들)` 제너레이터     | 표가 끝나면 헤더 버림. 구분선 행(`set(cells) <= set("-: ")`) 스킵                     |
| `parts(path)`   | `[(로마자, 제목, 리드), ...]` | 첫 열 헤더가 **정확히 `"부"`**인 표만. `제목`·`리드`는 `startswith` 매칭              |
| `part_of(path)` | `{장 번호: 로마자}`           | 첫 열 헤더가 **정확히 `"#"`**인 표만. 제목이 `표지`·`목차`·`간지`로 시작하면 **제외** |

조건에 맞는 표가 여러 개면 **비지 않은 첫 표**를 채택한다(`if out: return out`). 못 찾으면
빈 목록을 반환하고 예외를 던지지 않는다 — 이 조용함이 게이트 쪽 `if not want or not of:
return []`과 맞물려 **구판 계약은 내비 검사 전체가 무음으로 통과**하게 만든다(의도된 하위 호환,
동시에 [한계](8_TEST-DECISIONS.md)).

**같은 함수의 출력이 조판 입력이자 게이트 기대값이다.** 그래서 조판이 지어낸 부 이름은 100%
잡히지만, **계약 자체가 틀리면 아무도 못 잡는다.** 그 방어는 다음 절이 진다.

## 계약 ↔ 재료 대조 — `scripts/check_outline.py` (89줄)

```bash
uv run python scripts/check_outline.py <계약.md> <재료.md>
```

계약의 장 제목·부 제목이 **재료 헤딩 어휘에서 나왔는지** 낱말 겹침으로 본다.

| 단계      | 규칙                                                                       | 위치            |
| --------- | -------------------------------------------------------------------------- | --------------- |
| 헤딩 수집 | 재료의 `^#{1,4} ` 전부                                                     | `:23-25`        |
| 토큰화    | 숫자·마침표 제거 후 `공백 · , / ( ) - — 「」『』`로 분할, **2글자 이상만** | `:28-29`        |
| 열 추출   | 표 하나 단위로 `장 제목`/`제목` 열. 표가 끝나면 버림                       | `:32-54`        |
| 히트 판정 | 제목 어절이 헤딩 토큰의 **접두 또는 피접두**면 히트 (조사 흡수)            | `:74-76`        |
| 판정      | 전 헤딩 중 **최대 겹침률** < `OVERLAP_MIN = 0.5` → "지어낸 말이다"         | `:20`, `:78-80` |
| 면제      | `표지`·`목차`·`간지`, 토큰 0개인 제목                                      | `:69`, `:72-73` |

접두 매칭이 필요한 이유는 한국어 조사다 — 계약의 「의사결정과」가 재료 헤딩의 「의사결정」과
붙어야 한다.

**무엇을 안 보나 (명시)**

- **수치를 대조하지 않는다.** 제목 문자열만 본다.
- 재료의 본문 문단은 안 본다 — 헤딩만 풀로 삼는다.
- 순서·중복·누락 장 검사 없음. 계약↔pptx 대조도 안 한다(그건 `deck_state.py check`).

이 공백은 실제로 드러났다. 계약 S7 칸은 「거래 시나리오 **20종**」인데 재료가 뒤에 갱신되어
「**24종**」이 됐고, 제목 대조만 하는 이 검사는 통과시켰다. 같은 계약으로 한 장을 세 번 만든
실험에서 **3회 모두 독립적으로** 그 어긋남을 발견하고 재료를 따랐다.

**배선 상태 — 미배선.** `pptmaker/SKILL.md` 파이프라인이 이 스크립트를 부르지 않고,
`docs/MAP.md` §1 실재표에도 없다. 실행 근거는 핸드오프 문서의 수동 명령뿐이다.

## 실증 — 「핵심 의사결정과 한계」가 대조를 통과하는 과정

계약 Ⅴ부 제목: `핵심 의사결정과 한계`
→ 토큰화: `{핵심, 의사결정과, 한계}` (2글자 미만 없음)

재료 헤딩 후보 중 `## 5. 핵심 의사결정`
→ 토큰화: `{핵심, 의사결정}`

히트 판정:
- `핵심` — 완전 일치 ✓
- `의사결정과` — 헤딩 토큰 `의사결정`의 **피접두**(`"의사결정과".startswith("의사결정")`) ✓
- `한계` — 이 헤딩엔 없음 ✗

겹침률 = 2/3 = **0.67 ≥ 0.5** → 통과. (`## 6. 한계점`을 따로 보면 `한계`도 히트하지만,
판정은 **전 헤딩 중 최댓값**이라 하나만 넘으면 된다.)

