# 5. 게이트 — 기계 검사

```
 재료 ─▶ 계약 ─▶ 덱 ─▶ [ 게이트 ]
                        ▲ 이 장
```

검사는 세 러너에 나뉘어 있고 **서로를 import하지 않는다.**

```
 check_outline.py ──▶ 계약 ↔ 재료          1종  (파이프라인 ① — deck_state init이 부른다)
 check_deck.py    ──▶ 덱 ↔ 계약 · 좌표     9종 하드페일 + 1종 보고
                                                (파이프라인 ⑦ — deck_state check가 부른다)
 score_deck.py    ──▶ goldenfab.audit      12종  (파이프라인 ⑦)
 render_deck.ps1  ──▶ PNG 전장             ★ 눈검증이 진짜 게이트
 deck_state.py    ──▶ 단계·반려·획일화     9판정  (파이프라인 ①③⑦) + 위 둘의 호출처
```

## 5-1. `check_deck.py` — 좌표와 계약

```bash
uv run python check_deck.py <deck.pptx> [--outline=<계약.md>] [--material=<재료.md>]
```

`bad` 리스트에 들어가는 것이 전부 하드페일이고, 하나라도 있으면 `return 1`.

| #   | 검사               | 조건                                           | 발동        |
| --- | ------------------ | ---------------------------------------------- | ----------- |
| 1   | 우변 초과          | `x+w > RIGHT + 0.02` (블리드 면제)             | 항상        |
| 2   | 하변 초과          | `y+hh > 6.90 + 0.02 and y < 6.90` — 푸터 침범  | 항상        |
| 3   | 이미지 판독 폭     | `PICTURE and 1.00 <= w < 2.40`                 | 항상        |
| 4   | 헤드라인 계약 일치 | 계약 문구가 밑줄 위 텍스트 중에 없음           | `--outline` |
| 5   | 정형 장 문구 존재  | `formal()`이 뽑은 문구가 덱 전체 텍스트에 없음 | `--outline` |
| 6   | 부 내비 누락       | 계약이 부를 지정한 장에 `부내비:*` 도형 0개    | `--outline` |
| 7   | 부 내비 문구·순서  | `got != want` (리스트 전체 비교)               | `--outline` |
| 8   | 부 내비 강조 개수  | accent 런을 가진 내비 도형이 정확히 1종이 아님 | `--outline` |
| 9   | 부 내비 강조 대상  | 강조된 부 ≠ 계약이 그 장에 지정한 부           | `--outline` |
| —   | **재료 커버리지**  | 수치 토큰 교집합 비율 < 0.70이면 표시만        | **보고**    |

### 블리드는 결함이 아니다

```python
full_bleed = (x < FR["margin"] - LIM["right_tolerance"]
              or x + w >= FR["slide_w"] - LIM["right_tolerance"])
```

좌변이 여백 밖(전폭 배경)이거나 우변이 슬라이드 끝에 **정확히** 닿는 것(목차 띠처럼 한쪽만
흘리는 설계)은 면제한다. **어중간하게 넘는 것만** 잡는다. 이 면제는 우변·하변 두 검사에
동시에 걸린다.

### 좌표를 박지 않는다

```python
# 머리띠 = 헤더 밑줄 위. 좌표를 박지 않고 토큰에서 뽑는다 — 2026-08-03에 밑줄을
# 1.18에서 올렸더니 `0.4 < top < 1.1`로 박아둔 창이 제목을 통째로 놓쳤다.
and Emu(sh.top).inches < FR["rule"]
and not sh.name.startswith("부내비:")
```

이 회귀는 실제로 났다. 밑줄을 올린 직후 **12장 전부가 헤드라인 불일치로 오탐**했고, 창을
토큰 파생으로 바꿔 0건이 됐다.

### 재료 커버리지는 판정하지 않는다

```python
def coverage(deck, material) -> str:
    """재료 커버리지 보고 — **판정하지 않는다.**

    글자 수 하한은 텍스트로 채우게 만들어 시각을 밀어냈다(2026-08-03 실측). 커버리지는
    같은 절을 늘려 써도 안 오르고 새 사실을 가져와야 오르므로, 같은 왜곡을 만들지 않는다.
    그래도 하한이 아니라 **보고**로 둔다 — 19장이 재료 전량을 담을 수는 없고, 무엇을 담을지는
    계약이 정한 것이지 기계가 정할 것이 아니다.
    """
```

반환형이 문자열이라 종료코드에 영향이 없다. **말과 코드가 일치하는** 사례다.

## 5-2. `score_deck.py` + `goldenfab.audit` — 오딧 12종

`score_deck.py`가 유일한 러너다. `--body 4,5,7`이 있으면 그 장만, 없으면 도형 12개 이상인
장만 본다(정형 장 자동 면제).

| 검사                     | 무엇을 잡나                               | 프로파일                 |
| ------------------------ | ----------------------------------------- | ------------------------ |
| `check_accent`           | 포인트색 과다                             | 3종 전부(임계 4/6/8)     |
| `check_bounds`           | 경계 이탈                                 | 3종 전부                 |
| `check_density`          | 밀도 미달                                 | `band` 있을 때           |
| `check_fill_ratio`       | 상자가 내용보다 큼                        | sparse·dense             |
| `check_adhoc_card`       | **밋밋한 카드** — 밝은 카드에 구조 자식 0 | dense·legacy             |
| `check_duplicate_nodes`  | 같은 이름 + 같은 서명 = 정보량 0          | 3종 전부                 |
| `check_node_class`       | 같은 이름 + 다른 채움 = 클래스 모순       | 3종 전부                 |
| `check_verdict_contrast` | 판정 색 대비 (WCAG 4.5)                   | sparse·dense             |
| `check_text_overflow`    | 글자 넘침                                 | 3종 전부                 |
| `check_text_collision`   | 텍스트 겹침                               | 3종 전부                 |
| `check_picture_overlap`  | 그림이 글자 침범                          | 3종 전부                 |
| `check_icon_vocab`       | **덱 단위** 어휘가 통째로 죽었나          | `score_deck`이 직접 호출 |

**12종 전부 도달한다** — `generic_checks`에 11개가 배선되고 `check_icon_vocab`만 러너가 직접
부른다(장별로는 다 통과해도 덱 전체에서 아이콘이 0인 경우를 잡는 자리).

### 검사기는 대상을 절대 변형하지 않는다

```python
# 왜: 초판은 `sh.line.color.type` · `run.font.color.rgb`로 색을 읽었는데 python-pptx의
# ColorFormat은 **접근하는 순간 XML을 만든다** — `<a:ln><a:solidFill/></a:ln>`이 붙고,
# PowerPoint는 그걸 **검정 헤어라인 테두리**로 그린다.
# 교훈: 검사기는 대상을 절대 변형하지 않는다. 아래는 lxml로 XML을 **읽기만** 한다.
```

이것이 이 저장소의 유일한 CRITICAL 사고였다(→ [9장](9_TROUBLESHOOTING.md)).

### 두 규칙의 경계 — 재탕과 클래스

```python
    **채움 = 클래스**(이게 무엇인가 — 개념·문단·사례) → 같은 이름이면 같아야 한다.
    **테두리·점선 = 상태**(성립/불성립·자동/위임) → 달라도 된다, 그게 대조다.
```

`check_duplicate_nodes`는 "같은 이름 + 같은 서명"을, `check_node_class`는 "같은 이름 + 다른
채움"을 잡는다. **정확히 반대 방향이라 경계 선언이 없으면 어느 쪽으로도 못 빠져나간다.**

### 하한을 1보다 올리지 않는다

```python
    **하한을 1보다 올리지 않는다.** 골든도 본문 14장 중 9장(64%)만 쓴다. "장별 커버리지 하한"을
    만들면 그게 "카드 4장 써라"가 태어난 승격(한 장의 지적 → 모든 장의 명령)과 같은 경로다.
    잡는 것은 **"어휘가 통째로 죽었다"** 하나뿐이다.
```

### 임계는 실측에서 파생된다

`density_band()` 실행 결과 (2026-08-04):

```
{'shapes_min': 22, 'frames_min': 11, 'chars_min': 535, 'shapes_floor': 20, 'n_body': 10}
```

`chars_min`은 리터럴이 아니라 `round(min(골든 본문 장 글자수) * 0.85)`다. 원천은
`assets/golden-snapshot.json`(17장 850도형)이고, 스냅샷을 갈면 밴드도 따라 움직인다.

**도형 수가 아니라 글자 수로 재는 이유**는 도형 수로 재면 밀도 부족을 카드 4장으로 메우는
반사를 유발하기 때문이다. 골든의 항목형 장은 도형이 37개여도 글자가 꽉 차 통과작급이다.

## 5-3. `render_deck.ps1` — 진짜 게이트

35줄. 파라미터 `-Pptx` · `-OutDir` · `-Width`(기본 1920).

```powershell
# PowerPoint COM은 단일 인스턴스 — 동시 렌더가 서로의 Quit에 죽지 않게 전역 뮤텍스로 직렬화
$mutex = New-Object System.Threading.Mutex($false, "Global\pptmaker_render_deck")
...
$h = [int]($Width * $pres.PageSetup.SlideHeight / $pres.PageSetup.SlideWidth)  # 판형에서 파생
```

높이를 리터럴로 두지 않아 판형이 바뀌어도 안 깨지고, `finally`에서 `Quit` + `ReleaseComObject`
+ 뮤텍스 해제를 해 실패해도 COM 인스턴스가 남지 않는다.

**수정 라운드는 규율이 다르다.**

|      | 신규 조판       | 수정 라운드                                  |
| ---- | --------------- | -------------------------------------------- |
| 단위 | 전 장을 한 번에 | **한 번에 한 장씩**                          |
| 렌더 | 1920px 전장     | **고친 장만 `-Width 3840`**                  |
| 종료 | 전 장 훑고 채점 | **그 장이 끝나기 전에 다음으로 안 넘어간다** |

1920px 전장 훑기로는 카드 안 정렬이 안 보인다. 실제로 게이트 FAIL 0 · 렌더 PNG 확인까지
하고도 사용자가 확대해서야 어긋남을 발견한 사고가 있다.

## 5-4. `deck_state.py` — 단계·반려·획일화

`_workspace/<프로젝트>/STATE.md`를 만들고 대조한다. 하위 명령 3개.

| 명령      | 판정                                                       |
| --------- | ---------------------------------------------------------- |
| `init`    | 계약 없으면 중단 · STATE.md 이미 있으면 **덮지 않고** 중단 |
| `check`   | 6판정 + 획일화                                             |
| `gallery` | 3판정                                                      |

**`check` 6판정**: ①상태 표의 S번호가 계약 순서와 불일치 ②`deck.pptx` 장 수 ≠ 계약 장 수
③렌더 PNG 개수 ≠ 계약 장 수 ④`**단계**:` 미기재 또는 정의 밖 값 ⑤전 장이 대기인데 단계가
④ 이상 ⑥**반려 표의 `하네스` 칸이 `미정`으로 남아 있음**.

⑥이 이 스크립트의 존재 이유다 — 반려를 그 자리에서 안 적으면 세션과 함께 사라지고, 다음
덱에서 같은 반려가 다시 나온다.

**획일화 판정** (`variety()`):

```python
SAME_COMBO_MAX = 2      # 완전히 같은 조합이 이 수를 넘으면 형태가 아니라 틀을 찍은 것이다
ONE_PART_SHARE = 0.60   # 한 부품이 본문 장의 이 비율을 넘으면 그 부품이 덱을 지배한다
```

임계 근거가 주석에 있다 — *"local-ai-assist(본문 12장, 조합 12종)에서 오탐 0으로 맞춘 값.
잡으려는 실패는 2026-07-29에 박제된 '전 장이 같은 형식', '36장이 동일한 4카드'."*
본문 표본이 4장 미만이면 **판정 자체를 안 한다.**

**`gallery` 3판정**: 갤러리 스크립트를 `importlib`로 실행해 `CORE` dict를 읽고, 슬라이드를
4분면으로 갈라 각 사분면이 핵심 낱말을 절반(`CORE_MIN = 0.5`) 이상 담는지 본다. 갤러리 총
장 수가 본문 장 수와 다르면 경고. 후보에서 핵심 실체를 통째로 빼서 반려당한 실측에서 나온
검사다.

## 5-5. 이 층의 한계

| 한계                                       | 실측                                                                                                                                                        |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **프로젝트 훅 0개**                        | `.claude/settings.json` = `{"hooks":{}}`, `.claude/hooks/` 빈 폴더. **모든 게이트가 수동 실행이다**                                                         |
| 두 러너의 배선이 **덱 작업 밖에서는 없다** | `deck_state.py`가 부르므로 `_workspace/<프로젝트>` 절차 안에서만 돈다. 그 밖에서 만든 pptx는 아무도 안 본다 — 훅이 0개라 산출물 자체에 게이트가 붙지 않는다 |
| 블리드 면제 비대칭                         | `check_deck.py`에는 있고 `kit.R()`의 우변 경고에는 없다 — 같은 도형이 조판 WARN에는 뜨고 게이트는 통과                                                      |
| `--body` 죽은 인자                         | `main()`이 파싱해 `check()`에 넘기지만 `check()`가 안 읽는다                                                                                                |
| 구판 계약 무음 통과                        | 계약에 부 표·헤드라인 열이 없으면 검사 4~9가 통째로 스킵된다                                                                                                |
| 골든이 자기 게이트를 못 넘는다             | `score_deck golden-deck.pptx` → **FAIL 8건**(s09·s11·s14 노드 재탕 · s10·s17 밀도 · s17 경계). 골든은 sparse 프레임인데 러너 기본값이 dense인 구조적 불일치 |
| 밀도·정렬은 안 본다                        | 실측상 안 갈렸다 — 밀도는 좋다 한 장 137~200% vs 문제 장 172%, 정렬은 좋다 한 장 46·53쌍 vs 문제 장 15쌍(**반대**)                                          |

마지막 줄이 이 층의 설계 원칙이다. **갈리지 않는 축은 검사하지 않는다** — 상시 적색인
게이트는 무시당하고, 결국 우회된다.
