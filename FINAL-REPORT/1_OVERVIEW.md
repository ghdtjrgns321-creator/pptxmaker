# 1. 개요 — 무엇을 막는 시스템인가

## 문제 정의

프로젝트 소개용 B2B 셀링 덱을 만들 때, 실패는 두 방향으로 갈린다.

**한쪽은 서식이 흔들린다.** 장마다 색·글꼴·여백·페이지 골격이 조금씩 달라지고, 스무 장쯤 되면
같은 덱으로 안 보인다. 사람이 손으로 맞추면 한 장 고칠 때마다 나머지를 다시 훑어야 한다.

**다른 쪽은 형태가 굳는다.** 서식을 강제하려고 "이 장은 이 틀로"를 부품으로 만들면, 그 부품이
장 구성까지 정해버린다. 이 저장소가 실제로 겪은 결과는 **36장이 동일한 4카드**였다. 내용이
다른데 그림이 같으면 독자는 아무것도 못 읽는다.

**이 시스템은 앞쪽을 기계로 고정하고 뒤쪽을 열어 둔다.** 템플릿은 색·글꼴·여백·표지/목차/간지/
머리띠만 소유하고, "이 장을 어떤 구획으로 나눌까"는 매번 내용이 정한다.

## 왜 이 접근인가 — 대안 대비

| 접근                              | 하는 일                                                                      | 왜 안 골랐나                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **PowerPoint 마스터 슬라이드**    | 레이아웃 자리표시자를 미리 짜고 텍스트를 꽂는다                              | 자리표시자가 곧 장 구성이다. 열 개 레이아웃을 만들면 모든 장이 그 열 개 중 하나가 된다             |
| **spec → 빌더**                   | JSON 스펙을 넣으면 덱이 나온다                                               | 스펙 스키마가 표현할 수 있는 것만 그릴 수 있다. 스키마에 없는 배치는 시도조차 못 한다              |
| **LLM에게 통째로 맡김**           | 프롬프트 한 번에 덱 생성                                                     | 서식이 매번 흔들리고, 무엇이 왜 그렇게 됐는지 남지 않아 고칠 자리가 없다                           |
| **채택 — 토큰 + 원시도구 + 계약** | 색·치수는 토큰이, 페이지 골격은 함수 4개가, 배치는 매번 파이썬 좌표가 정한다 | 일관성이 필요한 것만 소유한다. 배치는 코드라 무엇이든 그릴 수 있고, 좌표가 남으니 고칠 자리가 있다 |

핵심은 **소유의 경계**다. 토큰이 소유하면 한 곳을 고쳐 전체가 바뀌고, 부품이 소유하면 그
부품이 안 맞는 장에서도 그 형태로 그리게 된다.

## 아키텍처 원칙 5

| #   | 원칙                                  | 코드에 어떻게 박혔나                                                                                                                        |
| --- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **일관성이 필요한 것만 소유한다**     | `brand.yaml` 토큰 33개가 색·글꼴·판형·게이트 임계를 진다. `kit.py`·`check_deck.py`가 각각 이 파일을 읽고 hex·pt 리터럴을 쓰지 않는다        |
| 2   | **장 구성은 소유하지 않는다**         | 흐름도·관계도를 그리는 `flow()`·`graph()` 같은 도해 부품이 **0종**이다. 사각(`R`)과 커넥터(`CONNECT`/`LINK`)만 주고 배치는 매번 좌표로 짠다 |
| 3   | **기계는 통보자이지 판정자가 아니다** | 물리(경계·판독 폭)·기하(채움률)는 하드페일, 미적인 것(표 행 높이·재료 커버리지)은 **경고만** 낸다. 강제로 누르면 재료가 부품에 맞춰 휜다    |
| 4   | **임계는 리터럴이 아니라 실측 파생**  | 밀도 하한 535자는 골든 17장 스냅샷의 가장 성긴 본문 장에서 파생된다(`density_band()`). 골든이 바뀌면 밴드도 따라 움직인다                   |
| 5   | **지어내는 것은 입력에서 막는다**     | 부 이름은 게이트로 뒤에서 잡는 게 아니라 `outline.parts()`가 **계약에서 읽어 온다**. 조판이 옮겨 적을 자리 자체가 없다                      |

원칙 3과 4는 같은 뿌리다 — **숫자로 굳히면 그 숫자를 채우는 쪽으로 왜곡된다.** 글자 수 하한을
걸었더니 본문 12장 합계로 글자가 +2,091 늘고 시각 요소가 −39 줄었다(막대가 텍스트 목록이 됐다).
그래서 지금 남은 하한은 실측에서 파생된 것뿐이고, 취향에 가까운 축은 경고로 내려갔다.

## 기술 스택

| 레이어          | 기술                                                   | 비고                                                            |
| --------------- | ------------------------------------------------------ | --------------------------------------------------------------- |
| 런타임          | Python **3.13** 고정 (`.python-version`)               | `requires-python >=3.13` (`pyproject.toml:6`)                   |
| 패키지·가상환경 | **uv** (`.venv` · `uv.lock`)                           | `uv run python <경로>` — venv 자동 활성                         |
| 조판            | **python-pptx** ≥1.0.2                                 | 슬라이드를 파이썬으로 직접 그린다. 빌더·spec 경로 없음          |
| 토큰            | **PyYAML** ≥6.0.3                                      | `deckkit/brand.yaml` 33개                                       |
| 차트(미배선)    | **matplotlib** ≥3.11                                   | `mpl_exhibits.py` 9종 — 구현은 있으나 호출자 0                  |
| 렌더            | **PowerPoint COM** (`render_deck.ps1`)                 | 전역 뮤텍스로 직렬화. 높이는 판형에서 파생                      |
| 검사            | **lxml**(python-pptx 동봉)                             | 색 읽기는 반드시 읽기 전용 — 이유는 [9장](9_TROUBLESHOOTING.md) |
| 개발            | **ruff** ≥0.15.20 (`line-length = 100`), **pypdfium2** |                                                                 |

`pyproject.toml`은 빌드 백엔드·엔트리포인트를 선언하지 않는다. 라이브러리가 아니라 **스크립트
모음**이고, `readme = "CLAUDE.md"`로 잡혀 있다.

## 무엇을 만들어 냈나

`local-ai-assist`(로컬 전표 전수 분석 시스템) 소개 덱 **19장** — 표지 · 목차 · 간지 5 · 본문 12.
계약(`01.5_outline.md`)이 5부 구성과 장별 헤드라인을 확정했고, 조판이 그 계약을 읽어 부
내비게이션을 매 장 상단에 깔았다. 게이트 결과는 **19장 결함 0건**이다.

그 덱을 만드는 동안 드러난 결함이 이 하네스로 내려왔다 — 그 사슬은 [9장](9_TROUBLESHOOTING.md)이
사고별로 추적한다.
