# 1. 개요 — 무엇을 막는 시스템인가

## 문제 정의

AI에게 발표자료를 시키면 네 가지가 반복해서 무너진다.

| 실패              | 어떻게 나타나나                                    | 이 시스템이 막는 방식                                               |
| ----------------- | -------------------------------------------------- | ------------------------------------------------------------------- |
| **형식 수렴**     | 장마다 다른 내용인데 전부 같은 레이아웃으로 나온다 | 형식을 배정하는 코드를 두지 않는다([4](4_GALLERY.md))               |
| **이미지로 굳음** | 표·차트가 그림이라 받은 사람이 못 고친다           | 네이티브 개체로 생성 — 값을 바꾸면 다시 그려진다([6](6_VISUALS.md)) |
| **성긴 슬라이드** | 여백이 많고 근거가 얇다                            | 밀도 하한을 골든에서 파생해 기계로 건다([7](7_GATES.md))            |
| **구조 오독**     | 재료의 관계를 잘못 읽고 그대로 그린다              | 후보를 그려 사용자가 고르게 한다([4](4_GALLERY.md))                 |

넷 중 **형식 수렴과 구조 오독은 규칙으로 못 막는다.** 이 프로젝트가 그것을 실측으로 배웠다 —
규칙을 639줄까지 쌓았지만 두 실패는 계속 일어났고, 형식 배정 코드를 **없애고** 후보 선택
왕복을 넣자 멈췄다. 상세는 [11_JOURNEY](11_JOURNEY.md).

## 왜 이 접근인가

### 형식을 미리 정하지 않는다

통상적인 템플릿 도구는 "이런 내용이면 이 레이아웃"이라는 매핑표를 갖는다. 이 프로젝트도
그랬다(`registry` 15타입). 결과는 **15개 형식이 돌아가며 나오는 덱**이었다.

지금은 매핑표가 없다. 장마다 재료를 보고 무엇을 말할지 후보를 내고, 그 후보를 **실제 pptx로
그려서** 사용자가 고른다. 형식은 그 선택의 결과이지 입력이 아니다.

### 일관성만 코드가 강제한다

자유롭게 두면 일관성이 깨진다. 그래서 **색·폰트·여백·좌표계·정형 3장만** 코드가 고정한다.

```
 강제되는 것 (334줄 + 설정 1개)        자유로운 것
 ─────────────────────────────        ──────────────────────────
 brand-kit.yaml  색 6·폰트 3·크기 8    무엇을 그릴지
 grid.py         좌표계·자리 파생       어떤 형태로 인코딩할지
 layouts.py      표지·목차·간지         몇 개를 어떻게 배치할지
```

`kit`(도형 헬퍼)·`dense`(밀도 부품)·`pptx-visuals`(렌더러 24종)는 **재료**다 — 쓰라고 강제하지
않는다.

### 왕복이 게이트다

기계가 판정할 수 있는 것(겹침·넘침·대비·밀도)은 `score_deck.py`가 잡는다. 기계가 못 보는
것("이 형태가 이 내용에 맞나")은 **렌더 PNG 눈검증**과 **갤러리 선택**이 잡는다.

이 프로젝트에서 지켜진 지시와 무시된 지시를 갈라보면 규칙성이 하나뿐이다 —
**산문으로 적힌 것은 전부 무시됐고, 기계나 왕복으로 바뀐 것은 전부 지켜졌다.** 근거는
[8_INHERITANCE](8_INHERITANCE.md).

## 아키텍처 원칙

| 원칙                         | 구현                                                               | 어겼을 때 실제로 벌어진 일                                 |
| ---------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------- |
| 형식 배정 코드를 두지 않는다 | `registry` 폐기                                                    | 15타입이 돌아가며 나와 전 장이 같은 형식                   |
| 부품은 재료로만 본다         | `figures/` 아카이브                                                | 부품 기본값이 골든 실측 좌표라 그대로 부르면 골든이 딸려옴 |
| 자리는 호출자가 준다         | `draw(slide, box, ...)` · `add_chart(slide, spec, brand, x,y,w,h)` | 부품이 자리를 독점하면 배치가 고정된다                     |
| 임계는 실측에서 파생한다     | `density_band()`가 골든 스냅샷에서 계산                            | 리터럴 임계는 근거 없이 왜곡을 만든다                      |
| 단일 출처                    | `brand-kit.yaml` · `audit.py:generic_checks`                       | 규칙이 갈라지면 한쪽만 고쳐진다                            |
| 조용한 폴백 금지             | 모르는 `layout`은 `ValueError`                                     | 폴백이 어휘 수렴의 기계적 원인이었다                       |

## 기술 스택

| 레이어      | 기술               | 비고                                    |
| ----------- | ------------------ | --------------------------------------- |
| 언어        | Python 3.13        | `.python-version`으로 고정              |
| 문서 생성   | python-pptx ≥1.0.2 | 네이티브 개체 — 표·차트 편집 가능       |
| 설정        | PyYAML ≥6.0.3      | `brand-kit.yaml` 단일 출처              |
| 통계 그래프 | matplotlib ≥3.11   | 네이티브가 못 만드는 9종을 220dpi PNG로 |
| 환경        | uv                 | `.venv`·`uv.lock`으로 재현              |
| 렌더 검증   | PowerPoint COM     | `render_deck.ps1` — 실물 렌더 후 눈검증 |
| 개발        | ruff · pypdfium2   | 포매터 · 레퍼런스 PDF 크롭              |

## 무엇이 아닌가

- **원클릭 생성기가 아니다.** ④에서 사용자 선택을 기다린다. 그 왕복이 품질의 원천이다.
- **템플릿 채우기가 아니다.** 골든 덱은 "글자만 갈아끼우는 정답지"가 아니라 보고 배우는
  그림이다([5](5_COMPOSE.md)).
- **완성된 제품이 아니다.** 실전 완주 사례가 **0건**이다([9](9_DIFFERENTIATION.md) 한계 절).
