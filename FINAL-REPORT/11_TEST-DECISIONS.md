# 11. 검증 로그와 의사결정 기록(ADR)

> **요지:** 이 장은 두 표가 본체다 — ① 실측 판정만 모은 검증 로그(PASS든 FAIL이든 그대로), ② 주요 결정의 ADR(Architecture Decision Record, 결정 기록). 검증의 원칙은 "산문 선언이 아니라 기계 대조" — 완료는 문장이 아니라 스크립트 exit 0으로만 선언한다. 단, 실전 파일럿 완주는 0건이며 검증 로그의 파일럿 행은 FAIL이다(`9_KIFRS-PILOT.md`).

## 0. 파이프라인 내 위치

```
 FINAL-REPORT ─▶ [①GRILL] ─▶ [②compose] ─▶ [②.5승인] ─▶ [③build] ─▶ [④QA] ─▶ (results/…pptx)
                                                            │           │
                                                    골든 수정 시      실전 덱
                                                            ▼           ▼
                                              ═══ ★ 이 장: 그 게이트들이 실제로 낸 판정 기록 +
                                                    그 구조를 만든 결정들(ADR) ═══
```

게이트 각각의 구조는 `8_QA-GATES.md`, 이 장은 **판정 결과와 결정 이력**을 다룬다.

## 1. 검증 흐름 — 판정이 만들어지는 경로

```
 골든(goldenfab) 수정 ─▶ [compare_golden] ─▶ 스냅샷 519도형 전수 대조 ─┬─ 불일치 0 ─▶ PASS(반영 허용)
                                                                      └─ 불일치 ≥1 ─▶ FAIL(반영 금지)
 실전 덱(deck.pptx) ─▶ [check_contract] 계약 3자 대조 ─▶ [audit_deck/audit_pptx] ─▶ [P4 병렬 채점] ─▶ 판정
 검사기 자신        ─▶ [--selftest 결함 주입] ─▶ 전건 검출 + 오탐 0 이어야 검사기로 신뢰
```

해설 1줄: 판정 대상은 3층 — 골든(스냅샷 회귀), 실전 덱(계약·오딧·채점), 그리고 검사기 자신(selftest).

## 5. 실증 예시(walked example) — 간선 총계 2,697이 2,694로 정정되기까지

"산문 검산 폐기 → 기계 대조" ADR이 실제로 오류를 잡은 과정. 근거: `_workspace_kifrs/07-s8-s9-verify.md`(기계 대조 PASS)·`07-s8-s9-selftest.md`.

1. **입력**: 골든 S9(지식그래프)에 적혀 있던 간선 총계 **2,697** — 원천 데이터에서 눈으로 옮겨 적은 값(그래프 v14 총계).
2. **기계 대조**: `verify_s8s9_data.py`가 간선을 7종으로 분해해 원천과 대조 — hier 79 · cp 250 · e3 244(중복 제거 264→244) · case 1,220 · term 755 · example 74 · e2 7 = 2,629, 여기에 BC 간선 65를 더해 **2,694**.
3. **판정**: 골든 표기 2,697은 e3 중복 제거 전 폐기값 — 불일치 검출, **2,694로 정정**. 같은 대조에서 용어 등재 423의 등급 분해(자동 316+위임 86+검토 18+제외 2+확정 1)도 전항 OK.
