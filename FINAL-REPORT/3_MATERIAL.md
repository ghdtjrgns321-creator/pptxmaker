 ▶ ① 재료 ◀ ─ ② 질문 후보 ─ ③ 갤러리 ─ ④ 선택 ─ ⑤ 조판 ─ ⑥ 눈검증 ─ ⑦ 채점
```

```
 <프로젝트>/FINAL-REPORT/*.md

        ├──────────────▶ scan_material.py ──▶ 절별 구조·개수·근거

## 재료는 단일 원천이다

콘텐츠는 사용자가 프로젝트별 `FINAL-REPORT/`(보고서형 md 묶음)로 **미리 정리해둔다.** 추출
단계가 없다 — 사람이 작성·검증한 as-built라 밀도·출처가 이미 확보돼 있기 때문이다.

FINAL-REPORT가 얇으면 억지로 창작하지 않는다. ① 인터뷰에서 보강 재료(추가 문서·스크린샷)를
요청한다.

## 재료를 기계가 센다 — `scan_material.py` (204줄)

### 왜 있나

질문 후보(②)를 내려면 재료를 세어야 한다. 그런데 그 "센 값"을 사람이 손으로 적으면 두 가지가
무너진다.

1. **그림을 먼저 떠올리고 거기 맞는 숫자를 적을 수 있다** — 판정을 앞으로 숨긴 것이다.
2. **재현되지 않는다** — 같은 보고서를 두 번 읽으면 두 번 다른 값이 나온다.

그래서 md 원문에서 기계가 센다. **이 스캐너는 그림을 모르고 부품 이름도 모른다.**

### 무엇을 세나

| 세는 것        | 방법                                                | 코드                  |
| -------------- | --------------------------------------------------- | --------------------- |
| 표 행 수·열 수 | `\|`로 시작하는 줄, 구분선(`---`) 제외              | `scan_material.py:56` |
| 번호 목록      | `^\s*(\d+)[.)]\s+\S`                                | `:44`                 |
| 불릿 목록      | `^\s*[-*]\s+\S`                                     | `:45`                 |
| 화살표 링크    | `[→▶]\|->\|─▶`                                      | `:47`                 |
| 순서 여부      | 머리글에 `단계·순서·순번·step·phase·시점·연도·일자` | `:49`                 |
| 부가 열        | 열이 3개 이상이면 `extra=True`                      | `:109`                |

한 절에서 **가장 큰 구조**를 골라 그것만 낸다(`max(cands, key=lambda c: c["n"])`, `:101`).

### 무엇을 세지 않나

- **어느 절이 슬라이드가 되는지 고르지 않는다** — ①GRILL과 ②의 일이다.
- **의미를 읽지 않는다** — "이 표가 대비인가 나열인가"는 판정이라 열 수만 센다.

그래서 출력에 `_evidence`(무엇을 보고 세었나)를 붙인다. 사람이 뒤집어 볼 수 있어야 한다.

### 실측이 낳은 규칙 하나 — 화살표 80% 문턱

표 셀 안 화살표를 전부 링크로 세면 오판이 난다. 15행 표에서 **한 행의 설명 문장**에 "A → B"가
있다는 이유로 1:N 방사 구조로 잡혔다(2026-07-27 실측). 그래서 문턱을 걸었다.

```python
rows_with = sum(1 for r in best["rows"] if ARROW.search(" ".join(r)))
if rows_with >= max(2, int(len(best["rows"]) * 0.8)):
    out["sets"] = 2      # 행마다 좌·우가 있다 = 두 묶음의 대응
    ev["링크"] = f"{rows_with}/{len(best['rows'])}행이 쌍 — 골격으로 인정"
elif rows_with:
    ev["링크"] = f"{rows_with}/{len(best['rows'])}행만 화살표 — 산문 표기로 보고 무시"
```

**무시했다는 사실 자체를 근거에 남긴다.** 조용히 버리면 사람이 뒤집어 볼 수 없다.

## 아웃라인 계약 — `deck-outline-grill` (①)

FINAL-REPORT만으로는 알 수 없는, **사용자 머릿속에만 있는 "이 장에서 가장 전하고 싶은 것"**을
개방형 질문으로 뽑아 그대로 채록한다. 구조 승인이 아니라 콘텐츠 인터뷰가 본체다.

| 순서 | 무엇을 하나                                                                        |
| ---- | ---------------------------------------------------------------------------------- |
| 1    | **목차 추천 1안 제시** — 빈 종이에서 묻지 않는다                                   |
| 2    | **부 단위 강조 질문** — "문제 인식에서 가장 강조되는 점이 뭐야?" 개방형            |
| 3    | **장 단위 전달 포인트** — 답변 원문이 그 장의 핵심 메시지가 된다(의역 금지)        |
| 4    | **새 재료 수집** — "비교 스크린샷 있어" 같은 게 나오면 받아서 `_workspace/`에 편입 |
| 5    | **한 번에 질문 하나** — 중복 감지(pull 원칙) · 종료 조건은 사용자의 "확정" 발화    |

산출물 `_workspace/01.5_outline.md`는 **이후 단계의 계약**이다 — ②부터 ⑤까지 장을 임의로
추가·삭제하거나 메시지를 바꾸지 못한다.

**왜 이 게이트가 있나(실측):** 골든 덱을 이 게이트 없이 진행했더니 S5 중복 삭제와 Part Ⅲ 재편이
전부 **빌드 후에** 발생했다. 구성은 빌드 전 텍스트 단계에서 확정하는 게 가장 싸다.

## 실증 예시 — 이 보고서 자신을 스캔한 결과

집필 중인 `FINAL-REPORT/` 3개 파일에 스캐너를 돌린 실제 출력이다.

```
$ uv run python .claude/skills/pptx-build/scripts/scan_material.py FINAL-REPORT/

절                                   구조    n   근거
0_README.md · 읽는 순서                표    13   셌다=표 13개 · 열=3
0_README.md · 핵심 수치                표    10   셌다=표 10개 · 열=3 · 링크=1/10행만 화살표 — 산문 표기로 보고 무시
1_OVERVIEW.md · 문제 정의              표     4   셌다=표 4개 · 열=3
1_OVERVIEW.md · 아키텍처 원칙           표     6   셌다=표 6개 · 열=3
1_OVERVIEW.md · 기술 스택              표     7   셌다=표 7개 · 열=3
1_OVERVIEW.md · 무엇이 아닌가           목록    3   셌다=목록 3개
2_PIPELINE.md · 단계 표                표     7   셌다=표 7개 · 열=5 · 순서=머리글에 단계/순서 계열 낱말

7개 절 — 어느 것이 슬라이드가 되는지는 ①GRILL·컴포저가 정한다

■ 축을 못 정한 절 6개 — ①GRILL이 물어볼 목록
  읽는 순서        이 표가 그냥 나열인가, 두 쪽을 맞대어 비교하는 것인가 / 행에 순서가 있나
  ...
```

세 가지가 보인다.

1. **`핵심 수치` 절**에서 화살표 1행이 잡혔지만 문턱(10행 × 0.8 = 8행)에 못 미쳐 **무시하고
   그 사실을 근거에 남겼다.**
2. **`단계 표`**는 머리글에 "단계"가 있어 `ordered=True`로 잡혔다 — 이 절은 시간축·절차 형태가
   후보에 오를 근거가 생겼다.
3. **6개 절은 "축을 못 정했다"**고 스스로 표시하고 GRILL이 물어볼 목록으로 넘겼다. 스캐너가
   판정하지 않고 사람에게 미룬 것이다 — 이게 설계 의도다.
