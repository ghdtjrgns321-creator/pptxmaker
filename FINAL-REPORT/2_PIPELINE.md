## 무엇이 강제되고 무엇이 안 되나

```
 강제됨(코드)                    강제됨(왕복)              강제 안 됨(산문)
 ──────────────────             ─────────────────         ──────────────────
 brand-kit 색·폰트·크기          ④ 사용자 번호 선택        반려 목록 8건
 grid 좌표계·자리 파생           ⑥ PNG 눈검증              design-rules 판단 지식
 layouts 정형 3장
 score_deck 12검사 + 밀도
 add_diagram 미지 layout → 죽음
```

오른쪽 칸은 **무시될 수 있다.** 그래서 이 시스템은 오른쪽을 최소로 유지하고, 새 반려가 나오면
왼쪽 두 칸으로 내리는 것을 먼저 시도한다([8](8_INHERITANCE.md)).

## end-to-end 실증 예시 — s05 한 장이 흐른 실제 기록

2026-07-29 pptmaker 자체 소개 덱을 만들며 실제로 일어난 일이다.

**① 재료** — `FINAL-REPORT`에서 s05가 다룰 대목을 읽었다. 첫 문장이 "이 프로젝트에는 두 얼굴이
있다"였다.

**② 질문 후보(1차 실패)** — 그 첫 문장만 보고 **혼자 구조를 확정했다.** "두 얼굴 = 병렬"이라고
읽고 2열 대비로 그렸다. 실제 재료는 "공장은 목표, 루프는 방법"이고 네 단계가 **순환**하는
구조였다. 형태가 내용과 어긋났다.

**② 질문 후보(2차)** — 구조를 혼자 정하지 않고 후보 6개를 냈다.

```
① 사각 순환      네 단계가 닫힌 경로를 돈다
② 나선 계단      돌 때마다 올라간다
③ 감싸기         공장을 루프가 감싼다
④ 맞물린 두 축   목표와 방법이 톱니처럼
⑤ 직선+되먹임    앞으로 가되 뒤로 화살표 하나
⑥ 나란한 두 목록 (대조군 — 원래 그렸던 것)
```

**③ 갤러리** — `_lab/mock_s05.py`로 6개를 **실제 pptx로 그렸다.** 후보마다 "답하는 질문"을
같이 적었다. 형태만 늘어놓으면 못 고른다는 것은 앞선 반려에서 배운 것이다([12](12_TROUBLESHOOTING.md)).

**④ 선택** — 사용자 회신: **"1이 나아"**.

**⑤ 조판** — 사각 순환으로 구현. 네 노드를 상·우·하·좌에 배치하고 화살표로 닫힌 경로를 만들었다.
조판 중 판단 하나가 더 나왔다 — 각 단계의 **사례를 노드 밖에 두면 화살표가 지나간다.** 그래서
노드 안쪽 하단으로 넣었다.

```python
# _lab/deck2.py:s05 — 자리는 호출자가 계산하고 grid가 자를 준다
RX = 8.30
bw = RX - G.MARGIN_L - 0.40
nw, nh = 2.42, 1.16
pos = [(cx - nw/2, by), (G.MARGIN_L + bw - nw, cy - nh/2),
       (cx - nw/2, by + bh - nh), (G.MARGIN_L, cy - nh/2)]
# 사례는 노드 **안** 하단에 — 밖에 두면 화살표가 지나간다
```

**⑥ 눈검증** — PowerPoint COM으로 렌더해 PNG를 Read. 겹침 없음 확인.

**⑦ 기계 채점** — `score_deck.py --body 4,5,7,9,10,11,12,14,16` 실행. s05는 도형 46개로 PASS.

이 한 장이 보여주는 것: **구조 오독은 ②에서 규칙으로 못 막혔고, ③④의 왕복으로 막혔다.**
"재료를 정확히 읽어라"라는 규칙을 아무리 정교하게 써도 첫 문장을 오독하는 것은 막지 못한다.
후보를 그려서 보이면 사용자가 1초 만에 고른다.
