## 4-1. 토큰 — `brand.yaml`

컨셉은 **무채색 + 포인트 하나(Muted Ember)**. 구조는 근흑이 지고 오렌지는 핵심 수치에만 쓴다.

### 색 11

| 키                                   | 값                                        | 뜻                                                |
| ------------------------------------ | ----------------------------------------- | ------------------------------------------------- |
| `ink`                                | `1F2329`                                  | 본문 잉크                                         |
| `dark` / `dark_lt`                   | `15171B` / `2A2D33`                       | 근흑 — 표지·간지 배경·표 머리 / 그 위 칩          |
| `struct` / `struct_lt`               | `15171B` / `F2F3F5`                       | 구조 강조 **= dark**. 파랑 자리를 근흑이 대신한다 |
| `accent` / `accent_lt`               | `D66E3A` / `FBF1EA`                       | Muted Ember — 핵심 수치·강조 바. **소량만**       |
| `muted` · `line` · `panel` · `white` | `8A9099` · `DCDEE1` · `F2F3F5` · `FFFFFF` | 보조·선·면                                        |

`struct == dark`인 것이 이 팔레트의 핵심이다. 구조 강조색이 근흑으로 접혀 있어 오렌지가
포인트 자리를 독점한다.

### 글꼴 9단 · 판형 6

```yaml
sizes: {cover:40, div:30, title:24, kpi:22, lead:13.5, h:11.5, body:10.5, small:9, tiny:7.5}
font: "Pretendard"
frame: {slide_w:13.333, slide_h:7.5, margin:0.62, rule:1.02, top:1.18, bottom:6.90}
```

단을 벌려 둔 이유는 **중간 크기 몰림**을 막기 위해서다. 22와 24 사이가 비어 있으면 "적당히
큰 글자"로 도망갈 자리가 없다.

`frame.rule`(헤더 밑줄)은 원래 1.18이었다. 눈썹 한 줄이 부 탭으로 대체되면서 그 위가 0.45″
비어, 머리띠를 통째로 올리고 `top`도 1.34 → 1.18로 내렸다. **본문 세로가 5.56″ → 5.72″로
2.9% 넓어졌다.**

## 4-2. 원시도구

| 함수                                   | 무엇                                                            |
| -------------------------------------- | --------------------------------------------------------------- |
| `T(slide,x,y,w,h,lines,...)`           | 텍스트 블록. 넘침을 **추정해 경고**하고 차단하지 않는다         |
| `R(slide,x,y,w,h,fill,line,...)`       | 사각. 그리는 순간 우변 초과를 경고                              |
| `BAR(slide,x,y,w,h,frac,color,track)`  | 비율 막대                                                       |
| `ARROW` · `CONNECT` · `LINK`           | 화살표·커넥터. `LINK`는 두 도형의 상대 위치로 접점을 고른다     |
| `IMAGE` / `image_h` / `image_ar`       | 그림. **칸을 그림에 맞춘다**                                    |
| `cover` · `toc` · `divider` · `header` | 페이지 골격 4. `blank`(빈 슬라이드)와 함께 조판이 부르는 입구다 |
| `set_parts` · `set_context`            | 덱 단위 상태                                                    |

### 한글 조판은 두 조각이 쌍이다

```python
p._p.get_or_add_pPr().set("eaLnBrk", "0")     # 어절 단위 줄바꿈
for tag in ("a:latin", "a:ea", "a:cs"):        # 세 자형 전부에 글꼴
    el.set("typeface", FONT)
```

`eaLnBrk=0`을 안 걸면 PowerPoint가 글자 단위로 끊어 고아 글자가 생긴다. 자형 셋 중 하나라도
빠지면 한글이 다른 꼴로 나온다. 둘 다 코드가 강제하므로 조판이 잊을 수 없다.

### 칸을 그림에 맞춘다 — 순서를 뒤집은 헬퍼

```python
def image_h(fname, w, caption=False, cap_h=0.24) -> float:
    """**폭 w를 다 쓸 때 필요한 칸 높이.**"""
    return w / image_ar(fname) + (cap_h if caption else 0)
```

보통은 칸을 정하고 그림을 우겨넣는다. 그러면 칸의 5%가 빈다. 이 헬퍼는 폭만 정하고 **높이를
그림에게 묻는다.** 안 쓰면 `IMAGE`가 채움률 미달을 경고하면서 해결책까지 메시지에 적는다.

### 도해 부품을 만들지 않는다

```python
def CONNECT(slide, x1, y1, x2, y2, *, elbow=False, head=True, ...):
    """… (앞줄 생략)

    **도해 부품을 만들지 않는 이유.** 흐름도·관계도를 `flow()` `graph()` 같은 블록으로
    굳히면 안 맞는 내용에도 그 형식으로 그리게 된다(2026-07-29 실측: 전 장이 같은 형식)."""
```

이 저장소가 가진 도해 부품은 **0종**이다. 사각과 커넥터만 주고 배치는 매번 좌표가 정한다.

## 4-3. 페이지 골격 — 부 내비게이션

`header()`가 그리는 것: 제목(24pt) · 밑줄 · 좌측 근흑 마디 · 푸터 · **그리고 부 탭 줄**.

```
룰 기반 검증 29종        Ⅰ 분석 범위와 문제 인식   Ⅱ 합성 데이터 생성   Ⅲ 분석 모델   Ⅳ 검증   Ⅴ 핵심 의사결정과 한계
━━━━━                                                              ━━━━━━━━━━ ← 밑줄 위 강조 바
```

| 규칙                                                | 왜                                                                                   |
| --------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 시작 x **고정**(6.00)                               | 장마다 탭이 움직이면 눈이 매번 찾아야 하고, 그러면 내비가 아니다                     |
| 항목 폭 = 제 글자만큼, 남는 폭을 간격으로 균등 분배 | 균등분할하면 짧은 부에 빈칸이 생기고 긴 부가 눌린다                                  |
| 간격 < 0.16″면 경고                                 | 메시지가 "**계약의** 부 제목을 줄인다"를 지목한다 — 조판이 아니라 계약을 고치라는 뜻 |
| 강조 바를 밑줄 위에 얹는다                          | 좌측 근흑 마디와 같은 선이라 새 요소를 만들지 않는다                                 |
| 도형 이름에 `부내비:{로마자}`                       | **게이트가 이 이름으로 찾는다** — 조판·게이트의 유일한 결합점                        |
| 간지에는 안 넣는다                                  | 간지 자체가 부 표시다                                                                |

가로로 늘어놓은 이유는 세로가 나빠서가 아니라, **가로가 제목 옆 빈 공간을 쓴다**는 사용자
판단이었다. 세로 시안은 7.5pt 5줄로 우상단에 붙였는데 공간을 덜 썼다.

## 4-4. 블록 8종

전부 `(s, x, y, w, h, 데이터, …)` 형태로 **주어진 사각형 안만** 그린다. 자기 자리를 모른다.

| 블록               | 데이터                        | 소유하는 것                                               | 호출자가 정하는 것                  |
| ------------------ | ----------------------------- | --------------------------------------------------------- | ----------------------------------- |
| `kpi_strip`        | `[(라벨,값,부연)]`            | 가로 균등분할 · 3층 위계(tiny/kpi/tiny)                   | 자리 · 항목 · 면 색                 |
| `slot_cards`       | `[(제목,묻는것,산출물,근거)]` | **행=항목 · 칸=슬롯** · 슬롯 구분선                       | 슬롯 라벨(`cols`)과 폭 비(`ratios`) |
| `numbered_steps`   | `[(제목,설명)]`               | 자동 번호 배지 · 행 높이 `h/n`                            | 제목 열 폭 · **강조 인덱스(`hot`)** |

| `value_bars`       | `[(라벨,값,비율,설명)]`       | `frac >= 0.999`면 accent — **최댓값 자동 강조**           | 4개 열 폭 전부                      |
| `card_grid`        | `[(코드,이름,태그)]`          | 행 수 자동 · 셀 3분할 · **접지 않는다**(전수가 목적)      | 열 수 · 태그→색 매핑                |

형태를 바꾸는 인자는 `slot_cards.cols`/`ratios`, `numbered_steps.hot`, `compare_table.right_hot`,
`card_grid.ncol`/`tag_colors`뿐이다. 나머지는 치수만 바꾼다.

### 슬롯 카드는 왜 가로인가

```python
def slot_cards(s, x, y, w, h, items, gap=0.10,
               cols=("묻는 것", "산출물", "근거"), ratios=(1.0, 1.0, 0.95)):
    """items = [(제목, 묻는 것, 산출물, 근거), ...] — **행 = 항목, 칸 = 슬롯.**"""
```

한 줄씩 쌓으면 카드 오른쪽이 통째로 빈다. 2열로 나눠도 반씩 같은 문제가 생겼다. 폭 전체를
슬롯으로 쪼개고 슬롯마다 라벨을 달면 **칸이 내용보다 넓어질 수 없고, 같은 슬롯끼리 세로로
비교된다.**

### 표 행 높이는 누르지 않는다

```python
if rh > LIM["table_row_warn"]:
    # 누르지 않는다 — 강제로 줄이면 긴 셀 텍스트가 잘린다. 알리기만 하고 판단은 눈이 한다.
    WARN.append(f'S{CUR["n"]:02d} 표 행 높이 {rh:.2f}" > {LIM["table_row_warn"]}" ...')
```

메시지에 권장 높이를 계산해 준다. 이것이 원칙 3(**기계는 통보자**)이 코드로 드러난 자리다.

## 실증 — S7의 「생성 순서 8단계」가 그려지는 과정

재료 `README.md ## 3-1`에 8단계 생성 순서가 표로 있다. 계약이 이 장의 초점을
*"실데이터가 없어서 직접 만들었다 = 회계 무결성을 지키며 만들었다"*로 확정했다.

조판은 이렇게 부른다:

```python
B.numbered_steps(
    s, M, TOP + 0.66, 5.90, 4.20,
    [("계정과목표", "가용 계정과목 풀 사전 생성 · 룰이 참조하는 계정(가지급금 1190) 고정"),
     ("마스터데이터", "거래처 · 고객 · 자재 · 자산 · 직원(권한 한도 포함)"),
     ...],
    lab_w=1.55,
)
```

블록이 계산하는 것: 행 높이 `4.20 / 8 = 0.525″`, 배지 크기 `0.30 × min(0.30, 0.525-0.06)`,
번호는 `str(i+1)` 자동. 제목은 `h`(11.5pt) 볼드, 설명은 `small`(9pt) muted.

블록이 **모르는 것**: 이 8단계가 왼쪽 열에 놓일지 가로 체인으로 눕을지. 그건 `x, y, w, h`를
주는 쪽이 정한다. 같은 계약으로 세 번 만든 실험에서 두 회차는 세로 열, 한 회차는 **가로 8칸
체인**으로 눕히고 6번 단계만 회색으로 꺼서 *"이 장에서는 안 도는 단계"*를 표시했다.
같은 블록에서 나온 서로 다른 장이다.
