## 좌표계 — `grid.py`

캔버스는 16:9 13.333″ × 7.5″. 주요 상수는 **골든에서 실측한 값**이다.

| 상수                             | 값           | 뜻                         |
| -------------------------------- | ------------ | -------------------------- |
| `MARGIN_L` / `RIGHT_EDGE`        | 0.6 / 12.733 | 좌우 여백                  |
| `COL_L_X` / `COL_L_W`            | 0.6 / 3.1    | 좌 컬럼(끝 3.7)            |
| `COL_R_X` / `COL_R_W`            | 4.2 / 8.533  | 우 컬럼(끝 12.733)         |
| `V_RULE_X`                       | 3.95         | 컬럼 사이 세로 룰          |
| `CONTENT_TOP` / `CONTENT_BOTTOM` | 1.75 / 6.35  | 콘텐츠 상·하한             |
| `BAR_Y` / `SOURCE_Y`             | 6.60 / 7.15  | 결론 바 · 출처선           |
| `CAP_PITCH`                      | 0.42         | 세로 피치 상한 = 골든 리듬 |

### 자리를 개수에서 파생한다 — `pitch()` · `track()`

리터럴 피치(`top + i*0.42`)를 쓰면 항목이 늘어난 순간 **조용히 하한을 넘는다.** 그래서 개수에서
파생한다. 그런데 파생만으로도 부족하다 — 항목이 아주 많으면 피치가 칩 높이보다 작아져
**칩끼리 겹친다.**

```python
p = min(cap, (bottom - top - h) / (n - 1))
if p < h:
    room = int((bottom - top - h) / h) + 1
    raise ValueError(...)      # 시끄럽게 죽인다
```

하한(6.35)은 안 넘으므로 경계 검사는 통과한다 — **조용히 틀리는 값**이다. 2026-07-15 케이스
테스트가 잡았다: 개념 18개 → 피치 0.109″ < 칩 높이 0.24″.

`cap=0.42`는 반대 방향을 막는다. 여유가 많아도 **골든 리듬보다 벌어지지 않는다.**

## 정형 3장 — `layouts.py`

`cover` · `toc` · `part`는 **확정 구현**이다. 좌표·서식을 임의로 바꾸지 않고 콘텐츠만 dict로
받는다. 본문 장은 자유롭게 그리되 이 셋은 고정 — 그래야 덱이 한 벌로 보인다.

## 실증 예시 — s05 사각 순환 한 장이 조판된 과정

[2_PIPELINE](2_PIPELINE.md)에서 사용자가 고른 ①번(사각 순환)을 실제로 그린 코드다.

```python
def s05(prs):
    """형식: 사각 순환 — 네 단계가 닫힌 경로를 돈다(사용자 선택 ①)."""
    RX = 8.30                                    # 우측 설명 패널 시작
    bw = RX - G.MARGIN_L - 0.40                  # 도해 폭을 grid 상수에서 파생
    by, bh = 1.02, 4.10
    nw, nh = 2.42, 1.16                          # 노드 크기
    NODES = [
        ("만든다",        "덱 한 벌을 재료에서 뽑는다", "재료 → 계약 → spec → pptx",
         C["primary"], C["bg"]),
        ("결함이 드러난다", "게이트가 모르는 것이 나온다", "밋밋한 카드가 전 검사 통과",
         C["bg"], C["primary"]),
        ...
    ]
    # 상 · 우 · 하 · 좌 네 자리 — 중심에서 파생한다
    pos = [(cx - nw/2, by), (G.MARGIN_L + bw - nw, cy - nh/2),
           (cx - nw/2, by + bh - nh), (G.MARGIN_L, cy - nh/2)]
    # 사례는 노드 **안** 하단에 — 밖에 두면 화살표가 지나간다
```

세 가지가 보인다.

1. **자리를 리터럴로 안 쓴다** — `bw`를 `G.MARGIN_L`·`RX`에서 뺀다. 패널 위치가 바뀌면 도해
   폭이 따라 움직인다.
2. **네 노드 좌표를 중심에서 파생**한다. 노드 크기를 바꿔도 사각형이 유지된다.
3. **주석이 판단을 남긴다** — "사례를 노드 밖에 두면 화살표가 지나간다"는 그리다가 발견한
   것이고, 다음에 같은 형태를 그릴 때 다시 발견하지 않아도 된다.

색 지정이 `C["primary"]`/`C["bg"]`로만 되어 있는 것도 규칙이다. **hex를 직접 쓰지 않는다** —
brand-kit을 바꾸면 이 장도 따라 바뀐다.
