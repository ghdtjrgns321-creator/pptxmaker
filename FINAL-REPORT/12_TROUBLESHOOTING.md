## 대표 사고 흐름 — #1 검사기가 산출물을 오염

```
 오딧이 도형 색을 읽는다
   sh.line.color.type
        │
        ▼
 python-pptx ColorFormat이 XML을 **생성**한다
   <a:ln><a:solidFill/></a:ln>   ← 빈 solidFill
        │
        ▼
 PowerPoint가 그것을 검정 헤어라인 테두리로 그린다
        │
        ▼
 게이트는 prs.save() **전에** 돈다
        │
        ▼
 테두리가 파일에 그대로 저장됨 ── 게이트는 전부 green
        │
        ▼
 legacy 배선 후 fixture 렌더 눈검증에서 발각
   "전 텍스트 상자에 테두리가 생겼다"
```

**게이트가 통과시킨 게 아니라 게이트가 만든 결함이었다.** 눈검증이 없었으면 못 찾았다.

## 교훈

| 사고 | 한 줄 원칙                                                                    |
| ---- | ----------------------------------------------------------------------------- |
| 1    | 검사기는 대상을 절대 변형하지 않는다                                          |
| 2    | 좌표 계산은 자기 컨테이너 기준으로 — 전폭 상수를 부분 폭에 쓰지 않는다        |
| 3    | 회전 도형이 하나만 있어도 기하 검사 전체가 오염된다. 좌표 보정은 한 곳에서    |
| 4    | 소수 사례를 구조로 승격하지 않는다. 무시한 것은 무시했다고 남긴다             |
| 5    | 근거 있는 임계도 부작용을 만든다. 파생값이라고 안전한 게 아니다               |
| 6    | 자기 판정을 자기가 검증하면 오판이 통과한다                                   |
| 7    | 옮긴 뒤 남는 참조는 경로만이 아니다 — 개념 이름도 지시가 된다                 |
| 8    | 검사는 쓰기 전에 전부 모아서 한다. 중간 실패가 앞선 성공을 지우게 두지 않는다 |
