# 9. 차별점과 한계

## 통상적 접근과의 비교

| 관점      | 통상적 접근                 | 본 프로젝트                                            | 차이가 만드는 효과                    |
| --------- | --------------------------- | ------------------------------------------------------ | ------------------------------------- |
| 형식 결정 | 내용 유형 → 레이아웃 매핑표 | **매핑표 없음.** 장마다 질문 후보를 그려 사용자가 고름 | 장마다 다른 형식이 나온다             |
| 반려 시점 | 완성본을 보고 반려          | 스케치(갤러리) 단계에서 번호로 선택                    | 반려에 **방향**이 생긴다              |
| 표·차트   | 이미지로 굳음               | python-pptx 네이티브 개체                              | 받은 사람이 값을 고치면 다시 그려진다 |
| 임계      | 리터럴("장당 5개")          | 골든 스냅샷에서 **파생**(535자)                        | 기준선이 바뀌면 임계가 따라 움직인다  |
| 규칙 축적 | 반려 → 규칙 추가            | 반려 → 코드·왕복 먼저, 안 되면 부정형 한 줄            | 규칙이 다음 반려를 낳지 않는다        |
| 미지 입력 | 기본값으로 폴백             | `ValueError`로 죽음                                    | 조용히 틀린 그림이 안 나온다          |
| 검사기    | 대상을 읽는다               | 대상을 **변형하지 않는다**(lxml 읽기 전용)             | 오딧이 산출물을 오염시키지 않는다     |

## 특장점 — 근거 있는 것만

### 1. 형식 배정 코드를 없앤 것 자체

`registry` 15타입을 폐기했다. 근거: 그것이 있을 때 **9장이 전부 "상단 밴드 + 하단 카드 4장"**
으로 나왔다(2026-07-29 1차 실험, 사용자 반려). 폐기 후 2차 실험에서 9장이 전부 다른 형식이
됐다 — 2열 대비 매트릭스 · 사각 순환 · 세로 타임라인 · 전폭 데이터 표 · 계산 워크시트 ·
실물+콜아웃 · 계단 · 수치 대시보드 · 갤러리.

근거 경로: `_archive/code/goldenfab/registry.py`(폐기분) · [11_JOURNEY](11_JOURNEY.md)

### 2. 임계가 실측에서 파생된다

`density_band()`가 `golden-snapshot.json`에서 계산한다 — 골든 본문 10장 중 가장 성긴 장의
글자 수 × 0.85 = **535자**. 리터럴이 아니라 함수다.

근거 경로: `goldenfab/audit.py:density_band()` · [7_GATES](7_GATES.md)

### 3. 부품이 자리를 소유하지 않는다

모든 렌더러가 `(slide, spec, brand, x, y, w, h)`를 받는다. 자리는 호출자가 정한다. 아카이브한
`figures/`는 `LAYOUT` 기본값에 골든 실측 좌표를 물고 있었고, 그래서 **그대로 부르면 골든이
딸려왔다.**

근거: 렌더러 24종 단독 호출 스모크 19/24(실패 5건은 필드명 오류) · [6_VISUALS](6_VISUALS.md)

### 4. 죽은 참조를 기계로 막는다

`_plan/verify_no_archive_refs.py`가 두 갈래로 검사한다 — 경로 실존(1부)과 죽은 개념
이름(2부). 2부가 필요했던 이유: 1부만 돌렸을 때 `deck-outline-grill`이 아카이브된
파이프라인을 4곳에서 지시하는데 **전부 통과했다**(경로가 아니라 개념 이름이라).

근거: 현재 1부 73건 중 0 · 2부 20종 중 0

### 5. 정직한 공백을 문서에 박는다

미배선 검사 4종, `legacy` 프로파일 대상 0, `brand.name` 미설정, 실전 완주 0건을 각 장에
명시했다. "구현이 있다"와 "배선됐다"와 "도달한다"를 구분한다.

**1번이 가장 큰 한계다.** 이 보고서가 서술하는 파이프라인은 단계별로 실측 검증됐지만
(③갤러리 생성 · ⑤빌드 17장 · ⑦채점 9장), 재료 읽기부터 최종 산출물까지 한 번에 통과한
기록이 없다. 그 이유도 기록해둔다 — 재료(`FINAL-REPORT`)가 아카이브된 구조를 설명하고 있어서
2026-07-31에 전면 재작성했고, 이 문서가 그 산출물이다.
