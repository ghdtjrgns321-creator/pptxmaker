## 2. 지금의 두 시스템 — 왜 자동 경로가 (B)로 새는가

```
  deck-spec.json ─┬─▶ golden.<layout> ──▶ registry.LAYOUTS 15종 ──▶ (A) 손으로 그린 도해
                  │                                                  ◇판정·점선·복귀호·fan-in
                  │                                                  이분매핑·계층트리·경계
                  │                                                     └─ visuals.py 참조 0건
                  │
                  └─▶ type:"diagram" ──▶ visuals.add_diagram 17종 ──▶ (B) 박스+화살표
                                              ▲                          └─ 사용자 전면 반려
                                              │
        archetype-catalog L-ID 37종 ──────────┘   ← 결정표·카탈로그가 전부 이쪽을 가리킨다
        layout-matching 결정표 ────────────────┘      (A) 문법은 카탈로그에 한 줄도 없다
```

**결함의 정확한 자리:** (A)는 렌더러로 **존재**하나 카탈로그·결정표에 **등재돼 있지 않다**.
그래서 컴포저가 형상을 보고 어휘를 고르는 단계에서 (A)는 후보에 오르지 못하고, 남은 (B)가
자동으로 선택된다. 현 실전 스펙(`_workspace_kifrs/02_deck-spec.json`)이 `golden.*` 17장으로
(B) 사용 0건인 건 **사람이 골든을 직접 지목했기 때문**이고, 구 스펙(`_workspace_prev/`)의
`diagram` 13장이 자동 경로의 실제 산출물이다.
