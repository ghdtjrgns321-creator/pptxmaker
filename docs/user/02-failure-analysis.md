# 실패 분석 — 왜 결과물이 "없어 보이는가"

2026-07-09, 결과물 `results/K-IFRS-1115-온톨로지-RAG-소개.pptx`(25장)를 전 장 렌더하고
`data/mckinsey-tech-trends-outlook-2022-full-report.pdf`(184쪽) 대표 10쪽과 육안 대조했다.
결론: **서식(컨설팅 골격)은 입혔지만, 매킨지가 실제로 하는 것 — "한 장 = 큰 전시물 하나", "숫자에게 무대 주기" — 이 빠져 있고, 내용의 고도가 임원용이 아니라 개발일지 수준이다.**

사용자가 느낀 "실제 데이터와 시각화 사이의 갭"의 실체가 이것이다.

## 근본 원인 — 왜 규칙 루프로는 안 되는가

지금까지의 수정 방식은 "증상 하나 발견 → 규칙·게이트 하나 추가"였다(v3 QA 게이트 8종, v4 다양성 게이트 3종).
그런데 위 표의 "규칙으로 고쳐지나" 열이 보여주듯, 갭 7개 중 규칙으로 닿는 것은 3개(#3·#6·#7)뿐이다.

```
[상향식 — 지금 공장]                        [하향식 — McKinsey]
규칙 더미 ─▶ 슬라이드 생성 ─▶ 게이트가 쳐냄     완성된 디자인 언어 ─▶ 모든 장이 그 언어의 문장
     │                                            │
 수렴점 없음: 규칙을 통과하는                  수렴점 있음: "저 모습과 같은가"로
 "규칙적으로 완벽하게 평범한" 덱               장마다 판정 가능
```

- **규칙은 나쁜 것을 막을 수 있지만 좋은 것을 만들지 못한다.** "최소 5종 사용" 다양성 게이트가 증거다 — 형식은 다양해졌는데 여전히 없어 보였다.
- **목표 이미지가 없으면 수정이 끝나지 않는다.** "게이트 통과"는 수렴점이 아니다. 수정에 수정을 반복하게 된 구조적 이유.
