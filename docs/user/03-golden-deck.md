# 03. 골든 덱 전환 — 결정과 진행 방식

## 목적 (명시)

**골든 슬라이드를 하나하나 사용자 승인으로 확정하고, 그 과정에서 나온 규칙을 전부 스킬·코드로
박제해서, 다음 자동화(새 포트폴리오 덱 생성) 때 사용자의 손을 조금이라도 덜 타는 방향으로
한 걸음씩 나아가는 것.** 슬라이드 한 장의 완성이 목적이 아니라, 그 장을 만들며 확정된 판단이
저장소에 남는 것이 목적이다.

규칙 이관 프로세스 (매 장 반복):

1. 시안 여러 개 제시 → 사용자 피드백 반복 → 승인 확정 (예: S4는 시안 A~K, 16버전)
2. 확정 과정에서 나온 판단을 **규칙으로 명문화** → `.claude/skills/pptx-build/references/design-rules.md` (단일 출처, 세션 메모리 아님 — 저장소를 쓰는 누구에게나 적용)
3. 기계로 강제 가능한 것은 **코드·오딧으로 박제** → `goldenfab/kit.py`(도형·텍스트 헬퍼) · `goldenfab/grid.py`(좌표계) · 오딧 5종(정렬·겹침·색 카운트, FAIL 시 렌더 금지)
4. 실행 주체 배선 확인 — "PPT 만들어줘" → pptmaker 오케스트레이터 → pptx-builder 에이전트("pptx-build 스킬을 반드시 읽고") → pptx-build SKILL.md("design-rules.md 필수, 오딧 미통과 산출물 내보내기 금지")

성적표: 규칙이 쌓일수록 다음 장·다음 덱의 승인 반복 횟수가 줄어야 한다 (S4 16회 → S5 목표 2~3회).

2026-07-09 결정: **"증상 → 규칙 추가" 루프를 중단하고, 손으로 만든 골든 덱을 기준으로 공장을 역설계한다.**
성공 기준이 "게이트 통과"에서 "골든 덱과의 일치"로 바뀐다 — 이것이 수렴점이다.
세부 실행 계획(덱 구성·Phase·리스크)은 [05-golden-deck-plan.md](05-golden-deck-plan.md),
최종 확정 덱은 19장·아키타입 15종([08-system-overview.md](08-system-overview.md)).

## 진행 루프 (Phase 1·2 완료 — 진행 상세는 [07](07-factory-port.md)·[08](08-system-overview.md))

```
[골든 덱 제작 — 완료]                 [공장 역설계 — 완료]           [실전 검증 — Phase 3]
golden/ 스크립트로 19장         ─▶  build_pptx에 레이아웃 이식  ─▶  K-IFRS 덱 재빌드로 갭 재점검
부 단위 제작 → 렌더 → 승인? ─┬─예       + 구조 비교 490/490 일치           │
                            └─아니오─▶ 해당 장 재디자인                  ▼
                                                          골든 19장에 없는 형태 발견 시
                                                          그때만 골든 1장 추가 (pull)
```

- 골든 덱 제작: 공장 없이 golden/ 전용 python-pptx 스크립트로 한 장 한 장, 부 단위 승인 루프(시안 렌더 누적 106장).
- 역설계: brand-kit·build_pptx가 골든 덱 재현 기준에 종속된다. 완료 후 golden/ 스크립트는 동결(기준 원본).
- 기존 QA 게이트는 폐기가 아니라 강등: 마감 결함(각주 겹침·잘림 등 갭 #7)처럼 규칙으로 잡히는 것만 담당한다.

## 결정 이력

- 초기 구상은 "아키타입 8장 카탈로그"였으나, 2026-07-09 grilling 인터뷰에서 사용자 목차 6부(문제 인식 → 파이프라인 → 기술 설명 → 문제와 해결 → 차별점 → 성과·증거)를 전부 흐르는 완전한 견본 덱으로 확정했다.
- 시각 무드(다크 단일 vs 흰 본문 + 다크 간지)는 같은 인터뷰에서 흰 본문 + 다크 간지로 해소됐다. 미결정 사항 없음.
