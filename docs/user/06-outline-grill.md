# 06. deck-outline-grill — 목차 공동설계 게이트 (구현 완료)

"PPT 만들어줘 → 전자동 생성" UX의 한계를 인정하고, 빌드 전에 목차와 장별 역할을
사용자와 공동 확정하는 grill식 인터뷰 게이트다. 순수 자동화가 아니라
**"스킬이 초안을 제안하고 사용자가 확정하는 반자동"**이 목표다.
`.claude/skills/deck-outline-grill/SKILL.md`로 구현됐고, pptmaker 오케스트레이터
파이프라인의 ① 단계로 배선됐다("아웃라인 승인 전 ② 진행 금지" 명시).

## 왜 만드는가 — 골든 덱(K-IFRS 1115, 2026-07-10)에서 실증된 문제 3가지

1. **구성 판단은 재료만으로 자동 결정되지 않는다.** 파이프라인 장(S6)에서 AI는 팩트시트
   조각을 서식에 맞춰 배치했지만, "어떤 기술이 주인공인지, 어느 깊이로, 뭘 버릴지"는
   전부 사용자가 사후에 바로잡았다.
   - 사례 ①: 기술 파트가 "그래프 등록부+검증" 2장으로 계획됐는데, 사용자가 "파이프라인
     노드 순서대로 기술 1개=1장(용어사전→지식그래프→판단트리→구조화출력), 각 장은
     구축 방법론→실제 적용→실증"으로 재정의했다.
   - 사례 ②: 계획된 S5(결격 사유 장)는 S4가 내용을 전부 흡수해 중복 판정 → 삭제(17장→16장).
   - 둘 다 빌드 후에야 발견됐다. 미리 물었다면 시안 반복 비용이 없었다.
2. **서식에는 기계 게이트(정렬 오딧·색 카운트)가 있는데 콘텐츠에는 게이트가 없다.**
   AI는 측정되는 서식만 최적화하고, "보는 사람이 이해하는가"('1홉 탐색' 같은 내부 용어
   노출, '판단트리를 어떻게 만들었나'에 대한 답 부재)는 아무도 검사하지 않았다.
3. **딸깍 → 완성본 제시 → 대량 반려 루프는 비싸다.** 반려의 대부분이 서식이 아니라
   구성·강조점 문제였다. 구성은 빌드 전 텍스트 단계에서 확정하는 게 가장 싸다.

## 파이프라인 내 위치 — 첫 단계 (①)

FINAL-REPORT를 재료로 발동한다 — 목차 1안을 재료 기반으로 제안해야 하기 때문이다.

```
① deck-outline-grill ─▶ ② deck-composer ─▶ ②.5 목업 갤러리 ─▶ ③ 빌드 ─▶ ④ QA
   "무엇을 말할 것인가"     deck-spec 작성      "어떻게 보일 것인가"
   목차·장별 역할 승인                         시각 승인
   → 01.5_outline.md (계약)
```

- 산출물(승인된 아웃라인)은 deck-composer의 **필수 입력**이 된다.
- ②.5와 역할 분담: ①.5는 구성(무엇을 말할 것인가), ②.5는 시각(어떻게 보일 것인가)을 각각 승인받는다.

## 인터뷰 방식 — 콘텐츠 인터뷰 (구조 승인이 아니라 육성 채록)

인터뷰의 본체는 목차 승인이 아니다. **FINAL-REPORT만으로는 알 수 없는, 사용자 머릿속에만 있는
"이 장에서 가장 전하고 싶은 것"을 개방형 질문으로 뽑아내 그대로 채록**하는 것이다.
채록된 답변이 곧 그 장의 강조점·콘텐츠 지시가 된다.

진행 순서:

1. **목차 추천 1안 제시** — FINAL-REPORT 기반으로 스킬이 먼저 던진다(빈 종이에서 묻지 않는다).
   예: "문제 인식 → 기술 설명 → 기존 기술과 다른 점 → TEST 결과 제시". 사용자가 수정하거나
   승인하면 구조는 확정, 바로 콘텐츠 질문으로 내려간다.
2. **부(섹션) 단위 강조 질문** — "문제 인식에서 가장 강조되는 점이 뭐야?" 개방형으로 묻고
   답을 그대로 채록. 답변에서 구성 정보가 나오면(예: "파이프라인 설명 후 용어사전·지식그래프·
   판단트리·구조화출력 4개") **되받아 확인**한다: "그럼 파이프라인 1장 + 기술 4장으로 만들
   생각하면 돼."
3. **장 단위 전달 포인트 질문** — 장마다 "여기서 가장 전해주고 싶은 게 뭐야?"를 묻는다.
   예: 지식그래프 장 → "K-IFRS 1115 본문에 위계가 이미 있었고 그걸 따랐다, 자의적으로 만든 게
   아니다"라는 답이 나오면 그 문장이 그 장의 핵심 메시지가 된다.
4. **답변에서 나온 새 재료 수집** — "기존 LLM과 비교 질문한 스크린샷 있어, 내가 줄게" 같은
   추가 재료가 나오면 받아서 _workspace에 편입한다. 인터뷰가 재료 보강 경로이기도 하다.
5. **한 번에 질문 하나.** 중복 감지(한 장의 메시지가 다른 장에 이미 있으면 삭제/병합 제안 —
   S5 사례)와 종료 조건(사용자 "확정")은 grilling 원칙 그대로.

확정본은 `_workspace/01.5_outline.md`로 저장하고 이후 단계의 **계약**으로 취급한다 —
deck-composer가 임의로 장을 추가·삭제하거나 채록된 메시지를 바꾸지 못한다.

## 산출물 형식 (아웃라인 계약)

구성 층만 담당한다. 장마다 최소 3요소: 장 제목, **사용자 육성 답변(그 장에서 전하고 싶은 것,
채록 원문)**, 재료 출처(팩트시트 섹션 또는 인터뷰에서 받은 추가 재료). 상세 스키마는
`deck-outline-grill` SKILL.md에 확정돼 있다(장 목록 표 + 추가 재료 + 삭제·병합 이력 +
자체 점검 4문항). 채록 원문 보존·재료 없는 장 금지·내부 용어 검사 규칙도 SKILL.md가 강제한다.

## 성공 기준

- "PPT 만들어줘" 요청 시 빌드 전에 **반드시 1회 발동** — 오케스트레이터 pptmaker
  SKILL.md의 파이프라인에 ① 단계로 등재됐고 "아웃라인 승인 전 ② 진행 금지"가 명시돼 있다.
- **성적표:** 완성본 제시 후 구성 사유 반려(장 추가/삭제/역할 재정의) 건수가 0에
  수렴하는가. 골든 덱에서는 S5 삭제·Part Ⅲ 재편 2건이 사후에 발생했다 — 이 게이트가
  있었다면 사전에 잡혔을 항목들이다.
