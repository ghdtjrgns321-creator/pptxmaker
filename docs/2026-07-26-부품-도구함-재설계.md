## 2. 왜 — 드러난 구조 결함

골든의 **설계 목적이 재료 창고가 아니었다.** 코드가 스스로 밝힌다:

> `goldenfab/reference.py`: *"골든 레퍼런스 덱(17장·5부) 정의. **회귀 게이트의 기준 산출물.**"*

즉 골든은 "안 변했는지 대조하는 잣대"로 설계됐고, 그래서 **재사용 단위가 장 전체**다.
부품은 479줄(4.0%)뿐이고 도해 15종의 구성 원소는 장 함수 안에 굳어 있다. 그 결과가
같은 화살표 14벌 · 같은 소제목 10벌이다.

### 현재 흐름 — 갈림길이 세 갈래로 갈라지고 두 갈래가 나쁘다

```
슬라이드 1장의 주장
      │
      ▼
 골든 장에 이 형태가 있나?
      │
      ├─ 있다 + 항목 수까지 맞다 ─▶ golden.<타입>  ─▶ 장 함수 호출 + 글만 교체
      │                                                 └ 배치는 K-IFRS 주장에 맞춰 굳음
      │                                                 └ 10/15종이 [고정:N] — 개수 다르면 절단
      │
      ├─ 형태는 맞는데 다르다 ───▶ adapted.<타입> ─▶ 장 스크립트를 손으로 변형(파이썬)
      │
      └─ 없다 ──────────────────▶ novel(손코딩)  또는  (B) 범용 박스 폴백
                                                          └ 실전 사용 0건 · 팔레트 전면 반려된 품질
```

**세 결함이 한 뿌리에서 나온다.**

| 결함                             | 뿌리                                                          |
| -------------------------------- | ------------------------------------------------------------- |
| "골든이랑 맞나"의 판정 기준 없음 | 재사용 단위가 장 전체 → 물성이 아니라 **장 통째로** 맞춰야 함 |
| 글만 교체가 성립 안 함           | 배치가 특정 주장에 결박 + 항목 수 고정 10종                   |
| 골든에 없으면 폴백으로 샘        | 부품이 없어 **조합으로 새로 만들 길이 없다**                  |

## 4.5 선행 완료 — 골든 단일화(dense 승격) · 2026-07-26

쪽으로 잡느냐가 먼저라 승격을 선행 처리했다.

### 9-b. 1차 눈검증 — "자리를 채우면 더 나빠진다"

첫 목업은 부품을 자리 폭에 비례해 늘렸다. 선만 6.8"로 길어지고, 노드가 화면 끝까지 흩어지고,
흐름 띠가 페이지 높이를 다 먹었다. 여기서 **고유 크기 원칙**이 나왔다 — 타이포에 묶인 치수는
자리와 무관하다.

### 9-c. 2차 눈검증 — 같은 원칙이 반대쪽으로 틀렸다 (반려 2건)

사용자 반려: **①** G05 세로판이 1:1인데 선이 전부 **사선**으로 떨어진다 **②** G22·G23·G24·G25가
"너무 대충 · 초등학생 PPT". 실측한 원인은 셋이다.

| 증상                 | 원인                                                                                | 내린 곳                                                                     |
| -------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 1:1인데 사선         | 위·아래 행을 **각각 따로** 가운데 정렬 — 칩 폭이 다르니 열 중심이 어긋난다          | `bipartite_map`: 1:1은 **공용 트랙**, N:M은 **소스 무게중심 + 겹침만 해소** |
| 화면 한구석의 낙서   | 배치 치수 상한을 자리보다 훨씬 작게 박음(격자 4.8"/12.1" · 16:9에 정원 · 위쪽 호만) | 열 폭·행 높이·반지름(**타원**)·호 위아래를 자리에서 파생                    |
| 잉크는 있는데 초라함 | 정보가 **한 겹**(라벨만) — 9pt 칩 한 줄, 각주로만 설명                              | 원소 `card`(2층)·`legend`(마크 실물)·`ribbon`(면으로 잇기)                  |

연결부에서 끊겼고(→ 사다리꼴 리본), 흰 글자를 **두께**로 결정해 회색 띠 위 흰 %·보조줄이
통째로 사라졌다(→ 기준을 **채도**로: accent 띠만 어둡다).

계약 문서(`figures/__init__.py` ①)를 고쳐 **두 방향의 실패를 같이** 적었다 — 1차 반려만 적어둔
탓에 2차 사고가 났다. 회귀 6종 전부 PASS(부품은 아직 골든 장에 안 물려 스냅샷 무영향).

### 9-d. 3차 반려 — "허브 표현이 저게 최선이야? 종류도 빈약하다"

사용자 지적의 핵심은 **어휘의 얕음**이었다. 1:N을 그리는 방식을 하나(방사)만 갖고 있었고,
그 하나도 검정 사각 + 회색 칩이라 "축이 여기"라는 말을 도형이 하지 않았다.

레퍼런스 조사(consulting ecosystem map 3변형 · radial layout · concentric rings · foundation
& pillars)로 확인한 것: **1:N은 하나의 그림이 아니라 인코딩이 다른 넷**이다.

| 부품              | 1:N을 무엇으로 말하나           | 언제 이게 맞나                          |
| ----------------- | ------------------------------- | --------------------------------------- |
| G22 `hub_spoke`   | **동등**(한 궤도) · 굵기=결합도 | 곁가지에 우열이 없을 때                 |
| G26 `orbit_rings` | **거리**=관계 강도(층이 여럿)   | "이 중 무엇이 핵심인가"가 질문일 때     |
| G27 `pillar_base` | **떠받침**(방향이 아래→위)      | 토대를 빼면 무너진다가 요점일 때        |
| G28 `bracket_fan` | **분해**(전체=부분의 합)        | 라벨이 길고 수치가 붙을 때(한국어 기본) |

부수 수정 — G26 링 이름을 옆에 띄우면 어느 링인지 눈이 못 잇는다(→ 링 **위** 6시에 앉히고
그 자리를 비우려 항목 배치를 318°로), G27 기둥이 남는 자리를 다 먹어 항목 밑 2/3가 빈 회색
판이었다(→ 높이를 내용에서 파생).

### 9-e. 4차 반려 — "검색해서 디자인 따온 거 맞아?" · 아니었다

**아니었다.** 웹 검색 두 번이 준 것은 템플릿 판매 페이지와 변형 **이름 3개**(hub-and-spoke ·
concentric rings · radial-network)뿐이고, 실제 디자인은 한 장도 보지 않은 채 그 이름에서
추론해 그렸다. 그런데 **레퍼런스는 처음부터 저장소 안에 있었다** — `ref/` 76장(McKinsey ·
BCG · Deloitte · Accenture 실물 + `catalog.md` 아키타입 색인). 1:N 도해도 색인에 있었다:
`bcggen_p023`(hub_spoke) · `mck_p025`(동심원 계층) · `bcggen_p022`(원형 2×2 허브).

**실물을 열어 대조한 결과 다섯 곳이 달랐다**(표는 `hub_spoke.py` 모듈 docstring에 박제).
핵심은 마지막 둘이 함께 만드는 구조다 — **컨설팅 1:N 도해는 도해 단독으로 페이지를 채우지
않는다.** 도해가 왼쪽 55~60%, 오른쪽은 설명 패널이고 **번호 배지**가 둘을 잇는다. 원은
글을 못 담으므로(내접 사각이 지름의 0.70배) 이름만 넣고 설명은 패널이 받는다. 도해 하나로
12"를 채우려 했던 게 §9-c에서 "정보가 한 겹"으로 나타난 증상의 진짜 원인이었다.

원소 2종을 내렸다: `elbow`(직교 꺾은선 + 접점 — 실물은 사선을 쏘지 않는다) ·
`badge`(도해↔표 번호 대응). 부수로 잡힌 것: 여유를 원 **중심** 기준으로 재서 곁가지가
궤도선을 물었고(→ 테두리 기준), 자리가 남으면 곁가지를 끝까지 밀어 꺾은선만 길어졌다(→ `gap_max`).

> **남은 부채**: G26·G27·G28도 이름에서 추론해 만든 것이다. `mck_p025`는 G26이 구조적으로
> 틀렸음을 보여준다 — 실물은 노드를 링 **위에 앉히지 않고 안에 담는다**(포함 관계 AI ⊃ ML ⊃ 4종)
