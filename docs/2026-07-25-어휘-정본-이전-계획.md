## 왜 (드러난 구조 결함)

시각 시스템이 **두 개로 병존**한다.

|                         | 어디                               | 무엇                                                                                      | 실전 사용                                                                        |
| ----------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **(A) 골든 도해**       | `goldenfab/sNN_*.py` (장별 손빌드) | ◇판정 분기·fan-in 수렴·이분 매핑·계층 트리·실물 카탈로그·IN/OUT 라우팅·경계 안/밖·복귀 호 | **현 실전 덱이 쓰는 것**(`_workspace_kifrs/02_deck-spec.json` = `golden.*` 17장) |
| **(B) 범용 다이어그램** | `visuals.py:add_diagram` 17종      | 박스+화살표                                                                               | **v3 유산**(`_workspace_prev/` = `diagram` 13장). 현 실전 사용 **0건**           |

**결함의 핵심:** `archetype-catalog.md` L-ID 37종과 `layout-matching.md` 결정표가 **전부 (B)를
가리킨다.** 골든 문법은 카탈로그에 없다(registry에만 존재). 그래서 **자동 경로를 타면 폴백이
나온다** — 사용자 덱 품질이 손빌드 골든 장에서만 나온 이유가 이것이다.

부수 사실: 골든은 `visuals.py`를 **전혀 참조하지 않는다**(grep 0건). 두 층이 완전 분리다.

**원인:** v5 전환은 전반부(추출·NotebookLM)만 제거했고, 골든 체계(2026-07-16 "변형 가능한
출발점")를 얹을 때 (B)를 폐기하지 않았다. 어휘가 둘로 남았고 문서는 (B)를 계속 가리켰다.

4. **배선** — **완료 2026-07-25.** "고를 수 있게 만들었지만 실제로 그 길로 가는지·검사가 도는지가
   산문"이던 자리 넷을 기계로 바꿨다.

   **(a) legacy 경로에 정본 게이트 배선.** `generic_checks`에 **프레임 프로파일** 축을 넣었다
   (`dense=bool` → `profile="sparse"|"dense"|"legacy"`). 규칙 코드는 하나, **임계만** 프레임별이다.
   어느 검사를 물릴지는 **legacy 산출물 111장 전수 실측**으로 정했다(분모 = 추적/비추적
   워크스페이스의 모든 deck-spec·exhibit-candidates에서 생존 어휘 슬라이드를 스크립트로 수집·중복 제거).

   | 검사                                            | legacy 위반 | 처분                                                                            |
   | ----------------------------------------------- | ----------- | ------------------------------------------------------------------------------- |
   | 즉흥 카드 · 노드 재탕 · 노드 클래스 · 그림 침범 | 0/111       | **배선**                                                                        |

   | 텍스트 넘침                                     | 6/111       | **배선** — 6건은 오탐 아니라 **진짜 결함**(아래)                                |

   | accent 상한                                     | 28→0        | **배선** — 런 제외 + 실측 상한 8(harvey_table 점수볼)                           |

   | 밀도 밴드                                       | 93/111      | **미배선** — 골든 458자 하한은 legacy에 부적합. 정본은 `audit_pptx` 본문 60단어 |

   러너 배선 2곳: `build_pptx._gate_density`(legacy 타입도 대상) + `consistency-qa/audit_pptx.py`
   (`legacy_gate()` — 이 파일은 전엔 `goldenfab.audit`을 **import조차 안 했다**).

   **(a-1) 부수로 잡힌 버그 — `audit.box()`가 회전을 무시했다.** legacy 프레임의 세로 저작권선은

   화면 중앙을 지나는 것으로 계산돼 **mpl 익스히빗 10장이 "그림이 저작권선 침범"으로 걸렸다(전부 오탐)**.

   **(a-2) `check_text_collision` 정밀화 — 상자가 아니라 글자 실점유로 비교.** legacy 렌더러는
   상자를 넉넉히 잡는다(`bullets` 상자 0.5"에 피치 0.46" → 0.04" 상자 겹침, `_stat_split` 40pt 숫자
   상자 1.4"에 실제 0.67"). **글자는 안 겹치는데 상자만 겹치는** 이 idiom이 오탐 17장의 전부였다.
   겹침 판정에 `h = min(상자 높이, text_need_height)`를 넣어 17→0. 상자가 글자로 꽉 찬 경우엔
   종전과 동일해 검출력이 유지된다 — 주입 프로브(꽉 찬 상자 0.05~0.25" 포갬 전건 검출 / 여유 상자
   오탐 0)를 `test_wiring` ④.5에 **상시 검사**로 박았다. 초판 docstring의 "렌더 추정을 안 쓴다 —
   순수 기하라 추정 오탐 0"은 **틀린 진술**로 정정했다(순수 상자 기하가 오탐의 원인이었다).

   **(a-4) 렌더 눈검증이 잡은 CRITICAL — 오딧이 산출물을 오염시켰다.** fixture 31장을 PNG로 렌더해
   보니 **전 텍스트 상자에 검정 헤어라인 테두리**가 있었다(게이트는 전부 green). 원인:
   `audit.line_hex`가 `sh.line.color.type`을, `runs_of`가 `run.font.color`를 읽는데 **python-pptx의
   ColorFormat은 접근하는 순간 XML을 만든다** — `<a:ln><a:solidFill/></a:ln>`(색 없는 빈 solidFill)이
   붙고 PowerPoint는 그걸 검정 선으로 그린다. 그리고 빌드 게이트(`_gate_density`)는 `prs.save()`
   **전에** 돌므로 그 테두리가 파일에 저장됐다. 즉 **검사기가 대상을 바꿨다.**
   (legacy 배선이 계기다 — 전엔 legacy 텍스트 상자를 아무도 안 읽어서 드러나지 않았다. 골든·dense는
   `add_box`가 선을 명시해 `<a:ln>`이 이미 있어 눈에 안 띄었다.)
   수리: 색 읽기를 **lxml 읽기 전용**으로 전환(`_solid_srgb`) — `fill_hex`·`line_hex`·`runs_of` 셋 다.
   의미는 동등(schemeClr·gradFill은 종전처럼 None). 재빌드 후 빈 solidFill 0건 · 재렌더로 테두리
   사라짐 눈확인. 재발 방지: `test_wiring` **가드 오딧 읽기 전용**(전 프로파일 검사 후 도형 XML 무변화).
   **이것이 "green ≠ 완성"의 이번 실증이다** — 기계 게이트 8종이 전부 통과한 상태에서 눈으로만 보였다.

   **(a-3) 넘침 6건은 진짜 결함(보고).** legacy 헤드라인 상자는 `(0.6, 0.32, 12.13, 0.52)`에 28pt다 —
   **31자를 넘으면 2줄이 되고 필요 높이 0.93"가 상자 0.52"를 넘겨 부제(y=0.86)를 덮는다.**

   재설계(부제를 아래로)인데 legacy는 폐기 트랙이라 **게이트로 드러내는 것까지** 했다.

   **(b) `adapted.`/`novel` content 계약 구멍 봉합.** `_render_scripted`에 계약 검사가 없어
   **실전 덱을 `adapted.`로 만들면 골든 K-IFRS 글이 남아도 전 게이트 green**이었다.
   `content_contract.assert_scripted_content`를 신설해 그 문에 물렸다. 오탐 0 설계:
   요구 키 = **(스크립트 DEFAULT 키) ∩ (스크립트가 실제 읽는 키)**. dense 기준작은 주입해도 안 읽는
   키가 28건이라 DEFAULT 전량을 요구하면 즉시 상시 적색이 된다 — 그 구멍 수 자체는 통합F가
   감소 전용 래칫으로 이미 고정하므로 "안 읽히는 키"를 늘려 검사를 우회할 수는 없다.
   DEFAULT가 없는 스크립트(실전용 신작)는 요구 0키 — novel을 막지 않는다.
   검증: `verify_content_contract` 케이스 ⑥ 신설(dense 9/9 — 요구 3~18키 · 완비통과 · 미주입 FAIL ·

     미배선 검사 표**를 범례 뒤에 추가. §8 체크리스트11의 문턱(3.0×1.5 → 2.4×0.9)·배선 범위도 정정
   - `layout-matching.md` "`adapted.`/`novel`은 **계약 검사 밖**" → (b)로 사실 아님. 무엇이 대체하고

   - `layout-matching.md` 세트 제약 "박스 30%" → 3단계에서 삭제된 게이트(유령). 삭제 사실 + 대체 명시
   - `audit_pptx.skeleton` 검사가 리터럴 `["cover","toc"]`·`"cta"`만 봐서 **모든 현행 덱에서 상시

   (A)**가 된다. `check_candidates` ⑧ 신설: "(A) 1순위 물성인데 (A) 후보 0개 + `why_not_golden` 없음"
   = **FAIL**. 일반 `why_not`으로는 갈음 못 한다(실측: 갈음을 허용하니 구 후보 파일이 "chart:bar를
   쓴 이유" 한 줄로 (A) 검토 의무를 전부 통과했다 — 다른 질문의 답은 이 질문의 답이 아니다).

   읽으므로 "판정 인과냐 집합 대응이냐"는 기계가 못 가른다 — 후보군 전체를 올리고 그중 무엇이냐는
