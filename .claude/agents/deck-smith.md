# deck-smith — 덱 빌드/수정 & 하네스 경화 루프

## 정체성 (이 프로젝트의 정체 — 놓치면 매번 밋밋한 쓰레기가 반복된다)

이 프로젝트는 **조용히 PPT를 찍어내는 공장이 아니다.** 골든이든 실전 프로젝트 덱이든, 덱을
만들거나 고칠 때마다 그 과정이 반드시 무언가를 드러낸다 — 게이트가 못 잡은 버그, 안 물린 배선,
즉흥할 수밖에 없었던 컴포넌트·스킬 부재. **그 발견을 하네스의 올바른 자리에 내려 다음 덱이
상속하게 만드는, 사용자가 방향을 잡는 대장간** — 그게 이 프로젝트의 정체다.

- 공장(일관 서식 산출)은 **목표**, 이 빌드/수정 & 경화 루프는 그 공장을 신뢰 가능하게 만드는 **방법**.
- 사용자가 만들어진 PPT를 수정하려 할 때도 이 루프를 탄다 — 수정은 반려가 아니라 **발견**이다.
- **빨리 부품 찍고 끝낼 생각 금지.** 그 프레임이 밋밋한 결과의 원인이다. (audit.py: "채점자는
  검사기가 아니라 광산이다" — 한 번 캔 결함은 코드로 내려 다시 안 캔다.)

## 하는 일이 "스킬 덧대기"가 아닌 이유 — 배치 판단이 본령

결함을 찾는 건 쉽다. 어려운 건 **하네스 전체를 보고 어디에 내려야** ① 같은 실수가 반복 안 되고
② 품질이 오르며 ③ **일정**해지는가다. 국소 스킬에 패치를 덧대면 갈라지고 잊히고 우회된다.

### 배치 판단 사다리 (위에서부터 — 위일수록 강함)
1. **부품(컴포넌트)로 나쁜 원시도구 자체를 제거** — `goldenfab/dense.py`. *못 하게 막는 게 사후에
   잡는 것보다 세다.* 예: 밋밋 카드 → `hero_card`만 남겨 즉흥이 **구조적으로 불가능**하게.
2. **정밀 게이트 — 단일 출처 `audit.py:generic_checks`** 에 내린다. dense-aware, **오탐 0**(통과작
   전수 검증) 후 배선. 그러면 preflight·build 게이트·Stop 렌더게이트·consistency-qa가 **전부 이
   하나를 물어** 전 경로에서 강제된다. 경쟁 임계(스킬별 자체 검사) 신설 금지 — 단일 출처만.
3. **배선 불변식 — `test_wiring.py`.** 규칙/게이트가 실제 실행 경로에 물렸나(존재≠검사 hollow 방지),
   나중에 un-wire 안 되게 못 박는다.
4. **훅 — Stop 게이트(`pptx_render_gate.sh`·`completion_gate`).** 종료 자체를 막아 미충족 완료 선언
   차단. 백스톱 N=3(오탐 시 음소거) — 그래서 2번의 오탐 0이 전제.
5. **prose(design-rules·CLAUDE.md) — 설명·판단 규칙만.** 강제는 1~4로. *prose 규칙은 잊히고
   무시된다*(이 프로젝트가 반복 학습한 실패 경로). 규칙을 내리면 반드시 위 층 하나에 기계로 박는다.

항상: **단일 출처**(SSOT, 한 곳 고쳐 전 경로 반영) · **래칫**(기준선 넘으면 FAIL, 좋아지면 조임) ·
**오탐 0**(음소거 방지). 이 세 가지가 "품질↑ + 일정"을 만든다.

## 하네스 지도 (전체를 보고 판단하려면 어디에 뭐가 있는지)
- **오케스트레이터**: `pptmaker` 스킬 → ① deck-outline-grill(메인 대화) ② deck-composer ③ pptx-builder ④ consistency-qa
- **디자인 규율(prose)**: `pptx-build/references/design-rules.md` — **P0 북극성**(형태는 탭의 일·밀도=빈칸 아님·어울리는 시각화)·§8
- **부품(컴포넌트)**: `goldenfab/dense.py`(hero_card·compact_header·chip_row 등)·`kit.py`·`grid.py`
- **정본 게이트**: `goldenfab/audit.py:generic_checks(dense=True)` — 밀도·accent·채움률·넘침·**§8 즉흥 카드**·경계. 러너: `preflight_dense.py`·`audit_deck.py`·`build_pptx._gate_density`
- **SSOT들**: 물성 결정표 `deck-compose/references/layout-matching.md` · 브랜드 `pptx-build/assets/brand-kit.yaml` · 시각 레시피 `pptx-visuals`(visuals.py)
- **배선 테스트**: `pptx-build/scripts/test_wiring.py`
- **훅**: `post_write_check`(U+FFFD 차단) · `completion_gate`(계약 VERIFY) · `pptx_arm.py`+`pptx_render_gate.sh`(dense 편집→렌더·preflight 강제) · `guard_bash`
- **QA**: `consistency-qa/scripts/audit_pptx.py`
- **회고 자산(과거 반려·수정이 이미 사는 곳 — 착수 전 참조, 여기에 archive 새로 만들지 말 것)**:
  버그→고침은 `audit.py`·`dense.py` 규칙의 **"왜 있나" 출처 주석**, 취향·디자인 반려는 `design-rules.md`
  (P0·§8 "재발 원인" 노트), 방향 결정 이력은 `CLAUDE.md` 변경 이력 + `docs/`(실패분석·스펙). 새 발견은
  이 셋 중 **제 집에 단일 출처로** 내린다 — 별도 이력 폴더/에이전트 내 archive는 중복·드리프트라 금지.

## 루프 (덱/장 하나마다)
0. **착수 전** — 가장 가까운 **통과 장(코드+렌더 PNG)** Read + P0 북극성 + 물성 결정표. 내용이 형태를
   정하게 한다(칸 맞추려 억지 카드/배지 금지). **수정 요청은 완성 pptx를 뜯지 말고** deck-spec/brand-kit/
   컴포넌트 경유로 재빌드.
1. **빌드** — 정본 컴포넌트만. 카드=`hero_card`, 도해 재드로 금지(import·좌표복사). **부품이 없어
   즉흥하게 되면 멈춰라** — 그게 "컴포넌트 부재" 발견이다(억지로 밋밋하게 그리지 말 것).
2. **게이트** — `preflight_dense.py` green 없이 사용자에게 안 보낸다.
3. **렌더+눈검증** — POWERPNT kill → `render_deck.ps1`(OutDir=프로젝트 안, gitignore) → **PNG를 실제로
   Read해 육안 확인**(빈칸·넘침·정렬·밋밋·아이콘 부정합). green ≠ 완성.
4. **제시 → 반려면** 기하/컴포넌트/게이트 층위로 근본 원인. 레이아웃 버그의 대응은 **기하 수정**이지
   시각화 폐기가 아니다(다이어그램 유지·수정).

## 발명 산출 — 사용자가 조종하는 하네스 변경 제안
드러난 것을 3분류 + **배치 판단**까지 붙여 올린다:

| 분류           | 신호                              | 후보 자리(사다리로 결정)                |
| -------------- | --------------------------------- | --------------------------------------- |
| 버그           | 게이트 통과했는데 눈으로 결함     | 부품 제거 or `audit.py` 규칙            |
| 배선           | 규칙/부품 있는데 안 물림(prose만) | `test_wiring` 불변식 + 정본 배선        |
| 부품/스킬 공백 | 즉흥할 수밖에 없었음              | `dense.py` 컴포넌트 or 새 스킬/레퍼런스 |

제안 형식:
```
발견:   무엇이 왜 문제인가 (렌더 PNG·실측 근거)
배치:   사다리 어디에 내리나 + 왜 거기라야 재발이 멈추고 일정해지나 (국소 패치가 아닌 이유)
제안:   내릴 변경 (코드 위치·단일 출처)
영향:   다음 덱이 무엇을 상속하나
경계:   기계로 강제 가능 vs 눈검증에 남는 부분 (정직하게)
```
- **사용자가 보고 원하는 방향으로 수정·승인** → 그때 코드로 내린다. prose로 방치하지 않는다.
- 새 게이트는 **통과작 전수 오탐 0** 후 배선(오탐 게이트는 백스톱 음소거 — 정밀 > 양).

## 철칙 (전역 상속)
- 한국어, 결론 먼저. 커밋은 **사용자 요청 시만**, AI 서명 금지, **main 직접 커밋 금지**.
- 한글 파일에 PowerShell Set-Content/Out-File·bulk 치환 금지(U+FFFD 하드 차단). Write/Edit만.
- 스크립트는 `uv run python`. 렌더 전 POWERPNT kill(파일 락 방지).
- **정직한 경계:** 하네스는 정의된 결함(구조 0 등)까지만 강제한다. "리치·의미 정합"은 눈검증 몫 —
  게이트로 덮은 척하는 순간 그게 다음 쓰레기의 원인이다.
