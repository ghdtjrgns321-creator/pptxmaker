# visual-selection — 메시지 유형 → 시각 형식 결정표

> **위치(2026-07-20):** 입력 축의 정본은 물성 하나이고 단일 결정표는
> `deck-compose/references/layout-matching.md`다. 이 문서는 그 표 **B(정량 물성)의 근거(왜 그
> 형식인가 — Zelazny 5비교·Abela 4목적)와 안티패턴 참조**다. `주장형태`는 별도 축이 아니라
> 물성의 산문 표현 — 형식 선택은 layout-matching에서 하고, 여기서 그 이유를 확인한다.

**제1원칙: 시각은 장식이 아니라 주장의 증거 형태다.** 이 덱의 목표는 "있어 보이는
디자인"이 아니라 **설명+분석+설득**이다. 슬라이드마다 먼저 "이 장의 주장은 무엇인가"를
한 문장으로 쓰고, 그 주장을 **무엇으로 증명하는지**에 따라 형식을 고른다.
형식을 먼저 고르고 내용을 끼워 맞추면 정합성이 깨진다(아래 안티패턴).

이론 근거: Zelazny(맥킨지) "Say It With Charts"의 **비교 유형 5종**(구성비·항목 순위·
시계열·분포·상관)과 Abela(Extreme Presentation)의 **목적 4분류**(비교·구성·분포·관계).
차트는 데이터 모양이 아니라 **메시지의 비교 유형**이 결정한다.

- 출처: datavizblog.com "Andrew Abela's Chart Chooser" · informit.com "Say It With Charts! 참조 가이드" · storytellingwithdata.com "chart chooser" · macrolake.com "Say It With Charts Workbook"

## A. 정량 메시지 → 차트 (Zelazny 5비교 매핑)

| 주장의 형태(한 문장 테스트)                  | 비교 유형   | 형식                      |
| -------------------------------------------- | ----------- | ------------------------- |
| "X가 전체의 N%를 차지한다"                   | 구성비      | `pie`/`doughnut` (≤5조각) |
| "원인/항목별 비중이 이렇게 갈린다" (이름 김) | 구성비+순위 | `hbar`                    |
| "A가 B보다 크다/많다" (동질 항목 간)         | 항목 비교   | `bar`                     |
| "시간에 따라 늘었다/줄었다"                  | 시계열      | `line`                    |
| "그룹마다 구성이 달라진다"                   | 구성 변화   | `stacked_bar`             |
| "임팩트 숫자 자체가 메시지" (2~4개)          | KPI         | `metrics`                 |

### A-2. 확장 정량 유형 (v4 — mpl 이미지 경로, 수치편집불가·재빌드로 수정)

| 주장의 형태(한 문장 테스트)                     | 비교 유형     | 형식                 |
| ----------------------------------------------- | ------------- | -------------------- |
| "합계가 이 증감들로 분해된다" (기여도 분해)     | 구성+증감     | `waterfall`          |
| "전/후 두 시점에서 항목별로 이만큼 변했다"      | 전후 비교     | `dumbbell` (표 금지) |
| "두 시점 사이 수준·순위가 이렇게 이동했다"      | 전후 비교     | `slope` (표 금지)    |
| "행×열 교차 어디가 뜨겁고 차가운가" (밀도 패턴) | 교차 매트릭스 | `heatmap`            |
| "단계마다 이만큼 빠져나간다" (전환·이탈)        | 흐름/전환율   | `funnel`             |
| "X와 Y가 상관인데, 저 점만 예외다"              | 상관+예외     | `annotated_scatter`  |
| "값들이 이렇게 퍼져 있다" (분포 자체가 주장)    | 분포          | `histogram`          |

네이티브 차트에는 `emphasis`(강조 항목명 목록)와 `annotations`(콜아웃)를 붙일 수 있다 —
**전부 회색 + 강조 데이터만 accent 1색 + 콜아웃 주석 + 하단 출처**가 BCG 룩의 최대 지렛대.

**차트 금지 조건:** 항목들이 **동질 단위가 아니면 막대로 비교하지 않는다**(예: 용어 수
423 vs 판단트리 41 — 서로 다른 종류의 재고 나열은 크기 비교 주장이 아님 → 표나 metrics).
합이 100%가 아닌 수치를 pie로 만들지 않는다.

## B. 정성 메시지 → 다이어그램·표

| 주장의 형태                                          | 형식                                                                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| "이 단계들에서 각각 이런 일이 일어난다"              | `diagram process_band` (단계+상세 칼럼 — 파이프라인 기본)                                                                |
| "순서대로 진행된다" (라벨만으로 충분할 때)           | `diagram flow`                                                                                                           |
| "그룹별 항목의 측정·판정 나열"                       | `diagram band_table` (그룹 병합 라벨+행 하이라이트)                                                                      |
| "두 축 위에서 우리 위치가 다르다" (정성)             | `diagram matrix_2x2`                                                                                                     |
| "성숙도 단계 중 여기까지 왔다" (정성)                | `diagram spectrum`                                                                                                       |
| "대안별 충족도가 축마다 갈린다" (정성 다축)          | `diagram harvey_table`                                                                                                   |
| "요건별 충족 여부의 대비" (정성)                     | `diagram check_matrix`                                                                                                   |
| "층층이 방어/구성된다" (통과 순서·계층 있음)         | `diagram layers`                                                                                                         |
| "하나가 조건에 따라 갈라진다"                        | `diagram branch`                                                                                                         |
| "시간 축 위의 이정표" (여정·로드맵)                  | `diagram timeline`                                                                                                       |
| "독립적 요소 N개가 병렬로 있다" (순서 없음)          | `diagram cards`                                                                                                          |
| "두 상태의 대비" (전/후, As-Is/To-Be)                | `two_column`                                                                                                             |
| "여러 축에서 우리가 우월하다"                        | `table style:matrix`                                                                                                     |
| "항목별 스펙·검증 결과의 나열"                       | `table`                                                                                                                  |
| "논리 전개 자체가 메시지" (증거 사슬)                | `bullets`(intro+중첩, ≤2장)                                                                                              |
| "문제→해결 전환의 나열" (기존 vs 본 시스템)          | `diagram from_to`                                                                                                        |
| "여러 지표의 전후 개선을 나란히"                     | `chart panels` (2~3패널)                                                                                                 |
| "행위자마다 단계별로 하는 일이 다르다" (단계×행위자) | `diagram process_grid` (셰브런 단계 헤더 + 행위자 행 + 열별 결론 배너 — jnu_p15)                                         |
| "분류 체계 전체의 수치·계획을 한 판에" (분류×축)     | `diagram category_spine_table` (좌측 아이콘 분야 스파인 + 행 그룹 명도 밴딩 — jnu_p28·p33, 색 인코딩은 무채 명도로 번역) |
| "왼쪽 집합이 오른쪽 집합에 대응된다" (A↔B 매핑)      | `diagram mapping` (좌우 카드 열 + 연결선 + 하단 근거 스트립 — jnu_p25)                                                   |
| "장의 결론 한 문장을 각인"                           | `banner` (하단 스트립)                                                                                                   |

**핵심 구분 — layers vs cards:** layers는 **통과 순서나 위계가 실재할 때만**(방어 레이어,
아키텍처 층). 병렬 목록(문제 4가지, 원칙 3가지)을 layers로 그리면 없는 위계를 지어내는
것 — `cards`를 쓴다. flow도 같다: 실제 선후관계가 없으면 화살표 금지.

## C. 안티패턴 (실제 발생 사례 — 재발 금지)

| 안티패턴                                        | 무엇이 틀렸나                             | 교정                       |
| ----------------------------------------------- | ----------------------------------------- | -------------------------- |
| 이종 재고 나열을 bar로 (노드 423·250·188·80·41) | 크기 비교 주장이 아닌데 크기를 비교함     | metrics/표(인벤토리)       |
| 병렬 문제 목록을 layers로 (4가지 균열)          | 위계·통과 순서가 없는데 적층으로 그림     | cards                      |
| 합≠100% 수치를 pie로                            | 구성비가 아닌데 구성비처럼 보임           | hbar + 출처에 분모 명시    |
| 모든 수치 슬라이드를 같은 차트로                | 메시지 유형 무시, 형식 관성               | 장마다 한 문장 테스트 수행 |
| 대비(전/후) 메시지를 불릿으로                   | 대비 구조가 시각에 없음                   | two_column/matrix          |
| 순서 없는 항목에 flow 화살표                    | 없는 인과를 시각이 주장함                 | cards                      |
| 파이프라인을 빈 박스+화살표만으로               | 단계 이름만 있고 내용이 없음(아마추어 룩) | process_band(상세 칼럼)    |

## C-2. 다양성 강제 조항 (v4 — consistency-qa 게이트가 기계 검증)

1. **동일 시각 유형 연속 2장 금지** — 유형 키는 chart:종류·diagram:레이아웃·table 등 단위.
2. **덱 전체 시각 유형 최소 5종** (본문 5장 이상일 때).
3. **박스 다이어그램(flow/layers/cards/branch/from_to) 본문의 30% 이하** — 박스+화살표는
   어휘 3종 중 1종일 뿐이다. 정량 주장은 차트로, 대비는 dumbbell/slope로 먼저 검토.

## D. 작성 절차 (deck-compose가 수행)

1. 슬라이드마다 **주장 한 문장**을 먼저 쓴다(거버닝 메시지가 그것).
2. 위 A/B 표에서 주장의 형태와 일치하는 형식을 고른다 — 일치하는 행이 없으면 bullets가
   아니라 **표**를 기본값으로.
3. 자기 점검: "이 시각을 처음 보는 사람이 **주장을 말로 하기 전에** 그림에서 읽어낼 수
   있는가?" 아니오면 형식이 틀린 것.
4. 같은 형식이 3장 연속되면 메시지 유형을 재점검(대개 2번을 건너뛴 관성이 원인).
