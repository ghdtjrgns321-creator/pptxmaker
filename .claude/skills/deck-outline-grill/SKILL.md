# deck-outline-grill — 목차·콘텐츠 인터뷰 게이트 (①)

재료만으로는 알 수 없는, **사용자 머릿속에만 있는 "이 장에서 가장 전하고 싶은 것"을
개방형 질문으로 뽑아내 그대로 채록**한다. 구조 승인이 아니라 콘텐츠 인터뷰가 본체다.
채록된 답변이 곧 각 장의 강조점·콘텐츠 지시가 되며, 산출물 `_workspace/01.5_outline.md`는
이후 단계의 계약이다 — ②(형태 후보)부터 ⑤(조판)까지 장을 임의로 추가·삭제하거나 메시지를
바꾸지 못한다. **채록한 "가장 전하고 싶은 것"이 그 장의 초점이 되고, ②는 재료보다 그 채록을
먼저 읽는다** — 재료 중 초점 밖은 버린다(2026-08-02 확정).

**왜(실측 근거):** 골든 덱(K-IFRS 1115)에서 이 게이트 없이 진행한 결과, S5 중복 삭제와
Part Ⅲ 재편(기술 1개=1장 재정의)이 전부 **빌드 후에** 발생했다. 구성은 빌드 전 텍스트
단계에서 확정하는 게 가장 싸다.

## 진행 순서

1. **목차 추천 1안 제시** — 재료 기반으로 스킬이 먼저 던진다(README를 쓰면 그 목차가 1안이다. 빈 종이에서 묻지
   않는다). 예: "문제 인식 → 기술 설명 → 기존 기술과 다른 점 → TEST 결과 제시". 사용자가
   수정/승인하면 구조 확정, 바로 콘텐츠 질문으로 내려간다.
2. **부(섹션) 단위 강조 질문** — "문제 인식에서 가장 강조되는 점이 뭐야?" 개방형으로 묻고
   답을 그대로 채록. 답변에 구성 정보가 나오면(예: "파이프라인 설명 후 용어사전·지식그래프·
   판단트리·구조화출력") **되받아 확인**한다: "그럼 파이프라인 1장 + 기술 4장으로 만들
   생각하면 돼."
3. **부(간지)·표지·클로징 문구도 재료에서 따온다.** 부 이름은 재료의 상위 헤딩(`##`)을
   묶어 만들고, 표지의 제목·부제·리드·팩트칩은 재료의 H1과 「프로젝트 소개」에서 가져온다.
   **여기서 확정하지 않으면 조판이 지어낸다** — 2026-08-03: 부 이름 「왜 전수인가」류가
   전부 조판 단계 창작이었다. 계약의 `## 정형 장 문구` 절에 적는다.
4. **장 제목은 재료 헤딩에서 먼저 뽑는다.** 장마다 대응하는 README·FINAL-REPORT 헤딩을
   찾아 **그대로 1안으로 제시**한다("S10은 README 「3-2. 룰 기반 검증」 → 제목 『룰 기반 검증
   29종』 어때?"). 사용자가 고치면 그게 확정 헤드라인이다.
   재료에 뎁스를 만들어 둔 이유가 이것이다 — **제목을 새로 지어낼 자리가 아니다.**
5. **장 단위 전달 포인트 질문** — 장마다 "여기서 가장 전해주고 싶은 게 뭐야?"를 묻는다.
   답변 원문이 그 장의 핵심 메시지가 된다(요약·의역으로 왜곡하지 않는다).
   **이 채록은 초점이지 제목이 아니다.** 슬라이드에 박히는 건 3번에서 확정한 헤드라인이다.
6. **답변에서 나온 새 재료 수집** — "비교 스크린샷 있어, 내가 줄게" 같은 추가 재료가 나오면
   받아서 `_workspace/`에 편입하고 계약의 재료 출처에 기록한다.
7. **한 번에 질문 하나.** 중복 감지(한 장의 메시지가 다른 장에 이미 있으면 삭제/병합을 먼저
   제안 — pull 원칙)와 종료 조건(사용자가 목차 전체에 "확정")은 grilling 원칙 그대로.

## 산출물: `_workspace/01.5_outline.md` (아웃라인 계약)

```markdown
# 아웃라인 계약 — <프로젝트명>
- 대상 독자: <누구에게 파는가>
- 목차(확정): 문제 인식 → 기술 설명 → 차별점 → TEST 결과
- 상태: 확정 (2026-07-10, 사용자 "확정" 발화)

## 장 목록
| # | 부 | 장 제목(재료 뎁스) | 헤드라인(확정) | 전하고 싶은 것 (육성 채록 원문) | 재료 출처 | 상태 |
| - | -- | ------------------ | -------------- | ------------------------------- | --------- | ---- |
| 4 | Ⅱ | 3.2 지식그래프 | 기준서의 구조를 그대로 옮겼다 | "본문·BC·B 위계를 따랐고 자의적으로 만든 게 아니다. QNA·IE는 제목 연결." | 팩트시트 §3.2 | 확정 |

- **장 제목**은 재료(README·FINAL-REPORT)의 헤딩을 그대로 가져온다 — 눈썹·목차에 쓴다.
- **헤드라인**은 슬라이드에 실제로 박히는 한 줄이다. 채록에서 뽑되 **인터뷰에서 사용자가 확정**한다.

## 정형 장 문구 (재료에서 따온다 — 조판이 지어내지 않는다)

### 표지 · 클로징
| 자리 | 문구 | 재료 근거 |
| ---- | ---- | --------- |
| 표지 제목 | 로컬 기반 전표 데이터 전수 분석 시스템 | README H1 |
| 표지 부제 | local-ai-assist | 저장소명 |
| 표지 킥커 | 감사 · 전표 데이터 분석 · 로컬 실행 | README 개요 |
| 표지 리드 | 로컬 환경에서 전표를 전수 분석하여 감사인이 검토할 항목을 1차 스크리닝하는 도구 | README 「1. 프로젝트 소개」 첫 문장 |
| 표지 팩트칩 | 라벨\|값\|부연 ×3~4 | README 수치 |

### 부(간지)
| 부 | 제목 | 리드 | 재료 헤딩 |
| -- | ---- | ---- | --------- |
| Ⅰ | 분석 범위와 문제 인식 | (한 줄) | README `## 1` · `## 2` |

## 인터뷰에서 받은 추가 재료
- 기존 LLM 비교 스크린샷 → _workspace/images/... (S/N장 차별점 근거)

## 삭제·병합 이력
- (예) S5 결격 사유 장 — S4가 흡수, 중복으로 삭제
```

## 규칙

- **전 장 상태 "확정" 전에는 ②(형태 후보) 진행 금지.** 부분 "보류"가 남으면 그 장만 재질문.
- **②에서 "후보 주제가 서로 다르다"는 반응이 나오면 갤러리를 고치지 말고 여기로 돌아온다** —
  그건 형태 문제가 아니라 그 장이 담을 내용이 안 정해졌다는 뜻이다.
- **채록 원문 보존** — 육성 답변은 원문 그대로 남긴다.
- **헤드라인은 여기서 확정한다. ⑤(조판)로 미루지 않는다.**
  전에는 "다듬는 건 조판에서"라고 했다가, 채록이 그대로 쓸 만한 장만 통과하고 나머지는
  조판할 때 지어냈다 — 2026-08-03 실측: 본문 12장 중 **8장의 제목이 계약과 달랐다**.
  사용자가 안 보는 자리에서 제목이 바뀌면 그건 계약이 아니다.
  - **1안은 언제나 재료 헤딩이다**(진행 순서 3). 채록에서 제목을 만들지 않는다 —
    채록은 육성이라 길거나 지시문이라 제목으로 안 선다(2026-08-03 사용자 판정:
    "계약 채록이 더 이상한데? 덱이 쓴 게 더 맞고").
  - 사용자가 그 자리에서 고치면 고친 것이 확정이다.
  - 확정된 헤드라인은 조판이 **그대로 쓴다**. 다르면 `check_deck.py --outline`이 잡는다.
- **재료 없는 장은 계약에 넣지 않는다** — 재료가 없으면 "추가 추출할까/재료 줄래?"를 먼저 묻는다.
- **내부 용어 검사** — 장 제목·메시지에 독자가 모를 내부 용어('1홉 탐색' 류)가 보이면
  인터뷰 중 "독자 언어로 바꿀까?"를 묻는다.
- 후속 "목차 다시/강조점 바꿔" 요청은 계약 파일을 수정하고 ②부터 재실행한다(pptmaker SKILL.md 파이프라인).

## 자체 점검

① 모든 장에 육성 채록이 채워졌나(빈 칸 0)? ② **모든 장에 `헤드라인(확정)`이 채워졌고, `정형 장 문구` 절이 채워졌나** —
빈 칸이 있으면 조판이 지어낸다(2026-08-03: 12장 중 8장이 그렇게 바뀌었다). ③ 두 장이 같은
메시지에 답하고 있지 않나? ④ 사용자가 "확정"을 명시했나? ⑤ 추가 재료가 전부 재료 출처에
기록됐나? 하나라도 아니오면 인터뷰로 돌아간다.
