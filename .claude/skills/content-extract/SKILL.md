# content-extract — 재료 추출 (직접 추출 메인 · 외부 재료 보조)

다음 단계(deck-compose)가 쓸 **재료**(01_extracted.md)를 만든다. 창작 금지 —
소스에 존재하는 텍스트·수치·고유명사만, 출처와 함께 뽑는다.

## 모드 A: 소스 직접 추출 (기본 — 2026-07-08 A/B 실측으로 채택)

로컬 프로젝트 소스(코드·docs·리포트)가 있으면 **NotebookLM을 거치지 않고 직접** 보고서형
재료를 작성한다. 근거: 같은 소스 A/B에서 직접 추출이 밀도 1.3배(6,246 vs 4,656단어)·출처
인용 16배(264 vs 16건, 외부 재료는 복사 시 인용 유실)·수고(한 마디 vs 프롬프트+복사) 우위,
NotebookLM 재료에서 고유명사 환각 2건 검출(_workspace/08_material-comparison.md).

절차(에이전트가 수행):
1. 소스 파일 전부 읽기 — 읽은 파일 M/N(분모 명시) 증거 남김
2. **보고서형 8요소**로 작성: 섹션 10~14개(문제→솔루션→차별점→성과→로드맵), 섹션당
   ①헤드라인+거버닝 ②배경 서술 3~5문장 ③주장 3~4개(각 근거 2~3문장) ④용어 정의
   ⑤수치 전부에 `[파일명.md]` 출처 ⑥방법론 입력→처리→출력 ⑦반론+대응 ⑧벤치마크
   (재료 없는 요소는 "소스에 근거 없음" 명기)
3. 자체 검증: 단어수 ≥3,000 · 섹션 ≥10 · 출처 인용 ≥40건 미달 시 보강
4. 오케스트레이터가 표본 수치 10개+고유명사를 소스 grep 재대조(창작 0 확인)

출력: `_workspace/01_extracted.md` (보고서 자체가 재료 — 별도 요약 불필요)

## 모드 B: 외부 재료 수입 (보조 — NotebookLM 보고서 등)

관점 변주가 필요하거나 소스가 로컬에 없을 때(웹 리서치 등) NotebookLM **보고서형 텍스트**
(docs/notebooklm-prompt.md 템플릿)를 input/에 받아 병합한다. pptx 수입은 최후 수단.

## 실행

```
uv run python .claude/skills/content-extract/scripts/extract_pptx.py \
    <작업디렉토리>/_workspace/extract  input/<프로젝트명>/*.pptx
```

산출물: `extract/extracted.md`(슬라이드별 텍스트·표·차트·이미지 목록),
`extract/charts.json`(네이티브 차트 수치), `extract/images/`(그림 폴백).

## NotebookLM pptx = 슬라이드당 래스터 1장 (2026-07-08 실측)

NotebookLM 슬라이드 생성은 **슬라이드 전체를 PNG 1장으로 굽는다**(텍스트 상자 0개,
네이티브 차트 0개 — 15/15 슬라이드 실측). 따라서 스크립트 추출은 이미지 덤프까지만 하고,
**본문 추출은 에이전트의 이미지 판독(Read로 images/*.png를 직접 읽기)이 기본 경로다.**
판독 시 헤드라인·거버닝 메시지·불릿·수치·표/차트 데이터를 슬라이드 번호와 함께 옮겨 적는다.
수치는 오독이 치명적이므로 애매하면 `(판독 불확실)`을 붙인다.

## 차트 3단계 폴백 (A안 박제)

1. **네이티브 차트** → 스크립트가 categories/series 수치를 charts.json으로 직접 추출
   (일반 pptx가 입력으로 올 때만 해당)
2. **래스터/도형 차트** → 이미지 판독으로 수치를 복원해 01_extracted.md에
   "복원(출처: 파일·슬라이드)"로 표기
3. **복원 불가** → 01_extracted.md에 **"재생성 불가, 이미지 폴백(경로)"**을 명시
   (조용히 버리지 않는다)

## 출력: `_workspace/01_extracted.md`

스크립트 산출물(extracted.md)을 그대로 넘기지 말고, 에이전트가 **정리**해서 쓴다:

- 초안별(3~5개) 핵심 메시지·수치·근거를 카테고리(문제/솔루션/기능/차별점/성과)로 분류
- 각 항목에 출처 표기: `(초안2 s5)` — deck-compose가 상충 시 원본을 추적할 수 있게
- 차트 재료는 charts.json 인덱스 또는 복원 수치를 명시, 이미지 폴백은 경로 명시
- 초안 간 **상충 수치는 삭제하지 않고 병기** — 선택은 deck-compose 몫
- **고유명사(모델명·제품명·버전)도 수치와 동급으로 검증** — 2026-07-08 실전에서 NotebookLM이
  지어낸 "Gemini 1.5 Flash"가 수치 검증만 통과해 덱까지 전파된 사고. 원 소스가 있으면 grep 대조,
  없으면 `(외부 재료 표기 그대로 — 미검증)` 마커를 붙인다

## 에러 핸들링

- pptx가 0개면 진행하지 않고 "input/ 비어 있음"을 오케스트레이터에 보고
- 파싱 예외 파일은 건너뛰고 목록에 명시(전체 중단 금지)
- NotebookLM 샘플 미확보 상태로 설계됨 — 실제 파일에서 새 형태(SmartArt 등)를 만나면
  extracted.md에 "미지원 형태" 표기하고 스킬/스크립트 보강을 제안
