# pptmaker — PPT 서식 공장

콘텐츠는 사용자가 프로젝트별 `FINAL-REPORT/`(보고서형 md 묶음)로 미리 정리해둔다. 이 스킬은
그 재료를 **장마다 다른 형식으로** 조판한다.

**실행 모드: 메인 대화가 직접 한다.** 서브 에이전트 파이프라인 아니다 — 덱 만들기는 사용자와
주고받는 일이고, 에이전트로 쪼개면 그 왕복이 끊긴다(2026-07-29 확정, 근거는 아래 §왜 이렇게).

## 파이프라인

```
① 재료 읽기    FINAL-REPORT/*.md + _workspace/01.5_outline.md(아웃라인 계약)
               계약이 없으면 deck-outline-grill로 먼저 확정 — 없이 진행 금지
② 질문 후보    장마다 "이 장을 무엇으로 말할까" 후보 4~6개를 재료에서 뽑는다
               형태가 아니라 **질문**이다 — "무엇을 답하는 장인가"
③ 갤러리       후보를 **실제 pptx로 그려** 한 벌 만든다. 한 장에 한 주제, 후보를 나란히.
               장 이름·재료 요약·후보별 "답하는 질문"을 같이 적는다(설명 없으면 못 고른다)
④ 선택         사용자가 번호로 회신 — "s04=1 · s07=2 · s09=전탈락"
               전탈락이면 그 장은 ②로 되돌아간다
⑤ 본편         고른 질문을 장으로 만든다. 파이썬 직접 조판(goldenfab kit·grid·dense·layouts)
⑥ 눈검증       render_deck.ps1 → PNG 전장 확인 → 겹침·잘림·넘침 수정. **이게 진짜 게이트다**
⑦ 기계 채점    score_deck.py — 튀는 곳만 본다(판정자 아님)
```

③에서 **왕복이 줄어든다.** 장마다 1안씩 내밀면 반려에 방향이 없다("별로다"로 끝난다).
한 벌을 깔면 사용자가 번호로 답한다.

## 확정 규칙 5개 (2026-07-29 실험 2회로 확정 — 어기면 같은 반려가 재발한다)

| #   | 규칙                                                            | 어겼을 때 실제로 벌어진 일                                                                     |
| --- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1   | 그림 그리기 **전**에 질문 후보를 내고 사용자가 고른다           | 구조를 혼자 확정해 오독(s05를 병렬로 읽었는데 실제는 순환)                                     |
| 2   | 고른 질문을 **전부** 시각으로 덮는다 (개수 하한 아님, 커버리지) | "시각화 자료가 너무 없음, 모든지 텍스트로 해결하려함"                                          |
| 3   | 글자 수 하한은 유지한다                                         | — 사용자 확정. 단 하한이 **떡칠을 유도**하니 ②의 커버리지로 갚는다                             |
| 4   | 부품함·골든덱은 **재료로만** 본다. 그대로 호출 금지             | 부품을 그대로 부르니 36장이 전부 같은 카드가 됨                                                |
| 5   | **인코딩** 발명은 환영, **잉크** 발명은 금지                    | 기존 잉크(사각·원·선·화살표)로 값을 인코딩하는 건 좋다. 도트·링·그라데이션 같은 새 장식은 금지 |

규칙 4의 뜻: `golden/render/`(골든 17장)와 `golden/render-부품/`(부품 27장)은 **보고 배우는
그림**이지 부르는 함수가 아니다. 생산 코드는 `_archive/`에 있다 — 되살리지 않는다.

## 무엇으로 그리나

- `goldenfab.kit` — 도형·텍스트·이미지 헬퍼, `load_kit()`(brand-kit), `new_presentation()`
- `goldenfab.grid` — 좌표계(MARGIN_L·RIGHT_EDGE), 개수에서 자리 파생(pitch·track)
- `goldenfab.dense` — 헤더·룰·카드 등 밀도 부품
- `goldenfab.layouts` — 표지·목차·간지(정형 장은 이걸 그대로 쓴다)
- `pptx-visuals` — 차트 6종(네이티브)·mpl 익스히빗 9종·도형 DSL 9종.
  필드는 `pptx-visuals/references/spec-fields.md`, 형식 선택은 `visual-selection.md`
- `pptx-build/references/design-rules.md` — 물성→형식, 색 규율, 타이포 위계

## 재료를 기계가 센다

```bash
uv run python .claude/skills/pptx-build/scripts/scan_material.py FINAL-REPORT/ --json
```

표가 몇 행인지, 목록이 몇 개인지, 화살표가 어디서 어디로 가는지를 md 원문에서 센다. ②에서
질문 후보를 뽑을 때 **그림을 먼저 떠올리고 숫자를 맞추는 것**을 막는다.

## 렌더·채점

```bash
pwsh .claude/skills/pptx-build/scripts/render_deck.ps1 -Pptx <경로> -OutDir <폴더>
uv run python .claude/skills/pptx-build/scripts/score_deck.py <경로> [--body 4,5,7]
```

⑥이 진짜 게이트다. ⑦은 참고값 — 게이트는 사용자가 반려한 조립 7장을 전부 통과시킨 전례가 있다.

## 산출물

- 작업 스크립트·중간 산출은 `_workspace/`
- 최종 pptx는 `results/<프로젝트명>-소개.pptx`. **한글 파일명 복사는 PowerShell**(bash는 인코딩 깨짐)

## 왜 이렇게 바꿨나 (2026-07-29)

이전 하네스는 `deck-outline-grill → deck-composer → pptx-builder → consistency-qa` 4에이전트가
`deck-spec.json`을 주고받는 파이프라인이었다. 13,710줄 중 실제로 값을 한 건 약 700줄이었고,
나머지는 실전 덱에서 **0회 호출**이었다. 더 큰 문제는 구조 자체였다:

- `registry`가 장을 통째로 배정 → 15타입이 돌아가며 나와 **전 장이 같은 형식**
- `figures/*.LAYOUT` 기본값이 골든 실측 좌표 → 그대로 부르면 **골든이 딸려옴**
- `dense.hero_card`가 유일한 카드 → 36장이 **동일한 4카드**
- Stop 훅이 "덱 에이전트 경유"를 강제 → 메인 대화가 직접 만드는 경로를 **차단**

전부 `_archive/`로 옮겼다. 이력·근거는 `docs/CHANGELOG.md`.
