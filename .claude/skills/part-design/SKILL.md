# part-design — 부품 시각을 정하는 절차

## 왜 있나 (2026-07-26 실측)

부품 1종(G22 방사)에 **약 6시간 · 10라운드**를 쓰고 산출물이 전부 폐기됐다. 원인 둘:

1. **내가 잉크를 지어냈다.** 검정 채움 원 · 두꺼운 컬러 링 · 진한 파이 · 회색 칩 · 선 끝 도트 ·
   밑줄 룰 · 비중 막대 · 폴라 막대 · 버블 · 게이지 — 전부 내가 발명한 것이고 전부 반려됐다.
2. **내 눈이 검수 기준이 됐다.** 매번 "됐다"고 판단해 보냈고 매번 틀렸다. 그런데 한 번에 한 안씩만
   내놓으니 반려는 **부호만** 오고 방향이 안 온다. 방향 없는 반려 × 10회 = 제자리.

그래서 이 절차는 두 가지를 금지한다 — **지어내기**와 **1안씩 내놓기**.

## 절차

```
① 웹에서 실물 확보  →  ② 6~9개를 한 장에 나란히  →  ③ 사용자가 번호로 고름  →  ④ 고른 것만 다듬기
   (다운로드해 직접 봄)     (렌더 1번 = 선택지 N개)      (내 판정 없음)         (요소 추가 금지)
```

### ① 웹에서 실물 확보 — 이름만 보고 추론 금지

- **반드시 이미지를 내려받아 `Read`로 직접 열어본다.** 검색 결과 제목·설명만 읽고 그리면
  실물과 다섯 곳이 어긋난다(2026-07-26 실측: 원 계열·굵은 링·꺾은선·라벨 위치·번호 대응).
- **템플릿 판매 사이트는 버린다** — PresentationGO·SlideModel·SlideTeam 등. 확인 결과 전부
  그라데이션·6색·드롭섀도·클립아트 아이콘이었다(사용자 표현: 아마추어틱).
- **쓸 만한 원천**: 실제 컨설팅 리포트 PDF. BCG `web-assets.bcg.com`은 봇 차단(403),
  McKinsey 직링크는 타임아웃. **S3·CDN에 올라간 사본이 잘 열린다**(예: `argaamplus.s3.amazonaws.com`).
- PDF는 페이지를 그림으로 렌더해서 본다(프로젝트 의존성 건드리지 않는 임시 실행):

```bash
curl -sSL --max-time 180 -A "Mozilla/5.0" -o r.pdf "<URL>"
uv run --with pymupdf --no-project python -c "
import fitz; d=fitz.open('r.pdf')
[d[i].get_pixmap(dpi=110).save(f'p{i+1:02d}.png') for i in range(d.page_count)]"
```

- 받은 것은 스크래치패드에 둔다. `results/`·`ref/`에 넣지 않는다.
- 못 찾으면 **못 찾았다고 말하고 멈춘다.** 없는 걸 지어서 채우지 않는다.

### ② 6~9개를 한 장에 나란히

- 찾은 실물 중 **서로 충분히 다른** 6~9개를 골라, 각각을 **그대로 옮긴** 변형을 만든다.
  내 조합·내 변주가 아니라 **1 실물 = 1 변형**이다.
- 한 슬라이드에 3×3(또는 2×3)로 작게 깐다. 칸마다 **번호 + 출처 파일명**을 적는다.
- 렌더 1번으로 선택지 전부가 보이는 게 요점이다 — 라운드 수를 10에서 2로 줄이는 유일한 수단.

### ③ 사용자가 고른다

- 내가 "이게 낫다"를 붙이지 않는다. 번호와 출처만 적어 보낸다.
- 전부 아니면 ①로 돌아가 **다른 원천**에서 다시 찾는다(같은 원천에서 더 짜내지 않는다).

### ④ 고른 것만 다듬기

- 고른 변형을 전체 크기로 키우고 **겹침·자리 밖·글자 넘침만** 잡는다.
- **요소를 더하지 않는다.** 허전해 보여도 내 판단으로 도트·룰·막대·아이콘을 얹지 않는다 —
  그 방향은 실측 10회 전부 반려됐다. 더할 게 있으면 사용자가 말한다.
- 다듬은 뒤에도 통과 판정은 사용자가 한다.

## 부품 계약과의 관계

이 절차는 **시각을 정하는 것**만 다룬다. 정해진 뒤의 구현 규율(자리 독립 · 개수 파생 ·
글 무소유 · 고유 크기)은 `goldenfab/figures/__init__.py`가 단일 출처다.

부품은 `box` 안 **그래픽 하나**만 그린다. 설명 패널·결론 배너·열 구성은 페이지(3층 배치)
몫이지 부품이 소유할 게 아니다 — 부품이 페이지를 소유하면 형식이 좋아 보여서 정작 약한
그래픽이 가려진다(2026-07-26 반려: "형식은 좋은데 그래픽이 별로").

## 발동 범위

- **발동**: 부품 신규 제작 · 기존 부품 시각 재설계 · 도구함 어휘 추가
- **비발동**: PPT 생성·수정, 골든 재작업, 덱 QA — 그건 `pptmaker`·`deck-smith`가 맡는다.
  이 스킬은 하네스(게이트·훅·계약)를 건드리지 않는다.
