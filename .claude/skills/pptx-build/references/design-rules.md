# 골든 디자인 규칙 (단일 출처)

> **목적:** 골든 슬라이드를 사용자 승인으로 확정할 때마다 그 판단을 여기에 박제해서,
> 다음 자동화(새 덱 생성)가 사용자 손을 덜 타게 만든다. 이 파일은 그 축적의 단일 출처다.
> 사용자 승인 반복으로 확정된 것이므로 임의 변경 금지 — 변경은 골든 덱 재승인 경유.

**골든셋 사용 원칙(사용자 확정 2026-07-11):** 골든 덱은 아키타입 **부품 창고**이지 납품물이
아니다. 실전 덱 제작 시 장 단위로 인출해 쓰며, 골든 덱 내부의 상호 참조 정합(목차 페이지
번호 ↔ 실제 장 수, 부-내용 채움 여부)은 요구하지 않는다.

구현 참조: `golden/kit.py`(도형·텍스트 헬퍼), `golden/grid.py`(좌표계),
`golden/build_golden.py`(확정 구현 — 간지·표지·목차의 기준), `golden/s11_branch_snap.py`(분기 스냅).

구성: **Ⅰ부 전역 규칙**(모든 장) → **Ⅱ부 장 유형별 문법**(아키타입별) → **Ⅲ부 제작 프로세스**.

## Ⅰ부 — 전역 규칙 (모든 장)

### 1. 레이아웃 GRID (임의 좌표 금지)

- 슬라이드 13.333×7.5". MARGIN_L=0.6, RIGHT_EDGE=**12.733**(13.333−0.6 — 12.x 착각 금지).
- 2컬럼 장: 좌 컬럼 x=0.6 w=3.1(끝 3.7), 우 컬럼 x=4.2 w=8.533(끝 12.733), 세로 룰 x=3.95.
- 세로 존: 헤더 룰 1.45 / CONTENT_TOP 1.75(위 여백 이보다 크면 안 됨) / 콘텐츠 하한 6.35 /
  결론 바 6.60 h0.45 풀폭 / 출처 7.15.
- 모든 좌표는 GRID 상수에서 파생 — 스크립트에 임의 좌표 리터럴 금지.
- 간격 조정은 요소 간 간격을 줄이는 게 아니라 **블록을 통째로 이동**해서 해결
  (텍스트-룰 간격 0.35 보존).

### 2. 색 규율 (흑/백/회 + accent 1색 절약)

- 파스텔 틴트 다단 금지. 베이스는 primary(근흑)·bg(백)·bg_alt(연회)·muted(회)만.
- **accent 사용처는 장당 3곳 내외로 카운트**(예: 대형 용어 1, 강조 도형 1, 강조 스파인 1) —
  스크립트로 accent 색 도형·런 수를 세서 검증(오딧 상한 4).
- 대비 도형 쌍은 동일 지오메트리(같은 라운드·스파인·패딩), 차등은 **채움 명도만** —
  처리 방식이 다르면 "실수"로 읽힌다.
- 색 파생은 kit.mix(브랜드 색 혼합)로만 — 신규 hex 금지.

### 3. 타이포 위계 (중간 크기 몰림 금지)

- 점프: display(40)/title(32) → head(15) → body(12) → caption(9)/foot(8). 구획 제목은 head 15pt.
- 장당 대형 런(>15pt, 헤드라인 제외) ≥ 2개 — 좌측 앵커 대형 용어가 그 자리.
- 헤드라인은 1줄(2줄 겹침 금지), 좌측 앵커 구조: 캡션 라벨 → 대형 용어 → 리드 1문장 →
  번호 리드인(01·02).
- 본문 폰트 하한 caption(9pt) — 그 미만 금지(사용자 가독 지적 이력).

### 4. 텍스트 리듬 (단어 쓸 곳 / 문장 쓸 곳 / 한글 줄바꿈)

- 도형 안(셰브런·칩) = 단어·구만. 패널·앵커 칼럼 = 완전한 문장 2줄 이상(BCG 밀도).
- 수동 \n 금지 — 폭으로 줄바꿈 제어. 어절 중간 깨짐·마침표/한 글자 orphan 금지.
- **어절 단위 줄바꿈은 코드로 강제**: 모든 문단에 `eaLnBrk="0"` + 모든 런에 한국어 언어 태그
  (`language_id=KOREAN`) — 둘 다 있어야 PowerPoint가 어절 경계에서만 줄바꿈한다
  (kit.add_text/set_shape_text가 강제, 2026-07-10 S6에서 확정). 문구 축약으로 피하지 말 것.
- 텍스트박스 내부 좌우 마진 0 (kit.add_text가 강제).

### 5. 도형·커넥터 어휘 (기본 사각형 나열 금지)

- 프로세스 밴드: 첫 단계 PENTAGON + 후속 CHEVRON, adjustment 0.55, 노치만큼 겹쳐 맞물림,
  결말(치명/안전 등)은 밴드의 마지막 도형으로 통합. 셰브런 밴드는 분기 없는 단순 진행에만.
- 셰브런 텍스트: vertical_anchor=MIDDLE, margin_top/bottom=0, 좌 0.08 / 우 노치의 1/4(화살촉 보정).
- 대비 분기: 공통 입력(라운드 카드, 뿌리) → 엘보 커넥터(muted 1.75pt) → 두 경로 — 나열형 2레인 금지.
- 패널 액센트 바: left=박스 left, w=0.05, top/height=박스와 완전 일치(컨테인먼트),
  텍스트는 박스+0.2에서 시작.
- 실행 그래프(분기 있는 플로우, S6 확정): 원문 다이어그램 구조를 그대로 도형화 — 라운드 노드
  레인(입력·출력은 라운드, 출력은 primary 채움) + 판정은 **diamond**(accent 테두리) +
  커넥터는 전부 **화살표**(tailEnd 삼각형 XML) + 분기 라벨(IN/OUT accent bold) +
  노드 아래 핵심 기술 태그 1줄(볼드).
- 다이어그램 상세는 도형 안이 아니라 **하단 두괄식 칼럼**(기술명 볼드 리드-인 → 작동 방식,
  세로 헤어라인 구분)으로 — 도형 캡션에 3줄 밀어넣기 금지.
- **1:3 flat tree 분기**(S11 스냅 확정): 루트 박스 세로중심 = 3갈래 전체 세로중심(가운데 갈래
  중심), 갈래 칩 left 3개 완전 동일, 가로 커넥터 y = 각 칩 세로중심, 행 피치 0.42.
  구현·오딧 표는 golden/s11_branch_snap.py(build_branch/audit) 재사용 — 편차 0.005 초과 시 FAIL.
- **점선/실선 형태 언어**(S14~): 점선 화살표·점선 테두리 = 확률·불확실, 실선 경로·실선 테두리
  +✓ = 결정. 차단은 경로를 끊는 짧은 바 + ✕. 덱 전체에서 이 의미를 일관 유지한다.

### 6. 구성 문법 (1장 = 다구획 고밀도 + 공기)

- 한 장 = 좌측 앵커 칼럼 + 주 시각 구획 + 보조 구획(+결론 바) — 한 정보만 넣으면 비어 보인다.
- 구획은 여백이 아니라 장치로 나눈다: 구획 소제목(head 15 bold)+수평 룰, 세로 헤어라인, 배경 밴드.
- 구획 사이 독해 동선 장치(커넥터·화살표) — 구획은 연결되지 나열되지 않는다.
- 용어 축 매트릭스(2×2 등 해독 필요 형식)보다 시나리오/스토리 구도 우선.
- "아이콘 1개+설명 1줄" 단독 나열 구획 금지(시각 다양성 상실). 아이콘은 패널 헤드 보조로.
- 숫자 스탯 단독 나열 금지 — 비례 바·대비·분기 등 관계 인코딩과 결합.
- **장 내 시각 어휘 중복 금지**(S11): 같은 도해 문법(세로 fan, 좌우 트리 등)을 한 장에 두 번
  쓰지 않는다 — 두 번째 분기는 다른 형태(1:3 flat tree, 브레이스, 표)로. "장마다 새 아키타입"의
  장 내부 버전.
- **예시와 실물 도해는 한 흐름으로 통합**(S11): "적용 예시" 스트립과 "실물 구조" 도해를 나란히
  두 개 만들지 말고, 실제 입력(질문)에서 시작해 실물 구조의 분기까지 한 줄 서사로 — 맨 위
  노드는 추상 제목이 아니라 실제 질문.
- **나열은 도형에 가두기**(S11): 갈래·항목 텍스트를 맨바닥에 나열하지 말고 라운드 칩/박스에
  가둔다(볼드 헤드 + muted 설명을 같은 칩 안에). 커넥터는 칩 좌변 세로중심에 닿는다.
- **공기 수치**(S11): 섹션 라벨 bottom ↔ 첫 도형 top ≥ 0.12(assert로 박을 것). 도형 그룹은
  칼럼 폭 기준 좌우 균형 — 왼쪽 절반에 몰려 오른쪽이 비면 텍스트 확대 또는 그룹 우이동.
  칩·박스는 풀폭 금지, 내용 폭 + 인셋으로.

### 7. 콘텐츠 원칙

- 수치·문단번호·엔트리는 팩트시트/실데이터 파일에서만 — **창작 금지, 축약만**. 발췌 데이터는
  원본 파일과 스크립트 전수 대조 후 사용.
- **프로젝트 진화 서사 금지**(2026-07-11): 기술 설명 장에 Before/After·"구 시스템"·"재설계 전"
  류의 개발 경과를 쓰지 않는다 — 독자는 이전 버전을 모른다. 전/후 비교는 Part Ⅳ
  "문제와 해결" 장 전용으로 격리.
- 내부 식별자(via_topic·hops=1·E3 등 코드/데이터 명칭)는 독자 언어로 번역해 싣는다 —
  용어 번역 패스가 오딧 예정(05-plan 이월).

## Ⅱ부 — 장 유형별 문법 (아키타입 카탈로그)

### A. 표지 (S1)

- 표지 전용 좌측 축 **0.65**(본문 0.6과 다름). 좌측정렬 요소 전부(킥커·구분선·사각형·제목·
  부제·연도·워드마크) left=0.65 편차 0.
- 상단: 킥커 0.55 / 구분선 0.92(0.65→12.683, 여백폭 — 풀폭 아님).
- 타이틀 블록은 **하나의 응집 유닛**(2.75~4.6): 액센트 사각형 0.3×0.3 top=2.75 → 제목 3.15
  (사각형 bottom+0.1) → 부제 4.25(제목 bottom+0.35). 제목 bottom~부제 top 간격 >0.5면 위반.
  블록 세로중심 3.4~3.8(광학 중앙보다 살짝 아래). 텍스트박스 높이는 실제 글줄만큼만.
- 연도는 블록에서 분리된 하단 앵커 top=6.35, bottom < 밴드 top−0.3.
- 하단 다크 밴드 top=6.95 풀폭(left=0). 워드마크는 **좌측정렬**(left=0.65) + 밴드 수직중앙 —
  중앙정렬 금지.

### B. 목차 (S2, vC5)

- 구도: 좌측 타이포 리스트 + 우측 다크 패널(x=9.6~끝). **밴드·카드·장식 모티프 금지**
  (교차 틴트 밴드, 카드 그리드, 그래프 성좌·거미줄 모티프 전부 사용자 기각 이력).
- 리스트: 번호 축 0.6(accent bold) / 제목·서브 축 1.35 / 행 top 2.0 + 피치 0.82 /
  항목 사이 헤어라인(bg_alt 0.01) / 우측 끝(9.1)에 `p.번호` 정렬. 번호 장치는 한 행에 하나.
- 서브카피: 제목 아래 1줄, 구분자 ' · ' 통일, 팩트시트 수치만.
- 다크 패널: **로고 슬롯**(저대비 테두리 박스+"회사 로고" 캡션, 실제 로고로 교체) +
  하단 덱 타이틀 2줄. 그 외 채우지 않는다 — 수치 스택·장식 모티프 기각됨.
- 시작 페이지 번호는 구성표(05-golden-deck-plan.md)에서 파생 — 창작 금지.

### C. 간지 (S3·5·7·13·16·19)

- 좌측 축 **0.65 한 축**: PART 태그(top 2.0, 1.3×0.42) · 제목(top 2.55, display) ·
  서브 액센트 바 · 진행 도트 첫 개.
- 서브 리드: 명사 마감("~4가지 균열"), 숫자 표기 통일('네 가지'✕). 바(w 0.05) 오른쪽 여백 0.2
  → 텍스트 left 0.9, top 4.4. **바 top/height = 서브텍스트 블록과 완전 일치**(감싸기) —
  2줄이 되면 어절 경계에서만 끊고 바 높이도 함께 늘린다.
- 고스트 워터마크 "0n": right ≤ **12.0**(우측 잘림 방지), 제목과 광학적 세로 정렬,
  색은 mix(primary, muted, 0.22) 저대비 유지.
- 진행 도트 6개(목차 6부 인디케이터): 지름 0.13, 중심간 0.35 균등, 첫 도트 left=0.65,
  현재 PART만 accent.

### D. 본문 공통 (고정 요소)

- 헤더: 킥커(캡션 muted) + 헤드라인(section 28 bold, 1줄) + 헤어라인(1.45).
- 하단: 결론 바(primary 풀폭, 흰 볼드 1문장) + 출처선(foot muted, 7.15).
- 간지·표지·목차는 golden/build_golden.py의 확정 구현이 기준.

### E. 기술 설명 장 (S8·9·11·12)

- 구조: 상단 **서사 3칼럼**(01 왜 필요한가 / 02 파이프라인에서의 역할 / 03 어떻게 만들었나 —
  볼드 헤드 + 완전 문장, 세로 헤어라인 구분) + 하단 **실물 증거 구획**. 폭이 필요하면 서사를
  좌측 세로 스택으로 전환 가능(S12).
- 실물 증거 어휘: **네이티브 표**(실제 데이터 파일에서 발췌한 행) + **모노스페이스 코드/JSON
  카드**(다크 라운드 rect, adjustments 0.04~0.06으로 라운드 과대 방지, Consolas, 실제 엔트리
  구조 그대로). 서사의 주장을 캡션이 아니라 데이터 실물로 증명한다.
- 기존 어휘(셰브런 밴드·좌앵커 대형 숫자·칩 나열) 재탕 금지 — 골든 덱의 장마다 새 아키타입을
  1개 이상 기여한다.
- 메커니즘 설명에는 **실물 적용 예시**를 붙인다: 질문 → 중간 산물 → 결과 체인을 칩+화살표로,
  모든 고리는 실제 데이터 파일 엔트리와 1:1 대조.

### F. 스크린샷 전용 장 (S10·S12 캡처부)

- 배경은 본문과 동일한 **흰 배경**(다크 특수 처리 금지 — 무드 통일, 기각 이력 있음).
- 실물 캡처가 주인공: 대형 배치(h ≈ 4.0~4.75), **muted 헤어라인 테두리**(line width 0.01)로
  화면과 슬라이드 경계 구분. 보조 전시(스키마·도해)와 병치 시에도 캡처가 최대 폭.
- 캡션은 **accent 바(0.5×0.035) + muted 캡션** 한 줄. 캡처가 실제 산출물과 다른 시점이면
  **스냅샷 시점을 캡션에 명시**(예: "초기 V1 스냅샷, 수치 표기는 v14 기준") — 불일치 은폐 금지.
- **관찰 포인트 칼럼**("이 화면에서 보이는 것" — accent 번호 + 볼드 헤드 + muted 설명):
  항목은 전부 캡처 안에 실제로 보이는 요소와 1:1 대응 — 화면에 없는 주장 금지.
- **발췌 크롭**(S12): 세로로 긴 캡처를 통짜 축소하면 글자가 죽는다 — 핵심 구간만 크롭해 폭을
  키운다(글자 판독 가능이 기준). 크롭 경계는 문장·행 중간 잘림 0이 될 때까지 조정, 캡션에
  "발췌"와 원본 맥락 명시.
- 오딧: 슬라이드당 picture == 1 — 캡처 2장 이상이면 장을 쪼갠다.

### G. 전환·비교 장 (Part Ⅳ — S14·15)

- **A/B 시뮬레이션 대비**(S14): 구 방식 vs 신 방식은 텍스트 나열이 아니라 **같은 입력 하나를
  두 판에 넣은 동작 시뮬레이션**으로. 구 방식 판(bg_alt) = 점선 산탄 + 컷라인 + ✕ 탈락,
  신 방식 판(백+accent 룰) = 실선 일직선 경로 + ✓ 도달. 경로의 매 단계·수치는 실데이터 체인으로
  검증된 것만 — 기전과 실측이 다른 균열이면 수치를 섞지 않는다. 전/후 서사는 이 파트만 합법.
- **검증 장**(S15): ①어떻게 만든 시험인가(재료 문서가 분해되는 그림 — 질문부→입력 /
  회신부→채점 정답지 / 문서→검색 차단 ✕) ②최종 기록(대형 숫자 + kv 행) ③실패 각 설명
  (건수 뱃지 + 원인 1줄 + 합계 전수 표기).

### H. 미러 매트릭스 — 경쟁 비교 장 (S17 vC)

- 비교의 물성 = **좌우 대결**: 중앙 다크 축 기둥(축 칩 7) 좌우로 날개가 마주 본다.
  좌 날개(경쟁) = 점선 테두리 + bg_alt + muted + 우측 정렬, 우 날개(자사) = 실선 테두리 +
  ✓ + 볼드 키워드 + 좌측 정렬. 셀은 문장이 아니라 키워드 1~2줄.
- 좌우 카드는 같은 행 y 완전 동일(같은 루프 변수로 생성). 풀폭 사용 — 사이드바·부가 문구는
  넣지 않는다(한계는 전용 장으로 분리, 사용자 확정).
- 오딧: 날개 카드 수 = 축 수 × 2, 축 칩 수 일치 assert.

### I. 한계(경계) 장 (S18 vB)

- 한계의 물성 = **경계**: 회색 캔버스("경계 밖") 중앙에 두꺼운 실선 라운드 영역("경계 안").
  안쪽은 스탯 재탕이 아니라 **경계 정책 문구**(답하는 범위·거절·유보)만 — 타 장 수치 재탕 금지.
- 경계 밖 입력 칩들이 점선 화살표로 접근하다 **차단 바 + ✕**에 막힌다(각 칩에 실측 건수 캡션).
- 경계 도해로 못 담는 잔여 한계는 하단 **번호 섹션 카드**로(실측 수치 포함) — 화면을 꽉 채운다.

### J. 클로징 (S21 vC)

- 클로징 = **침묵의 마침표**: 요소는 4종만 — 킥커+헤어라인 / 액센트 사각+가치 제안(표지 문장
  재사용) / 완주 도트(간지 도트 전부 점등) / 하단 백색 밴드(표지 다크 밴드의 반전,
  워드마크+로고 슬롯). 요약 리스트·부가 문장·신규 수치 금지.
- 텍스트 프레임 ≤ 6을 assert로 강제 — 이 장이 다시 빽빽해지면 빌드가 실패해야 한다.
- 타이틀 블록은 표지 GRID(축 0.65) + 광학 중앙(블록 중심 3.4~3.8) — 표지와 같은 자리에서
  같은 문장으로 닫는 수미상관.

## Ⅲ부 — 제작 프로세스 규율

### P1. 물성 우선 첫 시안 (S15 3회 반려에서 확정)

- 시안을 그리기 전에 반드시 "이 내용의 실제 물성이 무엇인가"를 먼저 답한다 — 재료·산출물 같은
  명사는 그 실물의 형태(문서면 문서 카드, 화면이면 캡처)로, 차단·분해·주입·도달 같은 동사는
  그 동작이 보이는 형태(잘린 화살표, 갈라지는 팬, 닿는 경로)로 그린다. 회색 텍스트 카드 나열은
  물성이 정말 "목록"일 때의 최후 수단. 첫 시안부터 통과할 것 — 반려 후 고치는 것은 실패다.
- **절차 강제**: 시안 작업 계약(contract)의 1번 항목은 반드시 "물성 선언 — <내용> = <형태>"
  한 줄이어야 하며, 완성 시안이 선언한 형태와 다르면 그 항목은 FAIL이다. 산문 규칙은 잊히지만
  계약 게이트는 건너뛸 수 없다 — 코드를 열기 전에 선언부터 쓴다.

### P2. 오딧 — 렌더 전 기계 게이트 (1건이라도 걸리면 수정 후 재검)

1. 좌 컬럼 요소 left ≠ 0.6 → FAIL (들여쓰기 1.1은 허용)
2. 우 컬럼 요소 left ≠ 4.2 → FAIL (박스 내 텍스트 시작선 4.4는 허용)
3. 콘텐츠 bottom > 6.35 → FAIL (풀블리드 배경 제외)
4. 풀폭 요소 행별 right ≠ 12.733 → FAIL
5. 수평 룰 × 채움 도형 겹침 → FAIL
- 공통 추가: accent 채움+런 카운트 ≤ 4 / 장 유형별 구조 assert(도트·워플·표 행수·날개 수·
  텍스트 프레임 수 등 그 장의 물성 수량) / 공기 간격 ≥ 0.12.
- 정렬 린터: 레인 라벨 좌변=밴드 좌변, 두 밴드 좌·우변 일치, 질문(뿌리) 중심=행들의 수직 중앙,
  룰 폭=컬럼 폭, 패널 하단+0.08≤바 상단.

### P3. 렌더 루프

- `uv run python golden/<script>.py`(오딧 assert) → PowerShell COM 렌더(PNG 1280×720) →
  Read 육안(겹침·잘림·어절 깨짐) → 자가수정 → 사용자 제시. 버전 이름 PNG를 golden/variants/에 누적.
- 렌더 육안이 애매하면(색·밴드) PNG 픽셀을 직접 검사한다 — 육안 오판 이력 있음.
- 확정 즉시: build_golden.py 채택 + 본 파일 박제 + 다음 장. 스냅 스펙이 오면 단독 덤프
  스크립트로 정렬 오딧 표(편차 0.000)를 먼저 통과시키고 본판에 dy 오프셋으로 이식한다.

### P4. 제시 전 셀프 반려 체크 (사용자 확정 2026-07-11 — "처음엔 대충, 다그쳐야 제대로" 차단)

사용자에게 시안을 보여주기 **전에**, 이번까지의 실제 반려 사유 8문항을 렌더 PNG를 보며 자문한다.
하나라도 걸리면 제시하지 말고 스스로 고친다. 계약에 "셀프 반려 체크 8/8 통과" 항목을 필수로 넣는다.

1. **텍스트 덤프인가?** — 회색 카드/불릿에 문장을 부어넣은 구획이 있나 (S14 vA·S15 vC1 반려)
2. **메커니즘이 형태로 보이나?** — 내용의 동작(차단·분해·경로)이 그림이 아니라 설명문에만 있나 (S15 리그 반려)
3. **재탕인가?** — 다른 장에서 이미 쓴 수치·내용·시각 어휘를 반복하고 있나 (S18 스탯·S20 폐기)
4. **빈 반쪽이 있나?** — 시선이 머무는 어색한 공백, 좌우 불균형이 있나 (S17 vD4·S21 vA 반려)
5. **글자가 읽히나?** — 캡처·라벨이 슬라이드 배율에서 판독 가능한가 (S12 캡처 반려)
6. **붙었나?** — 라벨-도형, 도형-도형이 숨 없이 붙어 있나 (S11 라벨-칩 반려)
7. **주제와 무관한 채움인가?** — 그 구획이 이 장의 독자 질문에 답하는가 (S18 경계 안 스탯 반려)
8. **정렬이 스냅됐나?** — 같은 계열 요소의 축·중심·피치가 수치로 균일한가 (S11 분기 스냅 스펙)
