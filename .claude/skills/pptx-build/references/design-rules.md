# 골든 디자인 규칙 (단일 출처)

> **목적:** 골든 슬라이드를 사용자 승인으로 확정할 때마다 그 판단을 여기에 박제해서,
> 다음 자동화(새 덱 생성)가 사용자 손을 덜 타게 만든다. 이 파일은 그 축적의 단일 출처다.
> 사용자 승인 반복으로 확정된 것이므로 임의 변경 금지 — 변경은 골든 덱 재승인 경유.

**골든셋 사용 원칙(2026-07-11 확정 · 2026-07-16 개정 — 변형 가능한 출발점):** 골든 덱은
복제 템플릿이 아니라 실전 덱이 출발하는 **완성도 기준점**이다. "그 장에 텍스트만 갈아 끼운 것"은
사용자가 명시 기각한 UX다 — 실전 장에서 골든과 갈라지는 선은 다음과 같다:

- **상속(골든에서 그대로):** 구획 문법(§6) · 도형 어휘(§5) · 색 규율(§2) · 타이포 위계(§3) ·
  GRID 좌표계(§1) · 물성→형태 원칙(P1).
- **파생(내용에서):** 항목 수 · 구획 수 · 피치 · 배치 — 내용이 정한다. 내용 구조가 골든과
  우연히 같으면 결과가 같아지는 것은 허용하되, 같음을 강제하지 않는다.
- **정형 장 예외:** 표지·목차·간지·클로징은 고정 템플릿(텍스트 스왑) 유지 — 내용이 변하지 않는 장.

실전 덱 절차(content 주입 / adapted 변형 / novel 신규와 게이트)는 Ⅲ부 P5. 골든 덱 내부의
상호 참조 정합(목차 페이지 번호 ↔ 실제 장 수, 부-내용 채움 여부)은 요구하지 않는다.

구현 참조(전부 `pptx-build/scripts/goldenfab/` — 2026-07-15 단일화로 golden/ 사본 삭제):
`kit.py`(도형·텍스트 헬퍼), `grid.py`(좌표계), `layouts.py`(확정 구현 — 표지·목차·간지의 기준),
`audit.py`(전역 오딧). 조판 도구함은 `deckkit`으로 옮겼다. 분기 스냅·골든 조립 코드는 2026-07-29에
아카이브했다 — 이 목록에 없는 이름은 부를 수 없다.

구성: **Ⅰ부 전역 규칙**(모든 장) → **Ⅱ부 장 유형별 문법**(아키타입별) → **Ⅲ부 제작 프로세스**.

## P0 — 북극성: 이 장이 왜 존재하나 (설계 **전** 필수 · 2026-07-21 사용자 확정)
> **강제:** [눈] — 목적·형태 판단은 참/거짓이 없다(P1.5: 하강 대상 아님, P4 채점 영구 위임).

> 반복 실패의 근본은 규칙 부족이 아니라 **목적 부재**였다 — 밀도 게이트만 보고 통과작을 베끼거나
> 4카드로 밀어버렸다(사용자: "s08 베껴오면 골든덱 또 만드는 의미가 뭐냐 · 카드4개는 기술설명에나
> 맞지"). 형식을 먼저 집는 것이 병이다. **설계 전 이 5개를 이 순서로 통과한 뒤 형태를 정한다.**

0. **내용이 형식을 정한다 — 형식 먼저 = 병.** 통과작(s08 등)을 베끼거나 4카드·워플로 밀지 마라.
   "이 장이 독자에게 말해야 하는 것"을 한 문장으로 먼저 쓰고, **거기서** 형태가 나온다. 같은 형식이
   다른 장에 반복되면 그 자체가 경고(§7 형제 대조).

1. **형태는 그 탭의 "일"이 정한다.** 통과작 6장을 실측해 뽑은 표 — 무엇을 hero로 보여줬나:

   | 탭 유형    | 통과작 | 핵심(hero) = 봐야 할 것                             | 형태                                 | 카드  |
   | ---------- | ------ | --------------------------------------------------- | ------------------------------------ | ----- |
   | 문제 정의  | s04    | 실패의 **인과**(근거 부족→확정강행→허위확정→불가역) | 인과 흐름도 + 한계 팬-인→깨진 게이트 | ✕     |
   | 기술 설명  | s08    | 실무어↔기준서어 **실물 매핑** + JSON                | 상단 N:M 도해 + 실물 카드            | ✓ 4장 |
   | 기술 설명  | s09    | **그래프 구조**(계층 트리 + 간선 7종)               | 상단 트리 + node-link                | ✓ 4장 |
   | 기술 설명  | s11    | **판단 메커니즘**(질문→걸림→분기)                   | 상단 흐름·분기 도해                  | ✓ 4장 |
   | 기술 설명  | s12    | **실물 화면** + 출력 계약 스키마                    | 캡처 + 스키마                        | ✓ 4장 |
   | 문제와해결 | s14    | 두 시스템 **대비**(탈락✕ vs 도달✓)                  | 좌우 병렬 패널 + 실측                | ✕     |

   읽는 법 — **기술 설명** = 그 기술의 실물 구조/메커니즘을 상단 도해 + 성질 3~4개를 하단 리치
   카드(**카드는 오직 여기**). **문제 정의** = 실패의 인과를 흐름·구조 논증(카드 아님). **대비·A/B**
   = 좌우 병렬, 같은 입력의 다른 거동(카드 아님). **결과** = 몇/몇 합격 + 실패 전수 해부 + 방법 →
   기술 카드 패턴 금지, 결과 고유 형태. 새 탭이면 이 표에 없는 hero를 P1(물성)으로 새로 판정한다.

2. **없어 보이지 않게 — 밀도(글자수 아님).** 통과작이 꽉 차 보이는 진짜 이유:
   · **모든 존이 정보를 진다** — 빈 장식 구역 0 (s09는 간선마다 우측에 출처 주석까지).
   · **주장마다 근거·수치가 층으로** — 리치 카드 = 배너+아이콘+2단 불릿 3+칩 3(4층). 바 레이블
     하나로 끝내지 않는다.
   · **실측 수치가 박혀 있다** — "105건 중 103 탈락 98%" · "노드 929 = 개념80+문단250+…".
   §6-D 글자수 게이트는 **최악의 텅 빔만 걸러내는 하한 대리지표**지 밀도의 정의가 아니다.

3. **어울리는 시각화를 넣는다.** 비교=대비/dumbbell · 비율=링·막대 · 관계·구조=도해(node-link/tree)
   · 실물=캡처 · 측정=metric. 내용의 **물성**에서 나온다(`pptx-visuals/references/visual-selection.md` 결정표). 안 맞으면 억지
   템플릿 금지 — 검색 플라이휠(P1.5).

4. **설명이 필요하면 텍스트를 많이 써도 된다.** 얇은 게 죄지 긴 게 죄가 아니다 — 근거·분석은
   문장으로 충분히. (단 한 장 한 메시지는 유지)

**게이트 순서:** P0(목적·형태 결정) → P1(물성 선언) → 착수 → P4(제시 전 셀프체크) → P5(기계 게이트).

### 2. 색 규율 (흑/백/회 + accent 1색 절약)
> **강제:** [기계: check_accent] · [부품: kit.mix] · [산문·하강대기: hex 래칫(test_wiring 아카이브로 2026-07-29 소멸)]

- **accent 사용처는 장당 3곳 내외로 카운트**(예: 대형 용어 1, 강조 도형 1, 강조 스파인 1) —
  스크립트로 accent 색 도형·런 수를 세서 검증(오딧 상한 4).
- 대비 도형 쌍은 동일 지오메트리(같은 라운드·스파인·패딩), 차등은 **채움 명도만** —

### 3. 타이포 위계 (중간 크기 몰림 금지)
> **강제:** [산문·하강대기: 대형 런 ≥2·9pt 하한은 산수인데 검사 없음] · [눈: 위계 적절성]

- 점프: display(40)/title(32) → head(15) → body(12) → caption(9)/foot(8). 구획 제목은 head 15pt.
- 장당 대형 런(>15pt, 헤드라인 제외) ≥ 2개 — 좌측 앵커 대형 용어가 그 자리.
- 헤드라인은 1줄(2줄 겹침 금지), 좌측 앵커 구조: 캡션 라벨 → 대형 용어 → 리드 1문장 →
  번호 리드인(01·02).
- 본문 폰트 하한 caption(9pt) — 그 미만 금지(사용자 가독 지적 이력).

### 4. 텍스트 리듬 (단어 쓸 곳 / 문장 쓸 곳 / 한글 줄바꿈)

### 5. 도형·커넥터 어휘 (기본 사각형 나열 금지)
> **강제:** [기계: check_node_class] · [눈: 점선/실선 의미 일관 · 진행형 도형(셰브런·펜타곤)은 분기 없는 단순 진행에만 · ~~s11_branch_snap.audit~~(아카이브)]

  결말(치명/안전 등)은 밴드의 마지막 도형으로 통합. 셰브런 밴드는 분기 없는 단순 진행에만.

  커넥터는 전부 **화살표**(tailEnd 삼각형 XML) + 분기 라벨(IN/OUT accent bold) +
  노드 아래 핵심 기술 태그 1줄(볼드).
- 다이어그램 상세는 도형 안이 아니라 **하단 두괄식 칼럼**(기술명 볼드 리드-인 → 작동 방식,
  세로 헤어라인 구분)으로 — 도형 캡션에 3줄 밀어넣기 금지.
- **1:3 flat tree 분기**(S11 스냅 확정): 루트 박스 세로중심 = 3갈래 전체 세로중심(가운데 갈래
  중심), 갈래 칩 left 3개 완전 동일, 가로 커넥터 y = 각 칩 세로중심, 행 피치 0.42.
  (구현·오딧 표였던 `s11_branch_snap.py`는 2026-07-26 부품화로 사라졌고 그 부품마저 2026-07-29
  아카이브됐다 — 지금 이 값은 **직접 조판할 때 맞춰야 할 수치**다.)
- **점선/실선 형태 언어**(S14~): 점선 화살표·점선 테두리 = 확률·불확실, 실선 경로·실선 테두리
  +✓ = 결정. 차단은 경로를 끊는 짧은 바 + ✕. 덱 전체에서 이 의미를 일관 유지한다.

### 6. 구성 문법 (1장 = 다구획 고밀도 + 공기)
> **강제:** [기계: check_density·check_fill_ratio·check_text_overflow·check_text_collision] · [눈: 어휘 중복·독해 동선 · 구획 공기(여백 부족은 눈이 진다)]

- 한 장 = 좌측 앵커 칼럼 + 주 시각 구획 + 보조 구획(+결론 바) — 한 정보만 넣으면 비어 보인다.
- 구획은 여백이 아니라 장치로 나눈다: 구획 소제목(head 15 bold)+수평 룰, 세로 헤어라인, 배경 밴드.
- 구획 사이 독해 동선 장치(커넥터·화살표) — 구획은 연결되지 나열되지 않는다.
- 용어 축 매트릭스(2×2 등 해독 필요 형식)보다 시나리오/스토리 구도 우선.
- "아이콘 1개+설명 1줄" 단독 나열 구획 금지(시각 다양성 상실). 아이콘은 패널 헤드 보조로.
- 숫자 스탯 단독 나열 금지 — 비례 바·대비·분기 등 관계 인코딩과 결합.
- **장 내 시각 어휘 중복 금지**(S11): 같은 도해 문법(세로 fan, 좌우 트리 등)을 한 장에 두 번
  쓰지 않는다 — 두 번째 분기는 다른 형태(1:3 flat tree, 브레이스, 표)로. "장마다 새 아키타입"의
  장 내부 버전.
- **예시와 실물 도해는 한 흐름으로 통합**(S11): "적용 예시" 스트립과 "실물 구조" 도해를 나란히
  두 개 만들지 말고, 실제 입력(질문)에서 시작해 실물 구조의 분기까지 한 줄 서사로 — 맨 위
  노드는 추상 제목이 아니라 실제 질문.
- **나열은 도형에 가두기**(S11): 갈래·항목 텍스트를 맨바닥에 나열하지 말고 라운드 칩/박스에
  가둔다(볼드 헤드 + muted 설명을 같은 칩 안에). 커넥터는 칩 좌변 세로중심에 닿는다.
- **공기 수치**(S11): 섹션 라벨 bottom ↔ 첫 도형 top ≥ 0.12(assert로 박을 것). 도형 그룹은
  칼럼 폭 기준 좌우 균형 — 왼쪽 절반에 몰려 오른쪽이 비면 텍스트 확대 또는 그룹 우이동.
  칩·박스는 풀폭 금지, 내용 폭 + 인셋으로.

### 8. 고밀도 개편 규율 (s06 기준 · 2026-07-20 재작성 — 공유 헬퍼 — 2026-08-03 삭제)
> **강제:** [기계: check_density·check_adhoc_card] · [부품: deckkit — 헤더·카드·2단 불릿(옛 dense는 삭제)] · [산문·하강대기: 도해 재드로(백로그 ①)·N카드 억지(백로그 ②)·재서술 바(백로그 ③)] · [눈: 리치·의미 정합]

s06(용어사전 파이프라인 장)에서 확정한 밀도·형태 기준. **주의: 이 조항 초판(2026-07-20)은
"압축 헤더 + 밴드 + hero_card 4장"을 고정 공식으로 박제했고, 4카드가 안 맞는 장(비교·경계·
문제정의·스크린샷)에까지 기계 강제되어 5장이 반려됐다. 그 공식은 폐기다 — 아래가 교정본이다.**
헬퍼는 `deckkit`(헤더·카드·칩·2단 불릿)을 쓰되, **카드는
카드가 필요할 때의 단일 컴포넌트일 뿐 장마다 N개를 강제하지 않는다.**

- **기본 개편 = 최소 손질(전면 재편이 예외).** 사용자 최초 불만은 *큰 헤더 + 하단 전폭 바 +
  일부 스카스한 장*이었지 도해가 아니었다. 그러므로 대부분 장의 dense 개편 = (a) 헤더 압축
  (b) 하단 전폭 바 제거 (c) **진짜 빈 곳만** 채움. **골든 도해·레이아웃은 유지한다.** "밴드 + N카드"
  전면 재편은 그 장이 *원래 스카스하고 + 내용이 N 대등 병렬*일 때만(s06 4기술이 그런 장).
- **N카드는 내용이 진짜 N 대등 peer일 때만.** 비교장(2항)·경계장·문제정의는 병렬이 아니다 —
  칸에 맞추려 억지 카드·억지 배지 숫자를 만들지 않는다. 안 맞으면 골든 원 레이아웃(2패널·3열·
  도해+주석, §6·Ⅱ부 그 장 아키타입)을 밀도만 올려 유지한다. **재발 원인: §8 초판이 4장을 공식으로 박음.**
- **도해는 재사용, 재드로 금지(치명).** 그 장에 이미 확정된 도해가 있으면 그 구현을 import/호출
  하거나 좌표만 옮겨 복사한다(로직·색·도형 100% 보존) — 새 드로잉 코드로 다이어그램을 다시
  그리기 시작하면 **멈춘다.** 절차·검증은 P5(content주입/adapted). **재발 원인: 템플릿 지키려
  골든 도해를 버리고 조악하게 재드로 → 원본보다 품질 하락(2026-07-20 반려 5장 전부 이것).**
- **하단 전폭 '한줄평/재서술 바' 금지 — 형태 자체가 금지.** 검은색이든 라이트 바탕이든
  accent 좌변이든, 슬라이드 맨 밑 전폭 한 줄로 결론을 재서술하는 요소는 만들지 않는다.
  결론 문장은 콘텐츠(카드 불릿·배너)에 흡수한다. `takeaway_strip`류 헬퍼는 폐기됨 — 되살리지
  말 것. **재발 원인: "검은 바"로만 기억해 색을 바꿔 되살림.**
- **압축 헤더 강제.** 키커(8pt) + 헤드라인(14pt) + 굵은 룰. 28pt 헤드라인·상단 리드 문단 금지
  (`deckkit.kit.header`). 상단 의식 ≤0.7".
- **밀도 패리티 — 죽은 흰 여백 금지·뒤 장일수록 얇아지면 FAIL.** 카드를 두면 s06 카드 밀도에
  맞춘다: 배너/헤드 + 2단 볼드 불릿 **≥3** + 아이콘 칩, 칩은 마지막 불릿 바로 밑에 붙여 여백이
  벌어지지 않게 콘텐츠에서 위치를 파생. **못 채우면 그 카드는 존재하면 안 된다**(억지로 얇게
  지어내기 금지). 내용은 팩트시트·원문 근거만(창작 0). **재발 원인: s06 밀도가 검사 가능한
  기준으로 없어서 장마다 약한 변형을 즉흥 생성.**
- **불릿은 2단(볼드 리드 + 짧은 설명), 서술형 문장 금지.** `deckkit`의 2단 불릿.
- **바 제거·헤더 압축으로 생긴 세로 공간을 '늘려서' 메우지 말 것(2026-07-20 s04 실측).**
  도해를 세로로 스케일(affine ty의 계수>1)하면 요소 간 간격만 벌어져 밀도가 떨어지고
  "비어 보인다"(사용자 반려). 골든 도해는 **자연 크기·밀도 그대로 두고 위로 평행이동**만 한다
  (ty(y)=y+dy, 높이 미스케일). 확보된 공간은 (a) 성긴 요소를 라벨+설명 2줄로 채우거나
  (b) 흡수한 결론을 아이콘 단 패널(§5)로 실질화해 메운다. 못 채우면 자연 크기로 두고 균형
  여백으로 남기되, 남은 공백이 넓으면 밀도 밴드(P5)가 FAIL로 잡는다. **핵심: 공간을 늘림이 아니라
  실질 내용으로 채운다 — 늘림은 밀도 하락이다.**
- **제시 전 밀도 게이트 필수(2026-07-20 배선 — 매 장 재시도 루프 차단).** 밀도 지표의 단일
  출처는 **정본 `goldenfab/audit.py`의 `check_density`(글자수 주지표, 스크린샷 예외)**다. 실전
  덱(여러 장)은 `score_deck.py`가 **정본 audit.py 지표**로 채점한다 — **green 된 뒤에만** 사용자에게 보인다(예전엔 preflight가 660이라는
  경쟁 임계를 따로 뒀는데, 그게 audit.py와 중복이라 정본으로 통일). 밀도 지표는 도형 수가 아니라
  **총 텍스트 글자수** — 임계는 리터럴이 아니라 **골든 스냅샷 본문 최저 텍스트량에서 파생**(골든이
  dense로 재개편되면 임계도 자동 상승, "골든 따라 이동"). **도형 수로 재면 안 된다**: 골든 항목형
  ab_simulation은 37도형이지만 624자로 꽉 찬 통과작인데 도형 수 게이트면 반려되고, 그게
  "hero카드로 도형 채우기"=4카드 강제의 기계적 원인이었다(2026-07-20 s14 반복). 스크린샷 장(§F)은
  밀도 예외(DENSITY_EXEMPT), 의도된 반복은 `generic_checks(dup_allow=)` 래칫. **이게 실전
  파이프라인이 novel 장을 뽑을 때 쓸 게이트와 같은 메커니즘** — 사람을 품질 게이트로 쓰면
  골든급이 안 나온다(P1.5).
  판단형(균형·형식적합·도메인 어휘)은 P4 병렬 채점에 렌더+통과작 앵커를 붙여 함께 본다.
- **착수 전 구조 게이트(그리기 전에 판정).** ①이 장에 잘 만든 도해가 있나 → 있으면 재사용
  (재드로 금지) ②내용이 N 대등 항목인가 → 아니면 N카드 금지 ③원래 스카스한가 → 아니면 최소
  손질로 끝. 제시 전 셀프체크는 P4(⑨⑩ 신설)로 승격 — 하단 전폭 바 없나 / 도해가 원본과 도형
  수·디테일 같나 / 카드 밀도 s06급인가.
- **골든 도해를 재배치할 땐 위치(ty)와 높이(sh)를 둘 다 스케일한다 — 위치만 늘리면 회귀한다
  (2026-07-20 s14 반복 반려).** affine으로 골든 도해를 넓어진 공간에 옮길 때 y 위치만 변환하고
  박스 높이를 골든 그대로 두면, 내용은 상단에 뭉치고 **위로 치우치고 밑이 텅 빈다**(검은 바가
  채우던 하단이 빈 채로). 채움 = 내용을 실제로 키우기 → 칩·카드·화살표 **높이도 같은 계수로
  스케일**(sh(h)=A·h). 그래야 도해가 커지며 하단까지 찬다. **위치 스케일만 = 간격 늘리기 = §8이
  금지한 그 늘림이다.**

### D-2. 문제 정의 장 (S4 v17 — 사용자 확정 2026-07-15, 반려 5회 끝)
> **강제:** [기계: check_verdict_contrast] · [눈: progress_shapes·ink_collision은 구현은 있으나 배선 0(위 정직한 공백)] · [눈: 분기 물성·인과]

- 문제의 물성 = **분기**. "두 시스템이 어떻게 다른가"는 **판정(◇)의 유무**다 — 구조가 다르다.
  **둘 다 같은 모양의 밴드로 그리면 구조가 같아 보여 말하려는 것과 정반대가 된다**(v16 반려:
  "저 비교는 파이프라인으로 할 게 아니다"). 공통 뿌리(질문) → ◇ → 충분/부족, 부족에서 두 갈래.
- **셰브런·펜타곤 0개**(오딧 강제). 확정/유보는 순서가 아니라 XOR이라 진행형 도형으로 이으면
  "확정한 다음 유보한다"는 거짓 인과가 된다.
- 오류 대비의 물성 = **회복 가능성**, 인코딩은 **경로 도달 거리**: 치명(2종)은 프레임 끝까지 가서
  종착 박스에 박히고, 안전(1종)은 **실제 복귀 호**로 질문까지 되돌아온다. 문장 박스 나열 금지.
  - **복귀는 반드시 선으로 그린다.** 한쪽은 진짜 화살표인데 다른 쪽이 글자면 **비교의 두 항이
    다른 층위**가 된다(v15 채점 FAIL 4건이 이 하나로 수렴). 복귀 호가 좌하단 공백도 함께 메운다.
- 원인(범용 LLM 한계 N가지)은 **fan-in**으로 → 종착은 **못 세운 ◇**(점선, §5 점선=불확실).
  상단의 서 있는 ◇와 같은 크기·같은 글자여서 "같은 판정인데 하나는 서고 하나는 못 선다"가
  형태로 읽힌다. 원인을 **결과(2종)로 수렴시키면 상단이 이미 배달한 결론에 다시 착지**한다(재탕).
- **색: accent는 면(面)으로만 위험을 말한다.** 판정 단어(✕·↩)는 primary 잉크 — accent 글자는
  흰 바탕 3.41:1로 판정을 지기엔 흐리다. **primary 채움은 결론 바 하나뿐**(종착 박스를 검정으로
  두면 파국과 우리 원칙이 같은 옷이 된다 — v15 실측 fill 바이트 동일).
- 확정 렌더: `_archive/golden-variants/`(2026-07-29 이동). 색 전수·음의공간 증명:
  `_workspace/06_s4-color-inventory.md`.

### E-2. 관계가 물성이면 표를 쓰지 않는다 (사용자 확정 2026-07-15 — S8·S9 반려)
> **강제:** [기계: check_duplicate_nodes(allow 실측)] · [부품: 자리 파생(항목 수에서 좌표를 뽑는 정본 — 한계 초과 시 시끄럽게 죽음) · ~~s08_variants.chip_w~~(아카이브 — 2026-08-02 확인)] · [산문·하강대기: 관계-표 판정(백로그 ⑤)] · [눈: 물성 판정]

**판정 기준 하나:** 열 사이에 **관계**가 있으면 표가 아니라 도해다. 표는 각 행이 독립적이고
열이 서로 무관한 **속성 목록**일 때만 쓴다. 헷갈리면: 셀 안에 `A · B`처럼 구분자로 여러 값을
욱여넣고 있으면 그건 관계이고, 표가 그걸 뭉개는 중이다.

반려 실측(이 조항의 출처):

- **S8 용어사전** — 물성은 "실무어를 기준서어에 **잇기**(N:M)"인데 4열 표로 그렸다. 한 용어가
  여러 개념으로 갈라지는 1:N도, 여러 용어가 한 개념으로 모이는 N:1도 쉼표 하나로 뭉개졌다 —
  그게 용어사전의 본질인데. 게다가 죽은 열이 절반이었다(`원천` 5행 중 4행 동일값, `등급` 4행
  "자동"). → **이분 매핑**: 좌열 ─선─▶ 우열. 갈래와 수렴이 선의 모양 그 자체로 보인다.
- **S9 지식그래프** — 물성은 "무엇이 무엇을 잇는가"인데 `어떻게 만들었나` 열에 40자 문장을
  붓고 `수` 열에 숫자를 세웠다. 그 열에 **노드와 간선이 섞여**(80은 노드, 79·1,220은 간선)
  더할 수 없는 숫자가 한 줄에 섰다. → **실물 카탈로그**: 각 행이 `[A] ─종류─▶ [B]` 도해 +
  출처 규칙 1줄. 노드 종류는 모양으로 구분.

**표는 검산을 강제하지 않는다.** S9 표의 수치를 비례·합으로 그리려는 순간 오류 3건이 드러났다
— 간선이 폐기값 2,697(팩트시트는 실측 2,694를 참값으로 명시), 용어 노드 423(실제 400), bc
그룹 11 누락. 합이 941인데 제목은 929였고, **표라서 아무도 검산하지 않았다.** 도해로 그렸으면
첫 렌더에서 선이 안 맞아 바로 드러났을 문제다. 수치를 표에 세우려거든 먼저 물어라 — 이 숫자들이
서로 더해지는가? 아니면 한 열에 세우지 마라.

수반 규율:

- **좌표 정렬은 폭이 아니라 한쪽 변으로.** 열을 맞추려고 칩 폭을 균일하게 두면 짧은 라벨에서
  죽은 회색이 생긴다(오딧 채움률 실측: "위탁약정" 4자가 3.45" 칩에서 12%). 칩 폭은 글자에서
  파생하고(계산기는 아카이브와 함께 사라졌다 — 쓰려면 다시 만든다), 정렬은 좌열=우변·
  우열=좌변 고정으로 잡는다. 그래야 선
  출발·도착점이 일정하면서 §6 "내용 폭 + 인셋"도 지켜진다.
- **항목 수가 content로 바뀌면 좌표를 파생**(§F)하고, **수용 한계를 넘으면 시끄럽게 죽인다**.
  자는 `goldenfab/grid.py`의 **`pitch`(세로)·`track`(가로) 단일 출처**다(2026-07-25: 같은 식이
  장 렌더러 3곳에 열화 사본으로 흩어져 있던 것을 합쳤고, 그 사본들은 아카이브와 함께 사라졌다).
  파생만으로는 부족하다 — 항목이 아주 많으면 피치가 칩 높이보다 작아져 칩이 겹치는데 하한(6.35)은
  안 넘어 경계 검사를 통과한다. 조용히 틀리는 값이다. 가로도 같은 병이다: 칼럼 폭이 판독폭 아래로
  내려가면 글자가 세로로 쪼개지는데 게이트는 통과한다(`check_text_overflow`는 글자폭을 0.62×pt로
  근사해 **한글 넘침을 못 잡는다** — 2026-07-25 실측: 폭 1.725"·9pt 본문 42자가 5줄로 흘러넘쳤는데
  미탐). 그래서 `track`의 `min_w`는 **그 상자가 실제로 수용한 폭을 렌더로 재서** 박는다.
- **같은 노드의 재등장이 메시지인 경우**가 있다(카탈로그에서 `변동대가`가 hier·cp·term 3행에
  등장 = "한 개념에 세 종류가 붙는다"). 오딧 `check_duplicate_nodes(allow=N)`에 **실측 수를
  박아** 늘면 FAIL로 잡되, 예외를 열지는 않는다.

### F. 스크린샷 전용 장 (S10·S12 캡처부)

- 캡션은 **accent 바(0.5×0.035) + muted 캡션** 한 줄. 캡처가 실제 산출물과 다른 시점이면

- **관찰 포인트 칼럼**("이 화면에서 보이는 것" — accent 번호 + 볼드 헤드 + muted 설명):
  항목은 전부 캡처 안에 실제로 보이는 요소와 1:1 대응 — 화면에 없는 주장 금지.
  **세로 피치는 항목 수에서 파생**한다. 리터럴 피치를 쓰면 항목 수와 무관해져
  넘친다 — 구 `py = 2.4 + i*1.05`는 4개일 때 마지막 본문 bottom 6.47로 하한(6.35)을 넘었다.
  검증: 3·4·5·6개 전부 하한 내. 이 규율은 **항목 수가 content로 바뀌는 모든 세로 나열**에 해당한다.
- **발췌 크롭**(S12): 세로로 긴 캡처를 통짜 축소하면 글자가 죽는다 — 핵심 구간만 크롭해 폭을
  키운다(글자 판독 가능이 기준). 크롭 경계는 문장·행 중간 잘림 0이 될 때까지 조정, 캡션에
  "발췌"와 원본 맥락 명시.
- 오딧: 슬라이드당 picture == 1 — 캡처 2장 이상이면 장을 쪼갠다.
- **이미지는 `kit.fit_picture()`로 박스에 맞춘다**(2026-07-15 버그). `add_picture(..., height=…)`처럼
  **한 축만** 주면 다른 축은 실제 파일 비율이 정한다 — 비율을 리터럴로 가정하면 다른 이미지가
  왔을 때 조용히 옆을 침범한다(실측: 가정 3200×2000(1.60) vs 실제 1899×926(**2.05**) → 폭 7.6"

### P4. 제시 전 셀프 반려 체크 (사용자 확정 2026-07-11 — "처음엔 대충, 다그쳐야 제대로" 차단)
> **강제:** [기계: check_adhoc_card(⑪)] · [눈: ①③④⑤⑧⑨⑩ — audit_golden이 잡던 ①③④⑤⑧도 2026-07-29부터 눈검증 몫]

사용자에게 시안을 보여주기 **전에**, 이번까지의 실제 반려 사유 11문항을 렌더 PNG를 보며 자문한다.
하나라도 걸리면 제시하지 말고 스스로 고친다. 계약에 "셀프 반려 체크 11/11 통과" 항목을 필수로 넣는다.

> **순서: 채점(`score_deck.py`) → 렌더 눈검증 → 사용자.** 11문항 중 기계가 잡는 건 ⑪뿐이다
> (`check_adhoc_card`). ①③④⑤⑧을 잡던 `audit_golden`은 2026-07-29 아카이브 — 그만큼 눈이 더 진다.

**실전 덱은 전 장 병렬 채점(2026-07-16 확정 — "전 장 채점하되 2시간은 안 된다"):** 본문 전 장의
렌더 PNG를 **장당 1개 채점 에이전트로 동시에** 파견한다 — 순차 금지(10장 순차 = 2시간 30분,
병렬 = 최장 1장 시간 ≈ 15분). FAIL 난 장만 고쳐 **그 장만** 재채점한다(전체 재채점 금지 —
P1.5의 "재채점 비수렴" 실측은 같은 장을 다시 채점할 때 이야기다). 채점 프롬프트에는 물성이
가까운 골든 렌더 PNG 1~2장을 첨부해 "골든 수준 대비 시각화·밀집화인가"를 함께 판단시킨다.
채점자가 캔 규칙은 audit로 하강(P1.5) — 회차가 갈수록 채점 FAIL 자체가 줄어야 한다.

1. **텍스트 덤프인가?** — 회색 카드/불릿에 문장을 부어넣은 구획이 있나 (S14 vA·S15 vC1 반려)
2. **메커니즘이 형태로 보이나?** — 내용의 동작(차단·분해·경로)이 그림이 아니라 설명문에만 있나 (S15 리그 반려)
3. **재탕인가?** — 다른 장에서 이미 쓴 수치·내용·시각 어휘를 반복하고 있나 (S18 스탯·S20 폐기)
4. **빈 반쪽이 있나?** — 시선이 머무는 어색한 공백, 좌우 불균형이 있나 (S17 vD4·S21 vA 반려)
5. **글자가 읽히나?** — 캡처·라벨이 슬라이드 배율에서 판독 가능한가 (S12 캡처 반려)
6. **붙었나?** — 라벨-도형, 도형-도형이 숨 없이 붙어 있나 (S11 라벨-칩 반려)
7. **주제와 무관한 채움인가?** — 그 구획이 이 장의 독자 질문에 답하는가 (S18 경계 안 스탯 반려)
8. **정렬이 스냅됐나?** — 같은 계열 요소의 축·중심·피치가 수치로 균일한가 (S11 분기 스냅 스펙)
9. **템플릿을 강제했나?** — 이 장 내용이 그 형식(N카드·밴드 등)에 진짜 맞나, 안 맞는데 칸을
   억지로 채웠나. N 대등 병렬이 아니면 그 템플릿을 쓰면 안 된다 (§8 · 2026-07-20 반려 5장)
10. **도해를 재드로해 열화시켰나?** — 이미 있는 도해(골든 장·아키타입)를 import/호출·좌표복사로
    재사용하지 않고 새 드로잉 코드로 조악하게 다시 그렸나. 원본과 도형 수·디테일이 다르면 FAIL (§8·P5)
11. **카드에 어휘를 집었나?** — 카드가 하나뿐이면 전 장이 같아진다. **좁은 자리면 겹을 빼는
    게 아니라 `hero`(아이콘 크기)를 줄여 그대로 쓴다**(필요 높이 파생식은 그 함수 docstring).
    → **기계 강제:** `audit.check_adhoc_card` — `generic_checks`의 **dense 프로파일**에 배선,
    `score_deck.py`가 물린다. sparse 제외(카드 idiom 상이) · 어두운 코드/아티팩트 패널 제외
    (P0 #1 실물). 한계: '어휘를 집었나'까지만 강제, '리치·의미 정합'은 눈검증 몫.
    - **문턱 2.4×0.9 근거(2026-07-25 래칫)** — 초판 3.0×1.5는 카드 크기만 봐서 다이어그램
      노드가 눈 밖이었다(`flow` 2.66×1.4·`layers` 12.13×1.0·`branch` 7.63×1.24·`from_to`
      4.69×1.15가 같은 결함인데 미달 통과). 오탐 실측 0건(dense 10 · 다이어그램 18 · 개선 4).
      더 낮추면(2.4×0.6) s14_dense 1 · s16_dense 2가 오탐 — 그게 하한이 여기인 이유다.
    - **판정 상향 2026-08-02** — 좌변 바(얇은 선)는 구조로 치지 않고, `높이 ≥ 1.5`인 카드는
      **어휘**(아이콘 PICTURE·배지 OVAL·중첩 박스)가 0이면 FAIL. 계기: local-ai-assist 카드
      14장이 accent 좌변 바 0.055" 하나로 전부 통과했고, FAIL 메시지가 `hero_card 미사용`이라
      적혀 있어 그 통과가 "안 써도 된다"로 오독됐다. 오탐 실측 0/152장(golden-deck 30 ·
      golden-pilot 45 · probe 42 · results-검토 35). `≥1.5` 단서가 오탐 0의 핵심 — 없으면
      골든 s16 다이어그램 노드(4.50×1.38)가 걸린다. 대가로 1.13" 카드 1장은 빠져나간다.
    - **덱 단위 짝(2026-08-02 신설)** — `audit.check_icon_vocab`: 본문 전체 아이콘 어휘가 0이면
      FAIL. 장별로는 다 통과해도 어휘가 통째로 죽을 수 있다(실측: 골든 94~96개 / local 0개).
      **하한을 1보다 올리지 않는다** — 장별 커버리지 하한은 "카드 4장 써라"와 같은 승격이다.

### P5. 실전 덱 — 변형(adapted)·신규(novel) 장 절차 (2026-07-16 배선, 사용자 확정)
> **강제:** [기계: score_deck(generic_checks+밀도 밴드)] · [눈: 병렬 채점·창고 편입은 사용자 선택]
> (content_contract·compare_golden은 2026-07-29 아카이브 — 골든은 이제 고정 기준선이다.)

골든이 변형 가능한 출발점이 되면서 실전 덱의 본문 장은 세 갈래로 만든다.
형식 판정은 `pptx-visuals/references/visual-selection.md` 결정표.

1. **content 주입(`golden.<layout>`)** — 내용의 항목 수·구획 구성이 골든과 그대로 맞을 때만.
   좌표·색·도형 고정. 골든 글이 조용히 나가지 않도록 **수치·문장을 전량 교체했는지 눈으로
   확인한다**(강제하던 content_contract는 2026-07-29 소멸). 맞지 않는데 우겨넣으면 그게
   기각된 "텍스트 스왑"이다.
2. **변형(`adapted.<layout>`)** — 물성은 매칭되나 카디널리티·구획이 다를 때. 그 골든 타입의
   **코드와 렌더 PNG를 먼저 Read**하고(출발점), goldenfab 부품(kit·grid·피치 파생)을 재사용한
   장 스크립트를 새로 쓴다. Ⅰ부 전역 규칙(임의 좌표 금지·신규 hex 금지·어절 줄바꿈)은 그대로.
   **그 장의 도해는 재드로 금지 — 원본 구현을 import/호출하거나 좌표만 옮겨 복사(로직·색·도형
   100% 보존)한다. 새 드로잉 코드로 다이어그램을 다시 그리기 시작하면 멈춘다(§8 치명 규칙 ·
   2026-07-20 반려 5장의 원인). 카디널리티가 달라도 바뀌는 건 항목 수·피치지 도해 문법이 아니다.**
3. **신규(`novel`)** — 어느 물성에도 안 맞을 때. **물성이 가장 가까운 골든 렌더 PNG 2~3장을
   Read해 밀도·구성 앵커로 삼고**(규칙 산문만으로 시작 금지 — "저만치의 시각화·밀집화" 감각은
   완성 예시가 전달한다) P1 물성 선언부터 새로 설계한다.

**게이트 2겹** — 스냅샷 회귀(compare_golden)는 2026-07-29 아카이브됐다(골든이 고정 기준선이
되어 대조 대상이 없다). 실전 변형·신규 장은 아래가 진다:

- **기계(2초):** `uv run python .claude/skills/pptx-build/scripts/score_deck.py <pptx> [--body 4,5,7]` —
  전역 규칙(goldenfab.audit.generic_checks) + **밀도 밴드**. 밴드 임계는 리터럴이 아니라
  골든 스냅샷 본문 장의 최저 밀도(도형 수·텍스트 프레임 수)에서 파생 — 골든보다 성긴 장은
  FAIL이고, 골든이 진화하면 밴드도 따라 오른다. 장별 예외는 spec의
  `"audit": {"dup_allow": N, "known": {...}}`로 선언(코드 수정 없이, 실측 수를 박는다).
- **채점(병렬):** P4의 "전 장 병렬 채점" — 장당 1개 에이전트 동시 파견, 골든 앵커 첨부,
  FAIL 장만 재채점. 장 스크립트 작업 계약에는 P1 물성 선언 1번 항목이 그대로 필수.
- **창고 편입은 사용자 선택:** 덱 완성 후 novel 장 목록을 제시하고, **사용자가 고른 장만**
  본 파일 박제 + 렌더 PNG를 `golden/render/` 옆에 자산으로 편입(골든 1장 = 유지보수 계약 1개).
  **타입 승격은 없다** — 장을 통째로 배정하던 registry가 2026-07-29 폐기됐다. 안 고르면 그 덱
  전용으로 남는다.
