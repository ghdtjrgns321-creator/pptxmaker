# pptx-build — 조판 도구함 · 디자인 규칙

슬라이드를 **파이썬으로 직접 그린다.** spec을 넣으면 덱이 나오는 빌더는 없다(2026-07-29 폐기 —
장을 통째로 배정하니 전 장이 같은 형식이 되었다). 자리는 호출자가 정하고, 이 도구함은 도형과
좌표계와 규칙만 준다.

일관성은 **brand-kit과 좌표계에 박제**한다 — 색·폰트·여백을 손으로 넣지 않는다.

## 도구함 (`scripts/goldenfab/`)

| 모듈         | 주는 것                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------ |
| `kit.py`     | `load_kit()`(brand-kit) · `new_presentation()` · `add_box` · `add_text` · `fit_picture` · `set_shape_text` · `mix` |
| `grid.py`    | 좌표계 상수(`MARGIN_L`·`RIGHT_EDGE`)와 **개수에서 자리 파생**(`pitch`·`track`) — 자리를 손으로 계산하지 않는다     |
| `dense.py`   | 헤더·룰·카드 등 밀도 부품                                                                                          |
| `layouts.py` | 표지·목차·간지 — 정형 장은 이걸 그대로 쓴다                                                                        |
| `audit.py`   | `generic_checks`(전역 규칙) · `density_band`(골든 스냅샷에서 파생한 밀도 하한)                                     |

차트·다이어그램은 `pptx-visuals` 스킬이 단일 출처다. 여기에 차트 코드를 중복 작성하지 않는다.

> **`pitch`/`track`이 `ValueError`로 죽으면 하한을 낮추지 말고 넣을 것을 줄인다.** 그 하한은
> 칩끼리 겹치는 것을 막는 실측값이다(2026-07-15: 개념 18개 → 피치 0.109″ < 칩 높이 0.24″).
> 완화하면 경계 검사는 통과하는데 **글자가 조용히 겹친다** — 죽는 쪽이 그것보다 싸다.
> 2026-08-02 사고: 갤러리 미니 캔버스에서 가드를 계속 완화하며 5~6바퀴를 돌았다.

## 스크립트

```bash
# 재료를 기계가 센다 — 표 행 수·목록 개수·화살표 방향
uv run python scripts/scan_material.py FINAL-REPORT/ --json

# 렌더(PowerPoint COM) — 눈검증용 PNG
pwsh scripts/render_deck.ps1 -Pptx <경로> -OutDir <폴더>

# 기계 채점 — 전역 규칙 + 밀도 밴드
uv run python scripts/score_deck.py <deck.pptx> [--body 4,5,7]
```

## 밀도 밴드는 리터럴이 아니다

`audit.density_band()`가 `assets/golden-snapshot.json`에서 파생한다 — 현재 **글자 535자 · 도형
바닥 20**. 골든이 바뀌어 스냅샷을 갈면 밴드도 따라 움직인다.

**왜 글자수인가:** 도형 수로 재면 밀도 부족을 카드 4장으로 메우는 반사를 유발한다. 골든 항목형은
도형이 적어도 글자가 꽉 차 통과작이다. 그래서 chars가 주 하한, 도형 수는 텅 빈 장만 거르는 바닥.

**한계(정직):** 하한은 **텍스트 떡칠을 유도한다.** 실제로 문장을 줄였더니 밀도 FAIL이 나서 다시
늘린 일이 있다 — 게이트가 떡칠을 요구한 것이다. 그 빚은 시각 커버리지(pptmaker 규칙 2)로 갚는다.

## 골든은 고정 기준선이다

`golden/golden-deck.pptx` + `golden/render/`(17장). **보고 배우는 그림이지 부르는 함수가
아니다** — 생산 코드(`reference.py`·`s0N_dense.py`·`build_golden.py`)는 2026-07-29에
`_archive/`로 옮겼다. 되살리지 않는다.

`assets/golden-snapshot.json`은 그 덱의 도형 서명이며 `density_band()`의 유일한 소비처다.
스냅샷과 `audit.SNAPSHOT_KEYS`는 한 몸이라 같이 간다.

## 디자인 규칙 (필수)

레이아웃 GRID·오딧·색 규율·타이포 위계·텍스트 리듬·도형 어휘·구성 문법은
**`references/design-rules.md`가 단일 출처**다. 슬라이드를 렌더하기 전에 읽는다.
실물 레퍼런스 실측치는 `references/reference-metrics.md`.

### 계약 필수 2항목 (P1·P4 — 산문으로 두면 잊힌다)

레이아웃·시각을 만들거나 고치는 작업이면 **코드를 열기 전에** 완료 계약에 아래 둘을 넣는다.

1. **물성 선언(P1)** — 계약 1번 항목: `물성 선언 — <내용> = <형태>` 한 줄.
   내용의 동사(차단·분해·분기·도달)는 그 동작이 보이는 형태로, 명사는 실물 형태로.
   **회색 텍스트 카드 나열은 물성이 진짜 "목록"일 때만.** 완성 시안이 선언과 다르면 그 항목 FAIL.
2. **반려 채점 8/8(P4) — 자기채점 금지, 반드시 제3자 에이전트** (2026-07-14 실증)
   사용자에게 **제시하기 전에** 렌더 PNG를 별도 에이전트(설계 맥락 미제공)에게 넘겨 8문항 +
   아래 2문항을 채점시킨다. 1건이라도 FAIL이면 제시하지 말고 고친 뒤 재채점.
   - **왜 자기채점이 금지인가:** 자가 8/8 PASS를 준 슬라이드를 제3자가 채점하자 **4건 FAIL**이
     나왔다 — 텍스트 덤프, 메커니즘 미형태화, 셰브런으로 XOR을 그림, 그리고 **같은 장에서 검정의
     의미가 뒤집힘**(상단 검정=안전 / 하단 검정=치명). 마지막 것은 자가채점이 끝내 못 본 결함이다.
   - **추가 2문항:** ⑨ 형식-내용 적합(이 형태가 내용의 물성에 맞나) ⑩ 색 의미 일관(같은 색이 한 장
     안에서 다른 뜻으로 쓰이지 않나).
   - 채점 프롬프트는 설계 의도·변명을 빼고 **보이는 것만**으로 판정시킨다("애매하면 FAIL").

자주 걸리는 함정: ①텍스트 덤프 ②메커니즘이 형태로 안 보임 ④빈 반쪽 ⑥라벨-도형 붙음.
"대비 분기는 공통 뿌리 → 엘보 → 두 경로 — **나열형 2레인 금지**", "**2×2 등 축 매트릭스보다
시나리오/스토리 구도 우선**", "장 내 시각 어휘 중복 금지"는 실제 반려 이력에서 나온 조항이다.
