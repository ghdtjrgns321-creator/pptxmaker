### 2. 문제 인식과 해결 방향

- 문제 인식
  - 생성 후 편집 불가능 : 범용 LLM은 PPT결과물을 이미지 형태로 생성
  - 일관성 보장 어려움 : 프로젝트마다 다른 규격과 템플릿으로 생성
- 해결 방향
  - 편집 가능한 PPT : 파이썬 활용 도형과 텍스트 직접 배치
  - 템플릿 고정 : 내용 생성과 디자인을 분리 → 일관성이 필요한 서식 규칙만 고정

## 1. 문제 인식과 접근 비교

### 템플릿이 고정하는 것과 고정하지 않는 것

개요 2절의 "일관성이 필요한 서식 규칙만 고정"을 가른 기준

| 구분 | 대상                                          | 정하는 곳     |
| ---- | --------------------------------------------- | ------------- |
| 고정 | 색, 글꼴, 글 크기, 여백, 페이지 골격 4종      | 공통 하네스   |
| 변동 | 장별 배치, 어떤 내용을 어떤 그림으로 나타낼지 | 개별 슬라이드 |

- 가른 이유 : 배치까지 템플릿이 쥐면 그 형식에 안 맞는 내용도 같은 형식으로 그려짐
- 그래서 뺀 것 : 흐름도, 관계도 같은 완성형 도해 부품 0종, 사각형과 연결선만 제공

### 통상적 접근 대비 차이

| 관점             | 통상적 접근             | 이 도구                                    | 차이가 만드는 효과                               |
| ---------------- | ----------------------- | ------------------------------------------ | ------------------------------------------------ |
| 템플릿 범위      | 레이아웃 자리표시자까지 | 색과 글꼴과 여백, 페이지 골격 4종까지      | 자리표시자가 없어 장 구성이 굳지 않음            |
| 제목 결정 시점   | 슬라이드를 그리는 단계  | 계약이 자료 헤딩에서 따와 사전 확정        | 사용자가 안 보는 자리에서 문구가 안 바뀜         |
| 검사의 성격      | 통과와 실패의 판정자    | 물리적 형태만 차단, 품질은 점수로 보고     | 자료를 부품 모양에 맞춰 휘게 하지 않음           |
| 임계값 출처      | 설계자가 정한 고정값    | 완성본 실측에서 산출, 기준선이 바뀌면 이동 | 추측값 10종 중 9종이 실측과 달랐던 전례 차단     |
| 사용자 확인 위치 | 완성 후 피드백          | 그리기 전에 목업을 보여주고 선택           | 반려에 방향이 생김, 1안만 내밀면 "별로다"로 끝남 |

## 2. 실증 예시

`local-ai-assist` 소개 덱 19장을 자료 지정부터 산출까지 실제로 만든 기록. 단계는 [3. 핵심 설계](#3-핵심-설계)의 파이프라인 그대로다.

### ① 자료 — 어느 정리본을 쓸지 먼저 정한다

| 후보            |        분량 | 목표량 대비 | 판단                             |
| --------------- | ----------: | ----------: | -------------------------------- |
| `README.md`     |    64,189자 |         7배 | **채택** — 골격과 문장을 여기서  |
| `FINAL-REPORT/` | 1,353,962자 |       149배 | 근거 창고로만 — 수치를 보충할 때 |

목표량은 본문 17장 × 밀도 하한 535자 ≈ 9,100자다. 100배를 넘으면 "무엇을 버릴까"가 작업 전부가 되어 인터뷰조차 못 한다.

### ② 인터뷰 — 목차와 장별 초점을 계약으로 고정

- 사용자가 제시한 8장 중 **내용이 터지는 5장을 분할**해 본문 12장으로 확정, 5부 구성 확정
- 장 제목은 자료 헤딩을 1안으로 제시 — 「3-2. 룰 기반 검증」 → 『룰 기반 검증 29종』

### 도입 배경

- 실측 문제 : 계약 도입 전, 본문 12장 중 8장의 제목과 부 이름 5개 전부가 조판 단계에서 창작됨
- 드러난 사례 : 부 표지에 「Ⅱ 검증할 데이터」로 적혀 있었으나 자료의 원래 제목은 「합성 데이터 생성」
- 근본 원인 : 계약에 그 칸이 없어 조판이 알아서 지었고 대조하는 곳이 없었음

### 계약 서식 — 장 목록 7열

| 열             | 내용                           | 읽는 쪽            |
| -------------- | ------------------------------ | ------------------ |
| `#`            | 장 번호                        | 조판, 검사         |
| `부`           | 로마자 Ⅰ에서 Ⅴ, 정형 장은 대시 | 부 내비게이션 대조 |
| 장 제목        | 자료 헤딩 그대로               | 자료 대조          |
| 헤드라인       | 슬라이드에 실제로 박히는 한 줄 | 덱 검사            |
| 전하고 싶은 것 | 인터뷰 육성 채록 원문          | 목업 단계의 초점   |
| 자료 출처      | 어느 절에서 왔나               | 사람               |
| 상태           | 확정 또는 보류                 | 사람               |

- 부 내비게이션 = 본문 장 상단에 부 5개를 가로로 나열하고 현재 부만 강조하는 띠
- 부와 부 표지를 적은 별도 표가 그 문구의 유일한 출처, 조판과 검사가 **같은 함수로** 이 표를 읽음

### 계약과 자료 대조 규칙

| 단계      | 규칙                                                   |
| --------- | ------------------------------------------------------ |
| 헤딩 수집 | 자료의 1단계에서 4단계 헤딩 전부                       |
| 토큰화    | 숫자와 마침표 제거 후 구분자로 분할, 2글자 이상만 채택 |
| 히트 판정 | 제목 어절이 헤딩 토큰의 접두 또는 피접두면 히트        |
| 판정      | 전 헤딩 중 최대 겹침률이 0.5 미만이면 지어낸 말로 표시 |
| 면제      | 표지, 목차, 부 표지와 토큰 0개인 제목                  |

- 접두 매칭이 필요한 이유 : 한국어 조사, 계약의 「의사결정과」가 자료 헤딩의 「의사결정」에 붙어야 함
- 안 보는 것 : 제목 문자열만 보고 수치는 대조하지 않음, 그 공백은 [6. 한계](#6-한계)

- 실패 기록 : 후보를 주제별로 냈다가 **"이건 다 다른 주제인데? 뭘 고르라는 거야?"** 반려

## 5. 핵심 의사결정

### 5-1. 규격을 조이는 방향에서 최소한만 규정하는 방향으로

몇 달 동안 목표는 규격을 조여 결과를 고정하는 것이었고, 조일수록 결과가 나빠짐

| 대상      | 조이던 때                           | 지금                          |
| --------- | ----------------------------------- | ----------------------------- |
| 목표      | 규칙과 부품을 늘려 결과를 고정      | 규격만 맞추고 나머지는 풀어둠 |
| 도해 부품 | 흐름도와 관계도까지 완성형으로 제공 | 사각형과 연결선만, 완성형 0종 |
| 밀도      | 글자 수 하한을 걸어 강제            | 하한 제거, 점수로만 보고      |
| 검사      | 미적인 것까지 통과와 실패로 판정    | 물리적 형태만 차단            |

- 조일수록 나빠진 실측 ① : 글자 수 하한을 걸었더니 본문 12장 합계로 글자 +2,091, 시각 요소 −39, 비례 막대가 텍스트 목록으로 퇴화
- 조일수록 나빠진 실측 ② : 구획 부품을 두자 새 컨텍스트가 **6회 중 6회** 호출, 본문 면적의 83\~94%가 회색 덩어리, 같은 장을 부품 없이 그린 완성본은 **0%**
- 원인 : 부품과 하한이 있으면 자료를 거기 맞춰 휘게 됨, 규칙이 아니라 기본값이 장 구성을 정함
- 그래서 바꾼 질문 : "어떻게 더 조일까"에서 "무엇까지만 규정하고 나머지를 풀어둘까"로
- 풀어둔 뒤 재생성 : 빈 자리가 허전해지지 않고 내용으로 참, 다만 **3회 중 2회 상승에 1회 제자리**

### 5-2. 텍스트와 내용의 변동을 인터뷰로 고정

풀어두자 흔들린 것은 배치가 아니라 텍스트와 내용

- 실측 문제 : 본문 12장 중 8장의 제목과 부 이름 5개 전부가 조판 단계에서 창작됨
- 코드로 못 막는 이유 : 무엇을 담을지는 정답이 코드에 없어 검사로 뒤에서 잡히지 않음
- 채택한 방식 : 그리기 전에 사용자와 목차와 핵심 내용을 확정해 계약 파일로 고정, 조판과 검사가 같은 파일을 읽음
- 계약이 정하는 범위 : 무엇을 담을까까지, 어떻게 그릴까는 목업 선택에 넘김
- 결과 : 자료 밖 제목 **0건**, 같은 계약 3회 반복에서 지어낸 수치 **0**
